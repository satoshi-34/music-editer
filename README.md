# Music Editor MVP

Finale ライクな楽譜作成 Web アプリの最小構成（MVP）です。  
React + TypeScript + Vite + VexFlow を使って、**クリックで五線譜に音符を配置**し、**リアルタイムで音を再生**できます。  
MuseScore 風の **小節幅の自動割り付け** と、**クリック位置の高精度スナップ**（線に置きやすいバイアス付き）を実装しています。

---

## 🎵 主要機能

### 楽譜編集
- React + TypeScript + Vite による高速な開発体験
- **単旋律（ト音記号）**・**ピアノ大譜表（右手＋左手）**・**弦楽四重奏（Vn.I / Vn.II / Va. / Vc.）**・**編成譜** の切り替えに対応
- **複数パートの拍の縦揃え**: ピアノ大譜表・弦楽四重奏・編成譜では、同じ小節内の全パート（右手/左手、各楽器）・全声部の音符を1回の VexFlow Formatter でまとめて整形するため、パートごとに音価の密度が違っても同じ拍の音符が同じ横位置に揃って描画される（詳細は `.claude/specs/multi-part-beat-alignment/design.md` を参照）
- **編成テンプレート**: 弦楽合奏、室内オーケストラ、二管編成オーケストラ、大編成オーケストラ、吹奏楽などを選択可能
- **カスタム編成編集**: 編成譜ではパート名、略称、音部記号を編集し、パートの追加・削除・並び替えができる
- **パート略称表示**: 編成譜の先頭システム左側に `Fl.` や `Vln. I` などの略称を表示
- **グループ括弧表示**: 木管・金管・弦などの楽器グループを 1 本の括弧でまとめて描画（鍵盤はブレース）
- **サブグループ括弧**: 弦楽セクション内の Vln I/Vln II など、同じサブグループのパートを細い括弧でひとまとめに表示
- **低弦サブグループ**: 弦楽合奏以上では Vc. / Cb. も低弦として細い括弧でまとめて表示
- **移調楽器の実音/記譜音表示切替**: 編成譜では「実音」「記譜音」をワンクリックで切り替え。どちらのモードでも音符と調号の編集ができ、入力された内容は実音側へ自動変換して保存される
- **記譜音表示での調号シフト**: 移調楽器パートは、記譜音表示時に調号も五度圏に沿ってずれる（例: 実音Cメジャー → B♭管はDメジャー、F管はGメジャー）
- **タブ式ツールバー**: `音符・記号 / 楽譜設定 / 再生・音色 / その他` を切り替えて表示し、ボタン増加時もヘッダーをコンパクトに維持
- **アルト記号（ハ音記号）** に対応（Viola パートで使用）
- **和音入力**: 音符の上をクリックするだけで音を追加（単音→和音。矢印キーで全音を同時移動）
- **和音内の個別音選択**: 和音の中の1音だけをクリックして選択し、Delete や ↑/↓、臨時記号をその音だけへ適用できる
- **休符編集入力**: 音符ツールで休符をクリックすると、同音価ならそのまま置換し、より短い音価なら休符を分割して音符を差し込める（例: 16分休符 → 16分音符、8分休符 → 16分休符 + 16分音符）
- **自動休符補完**: 次の小節を編集し始めたタイミングで、それ以前の未完成小節へ足りない休符を自動追加
- **既定休符位置の調整**: 新しく置いた休符や空小節の見た目用休符は、デフォルトで五線の下から2本目の線にそろえて表示
  デモ譜面内の既存休符データも同じ既定位置へそろえてあるため、サンプル読込時の見た目も一致
- **カーソルプレビューの加線表示**: 五線の上下へ音符を置くとき、配置前のプレビューにも短い加線を表示
- **Undo / Redo（元に戻す・やり直す）**: 音符の配置・削除・コピー＆ペーストなど譜面データの変更をスナップショット方式で最大50件まで履歴に保持。ツールバー常設の「元に戻す」「やり直す」ボタン、または `Cmd/Ctrl+Z`（元に戻す）・`Cmd/Ctrl+Shift+Z` / `Cmd/Ctrl+Y`（やり直す）で操作できる。テキスト入力中は無効。新しい編集を行うと、それより先の redo 履歴は破棄される。途中テンポ変更（♩=XXX）などの小節単位ツールの編集も Undo/Redo で表示・データとも正しく往復する（キャンバスが末尾に補う空小節パディングの長さ差は編集扱いにしない。詳細は `.claude/specs/undo-redo-implementation/design.md` の追補と `src/utils/scoreDataEquality.ts` を参照）
- **ピアノ譜の2声部入力**: ピアノ譜（右手/左手）で、パレットの「声部1（上声）/ 声部2（下声）」トグル（`V` キーでも切替可）を使って
  同じ小節に上声・下声を別々に入力できる。声部2は符幹が自動で下向きになり、声部1と同じ小節に重ねて表示される（`Formatter.joinVoices` による整形）。
  **クリック操作は常にアクティブ声部だけに作用する**: クリック位置への挿入・和音追加・個別音選択・臨時記号・強弱記号・
  カスタム記号のトグル付け外し・前打音・装飾記号（トリル/モルデント/プラルトリラー/ターン）・ペダル・オッターバ・休符クリックでの置換分割・Delete削除は、
  声部1・声部2のどちらがアクティブでも同じ操作体系で使える（`getVoiceEvents` / `withVoiceEventsUpdated` 経由で
  アクティブ声部の `events` だけを読み書きする）。非アクティブ声部の音符は薄いグレー（`#9ca3af`）で表示され、
  印刷時は常に黒に戻る。再生時は両声部が同じタイミングで同時に鳴り、保存・読込・Undo/Redo にもそのまま対応する。
  以下は既知の制限として未対応: 連符ツール（3/5/6/7連符）・タイ/スラーのドラッグ入力は声部1の音符間でのみ動作（声部2は無効）、
  カスタム記号のサイズ変更・位置調整・テキスト要素（歌詞等）・汎用⤢/✥ツール（標準記号のサイズ・位置調整）は声部1のみ対応、矢印キーでの音高変更は声部1のみ対応、
  MusicXMLでの声部2の書き出し/読み込みは未対応
  （詳細は `.claude/specs/piano-two-voice-implementation/design.md` を参照）
- **2声部の浄書ルール対応（バッハのアルマンド風の書法）**: 2声部が同じ小節に共存するときだけ、標準的な浄書ルールへ寄せて描画する。
  - 符幹の向き: 声部1は常に上向き、声部2は常に下向きに固定（`resolveVoiceStemDirections`）。声部1しかない小節は従来通り自動判定のまま
  - ビーム（連桁）: 声部ごとに独立して生成し、`Beam.generateBeams` に声部の符幹向きを渡して声部をまたいだ連桁を防ぐ
  - 符頭の衝突回避: 両声部の `Voice` を同じ `Formatter.joinVoices().formatToStave()` に通し、2度でぶつかる符頭を横にずらす
  - 休符の上下避け: 2声部共存時のみ、声部1の休符をやや上寄り・声部2の休符をやや下寄りに表示（`restKeyForVoice`）。単声部の小節は従来位置のまま
- **拍子記号対応**: 譜面ごとに `4/4 / 3/4 / 3/8 / 6/8 / 2/2` を選択でき、表示・入力制限・再生時間計算へ反映
- **臨時記号対応**: パレットの `♯ / ♭ / ♮` ボタンを選んで音符へ適用。`Alt + ↑/↓` の半音移動も継続対応
- **強弱記号対応**: `pp / p / mp / mf / f / ff / cresc. / dim.` を音符へ付与。表示と再生ベロシティを連動
- **クレッシェンド／ディミヌエンドの松葉（ヘアピン）対応**: パレット「演奏記号」タブの `＜` / `＞` ボタンを選び、タイと同じ操作系で開始音符から終了音符へドラッグすると、五線の下（強弱記号と同じ高さ帯）に開く/閉じる2本線の松葉記号を描画する。小節またぎ・段またぎ（タイ/スラーと同じ分割描画）に対応。描画済みの松葉をクリックすると青くハイライトされ、Delete キーで削除できる。再生時はテキストの `cresc.` / `dim.` と同じ「次の絶対強弱まで段階的に増減」として反映され、MusicXML 書き出しでは `<wedge type="crescendo|diminuendo"/>`〜`<wedge type="stop"/>` として出力される（読込は未対応）。`NoteEvent.hairpins` に保存され、保存・読込・Undo/Redo に対応。単旋律譜・ピアノ大譜表・弦楽四重奏・編成譜のすべてで使える（2声部の声部2は未対応）
- **アーティキュレーション記号対応**: `スタッカート（·）/ アクセント（>）/ テヌート（—）/ フェルマータ（⌢）` を音符へ付与（トグル式）。同じボタンを再クリックで外す。複数記号の同時付与も可能
- **カスタム記号作成（現代音楽対応）**: パレット「演奏記号」タブの「＋」ボタンから記号エディタを開き、フリーハンド（手書きの自由な線）・直線・円（白・黒）・弧を組み合わせて、オリジナルの奏法記号を作成できる。線の太さは3段階（1 / 1.5 / 2.5）から選択、元に戻す・全消去に対応。作成した記号はパレットに追加され、任意の音符へトグル式で付与・除去できる。エディタでは既存記号の一覧とプレビューを確認しながら削除（管理）もできる（削除しても、すでに付与済みの音符の参照は掃除されず無害に無視される）。記号は保存データ（`customSymbolDefs`）にも含まれ、自動保存・手動保存・ファイル保存/読込のいずれでも往復する。単旋律譜（`StaffCanvas`）だけでなく、ピアノ大譜表・弦楽四重奏・編成譜（`PianoSystemCanvas` 系）でも表示・付与/除去・サイズ調整（⤢）・位置調整（✥）のすべてに対応しており、どのパート（右手/左手、各弦楽器、各編成パート）でも同じ操作で使える。描画・座標計算のロジックは `src/utils/customSymbolRenderUtils.ts` に共通化されている
- **カスタム記号の個別サイズ調整**: 同じカスタム記号でも、音符への配置1件ごとに大きさを変えられる（記号定義そのものは変わらない）。パレットの各カスタム記号ボタンの隣にある「⤢」（サイズ変更）ボタンを押してから、対象記号が付いている音符をクリックすると、インライン入力欄（25〜400%、%表記）が開く。Enter で確定・Escape でキャンセル。空欄で確定すると等倍（100%）に戻る。対象記号が付いていない音符をクリックしても何も起きない。サイズは `NoteEvent.customSymbols[].scale` に保存され、省略時は等倍として扱われる（旧データとの後方互換）
- **カスタム記号の高さ統一と個別位置調整**: カスタム記号の縦位置は、音符の符頭上端ではなく**その段の五線上端を基準にした統一高さ**に描画される（音高によって上下しなくなり、同じ段の記号は常に同じ高さに揃う）。それでも位置を微調整したい場合は、パレットの「⤢」の隣にある「✥」（位置調整）ボタンを押してから対象記号が付いている音符をクリックすると、横・縦のオフセット入力欄（-100〜100px）が開く。縦は＋で下・−で上。Enter で確定・Escape でキャンセル・空欄は0扱い。対象記号が付いていない音符をクリックしても何も起きない。オフセットは `NoteEvent.customSymbols[].offsetX` / `offsetY` に保存され、省略時は0（統一高さのまま）として扱われる（旧データとの後方互換）
- **標準記号の配置ごとのサイズ・位置調整（⤢/✥の一般化）**: カスタム記号専用だった「⤢（サイズ変更）」「✥（位置調整）」を、運指・強弱記号・歌詞・コード記号・テンポ表記・発想標語の6種類にも拡張。パレット「演奏記号」タブ末尾の汎用「⤢」「✥」ボタンを押してから音符をクリックすると、その音符に付いている調整可能な記号（カスタム記号＋上記6種のうち実際に付いているもの）を自動判定し、1件だけなら従来と同じインライン入力欄（サイズは25〜400%、位置は横・縦それぞれ-100〜100px）を直接開き、複数件付いている場合は「どれを調整するか」の小さな選択リストを先に出す。値は `NoteEvent.symbolAdjust[記号種別].scale/offsetX/offsetY` に保存され、省略時は等倍・オフセットなし（旧データとの後方互換）。装飾記号（トリル等）・アーティキュレーション（スタッカート等）は、VexFlowのグリフ描画へ安全に反映する対応が難しいため今回は非対応（データ型・保存の受け皿はあるが、UIの調整対象には出てこない）。カスタム記号専用の個別⤢/✥ボタンの動作は変更なし。MusicXMLには出力しない（アプリ独自の表示調整のため）
- **テキスト要素対応**: 音符に付けるテキスト系の記号を5種類追加。①**歌詞**（音符の下に通常体で表示）②**コード記号**（Am、G7 など、音符の上に太字セリフ体で表示）③**テンポ表記**（Allegro、♩=120 など、五線上端の上に太字斜体で表示）④**発想標語**（espressivo、dolce など、五線下端の下に斜体で表示）⑤**運指番号**（指使いの数字。音符の符頭のすぐ上に小さめの通常体で表示）。ツールを選択して音符をクリックするとインライン入力欄が開き、Enter で確定・Escape でキャンセル。空欄で確定すると記号を削除
- **運指番号（指使い）対応**: パレット「演奏記号」タブの「運指」ツールで、対象の音符をクリックするとインライン入力欄が開く。基本は `1`〜`5` の単一数字だが、和音には `1,3,5` のようにカンマ区切りで音ごとの運指を指定でき、指替えは `5-1` のように自由文字列で入力できる（バリデーションは8文字以内の緩いチェック）。単旋律譜（`StaffCanvas`）・ピアノ大譜表/編成譜（`PianoSystemCanvas`）の両方で表示に対応。`NoteEvent.fingering` フィールドに保存され、MusicXML の書き出し・読み込み（`<notations><technical><fingering>`、和音は音ごとに複数の `<fingering>` 要素）にも対応
- **途中テンポ変更対応**: 小節単位で BPM を上書きできる機能を追加。パレットの「テンポ変更」ツールを選んで小節をクリックするとインライン数値入力が開く（60〜240 BPM）。空欄で確定するとその小節のテンポ指定を解除。設定したテンポは `♩=XXX` として楽譜上（琥珀色テキスト）に表示され、再生時にも反映される。`MeasureData.bpm` フィールドに保存されるため、保存・読み込みを通じて復元される
- **途中拍子変更対応**: 小節単位で拍子記号を変更できる機能を追加。パレットの「拍子変更」ツールを選んで小節をクリックするとドロップダウンが開き、4/4・3/4・2/4・2/2・6/8・3/8・5/4・7/8・12/8 から選択できる（「解除」で元のグローバル拍子へ戻す）。変更した拍子は VexFlow の拍子記号として楽譜上に表示され、以降の小節はその拍子を継続する。入力制限（小節に入れられる拍数）も即座に反映され、再生の拍数計算にも対応。`MeasureData.timeSignature` フィールドに保存される
- **途中調号変更対応**: 小節単位で調号（転調）を変更できる機能を追加。パレットの「調号変更」ツール（拍子変更の隣）を選んで小節をクリックすると、通常の調号セレクトと同じ15種類の調号のドロップダウンが開く（「解除」でその小節の指定を外し、直前の調号を継続する状態に戻す）。変更後は段頭・段の途中どちらでも VexFlow の調号記号として表示され、以降の小節はその調号を継続する。新規音符入力時の既定の♯/♭付与や臨時記号の判定も「その小節時点で有効な調号」を使うため、転調後は自動的に正しい記譜になる。編成譜（ピアノ大譜表・弦楽四重奏・可変編成）では、移調楽器の記譜音表示にも同じ調号変更が反映される。`MeasureData.keySignature` フィールドに保存され、MusicXML の書き出し・読み込みにも対応（`resolveMeasureKeySignature()` で「この小節時点の有効調号」を解決する共通ヘルパーを `src/utils/keySignatureMeasureUtils.ts` に用意）。VexFlow の制約により、旧調号のナチュラルキャンセル表示（過去の調号を打ち消す記号）には対応していない（詳細は `.claude/specs/mid-score-key-change/design.md`）
- **途中音部記号変更対応（テナー記号追加）**: 小節単位でクレフ（音部記号）を変更できる機能を追加。パレットの「音部記号変更」ツール（調号変更の隣）を選んで小節をクリックすると、ト音記号/ヘ音記号/アルト記号/テナー記号/「（解除）」のドロップダウンが開く（「解除」でその小節の指定を外し、直前の小節のクレフまたはパートの既定クレフを継続する状態に戻す）。変更した小節の頭には VexFlow の小型クレフ（`stave.addClef(clef, 'small')`）が表示され、段頭ではその段の先頭小節時点で有効なクレフを通常サイズで表示する。クリック入力時の Y座標→音高変換・臨時記号の既定付与・既定休符位置も「その小節時点で有効なクレフ」を使うため、クレフ変更後は自動的に正しい音高で入力される。単旋律譜（`StaffCanvas`）・ピアノ大譜表/編成譜（`PianoSystemCanvas`）の両方で対応。編成譜では調号と異なりクレフはパートごとの小節データに保存するため、チェロだけテナー記号にする、といった楽器ごとの独立した変更ができる。`ClefType` に `'tenor'`（チェロ・ファゴット・トロンボーンで使うテナー記号）を追加し、`MeasureData.clef` フィールドに保存される。MusicXML の書き出しにも対応（読み込みはパートごとの既定クレフのみ復元し、小節単位の途中変更の読み込みは対象外。詳細は `.claude/specs/mid-score-clef-change/design.md`）
- **リハーサルマーク（練習番号）対応**: 小節単位で練習番号（A, B, C… や 1, 2, 3…）を付与できる機能を追加。パレットの「リハーサルマーク」ツール（音部記号変更の隣）を選んで小節をクリックすると、インライン入力欄が開く（途中テンポ変更と同じ「クリックで開く→入力→Enterで確定/Escapeでキャンセル」パターン）。既存のマークが無い小節をクリックすると、既存のアルファベット表記マークを走査して次の連番（A→B→…→Z→AA）を自動提案し、空欄で確定するとその小節のマークを削除する。表示は小節の左上、五線上端よりさらに上に四角い枠で囲んだ太字で描画し、途中テンポ変更（`♩=XXX`）とは縦に積んで重ならないようにする（テンポ表記が五線上端36px上、リハーサルマークはその上＝56px上に配置）。編成譜・ピアノ大譜表では調号変更と同じく最上段（`partsScore[0]`）の小節データにのみ保存し、最上段の上にだけ表示する。`MeasureData.rehearsalMark` フィールド（1〜4文字の自由文字列）に保存され、保存・読み込みで復元される。MusicXML の書き出し・読み込みにも対応（`<direction><direction-type><rehearsal>` 要素。詳細は `.claude/specs/rehearsal-mark/design.md`）
- **装飾音符対応**: 前打音（スラッシュ付き短前打音、VexFlow `GraceNote`）と装飾記号（トリル・モルデント・プラルトリラー・ターン、VexFlow `Ornament`）をパレットから付与できる。いずれもトグル式で、同じボタンを再クリックすると解除、別の装飾記号を選ぶと置き換え（1音符につき1種類）。前打音は主音符の1音上を自動設定。単旋律譜（`StaffCanvas`）・ピアノ大譜表/編成譜（`PianoSystemCanvas`）の両方で表示・付与に対応。`NoteEvent.graceNotes` / `NoteEvent.ornament` フィールドに保存され、ロード時に復元される
  - **トリル**（`tr`）: VexFlow コード `'tr'`
  - **モルデント**（下隣接音と1往復。波線＋縦線の記号）: グリフは SMuFL `ornamentMordent`（U+E56D）だが、VexFlow のコード名は歴史的経緯で逆転しており `'mordentInverted'` を指定する必要がある
  - **プラルトリラー**（上隣接音と1往復。波線のみの記号）: グリフは SMuFL `ornamentShortTrill`（U+E56C）で、VexFlow のコード名は `'mordent'`（これも上記と同じ理由でねじれている）
  - **ターン**（S字型の記号）: VexFlow コード `'turn'`
  - このねじれの詳細と判断根拠は `src/utils/ornamentUtils.ts` のコメントと `.claude/specs/extended-notation-features/design.md` を参照。モルデント/プラルトリラーの区別・再生は表示のみで、再生音への反映（装飾音を実際に鳴らす）は未対応（トリルと同じ扱い）
- **ペダル記号対応**: ピアノ曲向けに「ペダル↓（Ped）」「ペダル↑（✱）」記号をパレットから音符へ付与できる。五線下端に SVG テキストとして表示。`NoteEvent.pedalMark` フィールドに保存。down→up が時系列でペアになる区間は破線（Ped ╌╌╌ ✱）でつないで踏み続ける範囲を示す（対応しない単独の down/up は従来どおり単独表示。段またぎは各段の端まで破線を伸ばして分割表示）。ペアリングロジックは `src/utils/pedalBridgeUtils.ts` に切り出し、詳細は `.claude/specs/pedal-bridge/design.md` を参照
- **8va / 8vb 記号対応**: オッターバ括弧（1オクターブ上/下）を付与できる。「8va」「8vb」「8va終」「8vb終」の4ボタンで開始/終端を音符へ設定し、破線と縦線で表示。`NoteEvent.ottava` フィールドに保存
- **パート譜の抽出（表示・印刷）**: 弦楽四重奏・編成譜で、合奏練習用に1パートだけを抜き出した単一五線の譜面を表示・印刷できる。その他タブの「パート譜表示」セレクトで「総譜（通常）」か対象パート（例: Violin I、Horn in F など）を選ぶだけで切り替わり、ヘッダーに「パート譜: ○○（閲覧・印刷専用）」と表示される。総譜のデータそのものは変更せず、選んだパートだけを描画する一時的な表示モードのため、保存データには含まれない（保存・読込・リロードすると必ず総譜表示に戻る）。編成譜では移調楽器の記譜音表示・調号シフト・途中のテンポ/拍子/クレフ変更などを含め、既存の描画ロジックをそのまま流用しているため通常の総譜表示と同じ見え方になる。パート譜表示中は閲覧・印刷専用（編集不可）。再生ボタンを押すと選択中パートだけが鳴る（総譜表示に戻すと全パート再生に戻る）。単旋律譜・ピアノ大譜表はもともと1〜2段しかないため対象外（詳細は `.claude/specs/part-extraction/design.md` を参照）
- **MusicXML エクスポート**: その他タブの「MusicXML書出」ボタンで現在の楽譜を MusicXML 3.1 (score-partwise) 形式で書き出し。アーティキュレーション・強弱・リピート・テンポ変更・装飾記号（`<trill-mark/>` / `<mordent/>` / `<inverted-mordent/>` / `<turn/>`）を含む
- **MusicXML インポート**: 「MusicXML読込」ボタンで Finale / Sibelius / MuseScore 等が出力した MusicXML ファイルを読み込み、楽譜データに変換して画面へ反映
- **MIDI エクスポート**: 「MIDI書出」ボタンで MIDI Type 1 ファイルを生成。PPQ=480、GM 音色マッピング付き
- **レイアウト制御**: その他タブの「段あたり小節数」入力（1〜8）で、1段に表示する小節数を変更できる。これは上限であり、16分・32分・64分音符などで必要幅が足りない段は自動的に小節数を減らす。変更は保存・読み込みで復元される
- **ページ高さの統一**: 1ページ目のタイトル・作者欄を含む表示中ページの最大高さを全ページで共有し、譜面ページの大きさとページ間隔をそろえる
- **五線位置の統一**: タイトル欄の有無にかかわらず、各ページの五線が同じ上端から始まるようにヘッダー領域を確保する
- **ページ高さの統一**: 1ページ目のタイトル・作者欄を含む表示中ページの最大高さを全ページで共有し、譜面ページの大きさとページ間隔をそろえる
- **キーボードショートカット（Finale 風）**: 数字キー 1〜7 で音価を選択（5=四分、6=二分、7=全音符、4=八分、3=十六分…）。R キーで現在の音価を維持したまま休符モードをトグル。`.` キーで付点のON/OFFをトグル。テキスト入力中・Ctrl/Cmd 押下中は無効
- **調号対応**: `調号` セレクトで基本の調号ファミリーを選択。新規入力や通常の上下移動に既定の `♯ / ♭` を反映
- **タイ／スラー入力**: パレットのタイボタンを選択し、開始音符から終了音符へドラッグして設置。同音はタイ、異音はスラーとして自動判定。小節またぎ・段またぎにも対応
- **リピート記号入力**: パレットの `||:` / `:||` を選び、対象小節をクリックして開始/終了リピートを配置
- **1番括弧 / 2番括弧入力**: パレットの `1.` / `2.` を選び、対象小節をクリックして終止括弧の所属番号を付与
- **選択範囲の移調**: パレットの「小節選択」ツールで小節（範囲）を選択すると、その他タブに「移調」ボタンが現れる。クリックすると「半音上/半音下/全音上/全音下/オクターブ上/オクターブ下」の6ボタンと「半音数指定」（-12〜+12）の入力欄が開き、選択中の小節をまとめて移調できる。キーボードでは `Cmd/Ctrl+Shift+↑/↓` で半音移調（単音選択時の `Alt+↑/↓`・`Shift+↑/↓` とは修飾キーを分けて区別）。ピアノ譜・弦楽四重奏・編成譜では、既存のコピー＆ペーストと同じく「選択した小節範囲 × 全パート」が対象になる。異名同音の綴りは、選択範囲内の各小節時点で有効な調号（`resolveMeasureKeySignature()`）に沿って♯系/♭系を自動選択する（調号なしの場合はシャープ系）。和音・前打音（`graceNotes`）・複数声部（`voices`）もまとめて移調され、四分音の臨時記号（`microtones`）はそのまま維持される。移調結果が対応音域（VexFlowが扱えるオクターブ0〜9の範囲）を外れる音が1音でもあれば、操作全体を中止してエラーメッセージを表示し、データは一切変更しない（部分適用しない）。Undo（`Cmd/Ctrl+Z`）で元に戻せる。ロジックは `src/utils/transposeUtils.ts` に実装（詳細は `.claude/specs/transpose-selection/design.md`）
- **弧の選択と編集**: 描画済みの弧をクリックすると青くハイライト。弧をドラッグすると曲率を調節。青いハンドルをドラッグすると接続位置を2D調節。段またぎでは切れ目位置も調節可能。音符の反対側までドラッグすると弧の向きが反転。Delete キーで弧のみ削除（音符は残る）
- クリックで音符／休符を配置（加線域も含め 0.5 行刻みでスナップ）
- 小節幅の自動割り付け（全・二分はやや広め。細かい音符は過密回避）
- 見た目の横位置に最も近い場所へ自然に挿入（getAbsoluteX + BoundingBox）
- 全音価対応（全音符・二分音符・四分音符・八分音符・十六分音符・三十二分音符・六十四分音符）
- **付点音符・付点休符**: Palette の `.` トグルボタン（またはキーボードの `.` キー）をONにしてから音符/休符を配置すると、音価が1.5倍になる付点が付く。拍数計算・再生時間・MusicXML/MIDI書き出しにもすべて反映される。休符へ差し込む場合は「その場に付点音符ぶんの空きがあるか」だけで判定する保守的な仕様（休符側を付点休符へ再分割する処理はしない）
- **連符入力（3連符・5連符・6連符・7連符。単旋律譜・ピアノ大譜表・弦楽四重奏・編成譜すべて対応）**: Palette の「3連符」「5連符」「6連符」「7連符」トグルボタンのいずれかをONにしてから音価（例: 8分音符）を選び五線をクリックすると、音符1つ＋連符内休符(N-1)個からなる連符グループ（N個で本来の notesOccupied 個分の長さ。3連符=3:2、5/6/7連符=いずれも○:4）を一度に配置する。小節に空きが足りない場合は何も置かない。連符内の休符は同じ音価の音符でのみ置き換え可能（tuplet情報を引き継ぐ）。連符内のどれか1つを削除するとグループ全体が同じ長さの通常の休符に置き換わる。拍数計算・描画（VexFlowのブラケットと数字表示）・再生・MusicXML（`time-modification`）・MIDI書き出しにすべて反映される。多段譜ではパート（右手/左手、各弦楽器パートなど）をまたいでも tuplet id が衝突しないよう発行している。2連符（2:3、複合拍子専用）は直感に反する挙動になりやすいため今回は対象外

- **正確な音高再生**: 五線上の位置に応じた正確な音高
- **音価対応**: 全音符から六十四分音符まで正確な長さで再生
- **テンポ調整**: BPM設定による再生速度制御
- **音色プレビュー**: スピーカーボタンで音色確認

- **音量スライダー**: 再生コントロール列の「音量」で全体音量を調整（50%=標準、100%=約4倍、0%=ミュート。二乗カーブで上側の伸びしろを大きめに確保）。再生中でも即時反映され、設定は保存される
- **音色詳細UI**: 明るさ、アタック感、余韻、厚みをエンドユーザーが調整可能
- **音源方式切り替え**: 内蔵音源 / SoundFont / プラグイン連携（将来拡張）を選択可能
- **スウィング再生（ジャズ）**: 「音色詳細」の「スウィング再生」トグルをONにすると、記譜（見た目・保存データの音価）は8分音符のまま、再生タイミングだけを2:1のスウィング（表拍2/3拍・裏拍1/3拍）に揺らす。対象は付点なし・連符なしの8分音符のみで、16分音符・3連符・付点音符・6/8などの複合拍子はストレートのまま。内蔵音源・SoundFontの両方式に対応し、設定はLocalStorageに保存される。MIDI書き出しは常にストレートな音価で出力する
- **再生フォールバック**: SoundFont の読み込みに失敗した場合は、その再生操作だけ内蔵音源へ退避して無音のまま止まるのを避ける
- **実再生方式の表示**: SoundFont から一時的に内蔵音源へ退避したときは、設定保存値とは別に「今鳴っている方式」を UI に表示して見た目と実音のずれを減らす
- **再生復旧の安全策**: 優先エンジンで再生に失敗した場合は、新しい内蔵音源へ一度だけ退避して再試行し、再生ボタンと音色プレビューが同時に無音になるケースを減らす
- **Safari 安全策**: Safari でもまず選択中の音源方式で再生を試し、初期化や読み込みに失敗したときだけ一時的に内蔵音源へフォールバックする
- **Safari 再利用安定化**: built-in 再生時は毎回 `AudioContext` を捨てず、通常は既存エンジンを再利用して Safari の断続的な無音化を減らす
- **無音の自動検知と復旧（issue #14）**: 再生・音色プレビュー開始後に出力経路をヘルスチェック（currentTime 進行 + 無音プローブ）し、silent failure を検知したら設定を維持したままエンジンを自動再起動して通知を表示。30 秒以内の再発時は手動復旧へ誘導
- **手動の音声復旧**: Safari で silent failure が起きたときは `音声復旧` ボタンで `AudioContext` を作り直し、Safari の再起動なしで戻せる可能性を上げる
- **ブラウザ対応**: 自動再生ポリシーに完全対応

- **保存・読み込み**: LocalStorageによる譜面データの永続化
- **バックアップ復旧**: 主データが壊れていても、バックアップ側が有効なら読み込み時に譜面を復旧
- **印刷対応・PDFエクスポート**: その他タブの「PDF書出 / 印刷」ボタンでブラウザの印刷ダイアログを開き、送信先で「PDFに保存」を選べばPDFとして書き出せる（自前でPDFを生成せず、既存の `@media print` 整形をそのまま利用する方式。詳細は `.claude/specs/pdf-export/design.md` を参照）。印刷CSSは「線・塗りの有無は元の描画を尊重し、色だけを黒へ統一する」方針（一律の stroke/fill 強制はスラーの塊化・リハーサルマークの黒四角化・全体の太りを招いたため属性セレクタ方式に修正済み。同設計書の追補を参照）。編集画面の1ページは A4 実寸（297mm）に固定されており、画面のページ割りがそのまま印刷の1枚になる（段数は楽譜種別ごとに A4 に収まるよう調整: 初期値は単旋律8段・ピアノ4段・四重奏2段・編成譜2段/ページ。段はページ全体へ均等配置され、市販譜のような行間になる。その他タブの「段数/ページ」でユーザーが変更でき（A4に収まる上限までクランプ）、設定はブラウザに保存される。内容のない末尾の段・ページは印刷から自動で除外される）。内容のある最後の小節には**終止線（細＋太の二重線）**が自動で表示される（`Barline.type.END` / 多段譜では `StaveConnector.type.BOLD_DOUBLE_RIGHT` を併用。ただしその小節に終了リピート記号が付いている場合はそちらを優先し終止線は描かない。単旋律譜・ピアノ大譜表・弦楽四重奏・編成譜・パート譜抽出のすべてに対応、表示専用で保存データは変更しない）。**タイトルページ（1ページ目）にも、中間ページと同じ段数（段数/ページ）を入れる**（以前は市販譜の作法にならい1ページ目だけ段数を1段減らしていたが、物理印刷して確認したところタイトル下の余白が大きくなりすぎ紙面が無駄になったため、紙面効率を優先し全ページ同数へ変更した。タイトルページはヘッダーの実高さぶんだけ譜面領域が他ページより狭くなるため、段の縦位置が中間ページとぴったりは揃わないが、これは意図した挙動）。ページごとの段数配分は `src/utils/pageSystemLayoutUtils.ts` の純粋関数（`getPageSystemsCapacity` / `getPageSystemOffset` / `findPageIndexForSystem`）に集約し、`ScorePage.tsx` 側は「iページ目に何段入るか／iページ目が何段目から始まるか」を必ずこれらの関数経由で求める。全ページ同数のため実質 `i * systemsPerPage` と等しいが、将来また段数がページごとに変わる場合に備えてこの経由方式を維持している。各ページの `.system-stack` は `flex-grow` に `--page-capacity`（＝そのページの段数）を使い、直下の各段を等分の `flex:1 1 0` にすることで、そのページの残り高さの中で段を均等配置する（最終ページの下端寄せ／可視段1段の上揃えはこのグリッドの対象外で、従来どおりの配置のまま。詳細は `.claude/specs/final-barline/design.md` 追補7を参照）。印刷時は、内容のある最後のページだけ最後の段をページ下端へ寄せ、終止線がページ右下角で締まるように配置される（`.print-final-page .system-stack { justify-content: space-between; }`。最後のページに残る内容段が1段だけのときは `space-between` が効かないため `.print-final-page-single .system-stack { justify-content: flex-end; }` で下端へ寄せる）。**画面表示でも**、楽譜の作法として「最後の音符がある小節が譜面の最後」になるよう、内容のない末尾の空の段・空のページは既定では表示しない（完全に空の楽譜のときだけ入力の起点として最低1段を表示）。曲の続きを入力したいときは、譜面エリア内の最後の段の直後に出る控えめな「＋ 小節を追加」ボタン（画面専用・印刷には出ない）を押すと、空の段が1段ずつ表示され、そのまま音符を置ける（音符を置かずに保存すれば既存の `trimTrailingEmptyMeasures` により自然に消える）。ボタンのクリック自体は Undo 履歴に積まれない。詳細は `.claude/specs/final-barline/design.md` を参照）

### ページレイアウトの実装ポイント
- `ScorePage` が表示中の `.print-page` の高さを測り、最大値を `ScaledPageWrapper` へ渡す
- `ScaledPageWrapper` は共通高さを紙面と外側ラッパーへ反映するため、タイトル欄の有無でページサイズが分かれない
- `.page-head` はタイトル欄ぶんの最小高さを全ページで共有し、五線の開始位置をそろえる
- A4を超える大編成譜では、必要な高さを保ったまま全ページを同じ高さへそろえる

### 音符密度に応じた改段
- `measureMinimumContentWidth` / `vexFlowCombinedMeasureMinimumContentWidth` が符頭・細かい音価のビーム・臨時記号・前打音の最低幅を見積もる
- 指定した「段あたり小節数」から 3・2・1 小節の順に収まる段を選び、過密な小節で音符が重ならないようにする
- 自動休符補完や休符の置換・分割で小節内容が変わった直後も、この最低幅で再レイアウトする
- `SCORE_LAYOUT_RENDER_SCALE`（VexFlow の論理座標→物理SVG座標の倍率、`measureLayoutUtils.ts`）は等倍だと五線が実際の印刷譜（約6〜7mm）より1.5〜1.8倍大きくなり、1小節の最低幅が過大評価されて「1小節しか段に入らない」レイアウト崩れを招くため 0.4 を基準に調整している（印刷テストで記号・音符が市販譜よりひと回り小さかったため、現在は 1.1 倍の 0.44。音符の大きさを変えたいときはこの定数を変更する）。`measurePlannerSafetyPadding` の移調楽器向け安全マージン（臨時記号の最悪ケース加算）も Ensemble のときだけ適用し、ピアノ・四重奏では実測値をそのまま使う（詳細は `.claude/specs/multi-part-beat-alignment/design.md` 追補4を参照）

### 小節幅の均等さの調整
- **どこで変えるか**: **その他タブの「小節幅の均等さ」スライダー**（0〜100%）で画面から調節できる。密な小節（32分トレモロ・64分16連など、音符が多く最低幅が大きい小節）と疎な小節の**幅の差**を変えられる。設定はブラウザ（localStorage キー `score-measure-width-evenness`）に保存され、楽譜データには含まれない
- **値の意味**: `0%` = 各小節を最低必要幅どおりに配分（幅の差が最大。密な小節が段を独占しがち） / `100%` = 全小節を完全に等幅へ（差ゼロ） / `50%` = 中間（最低幅ベースの配分と等分幅のちょうど中間へ寄せ、差を約半分に縮める）
- **トレードオフ**: 値を大きくすると小節幅は均等に近づくが、64分16連など極端に密な小節は符頭が横に詰まり黒い塊に見えやすくなる。差を広げたい（密な小節に余裕を持たせたい）なら小さく、均等にしたいなら大きくする
- **既定値**: スライダー未設定時はコードの定数 `MEASURE_WIDTH_EVENNESS`（`src/utils/measureLayoutUtils.ts`、0.5）が使われる。アプリ全体の初期値を変えたい場合はこの定数を変更する
- 実装は「余剰幅を各小節へ均等配分した base」を「段内の等分幅 equalShare」へ線形にブレンドする方式で、総和は段の使用可能幅に保たれる（総和保存）。段に収まらない小節（overflow）はブレンドせず最低幅どおりに描き、はみ出し警告を隠さない。スライダー値は段確定後の幅配分だけに効き、改段（段割り・ページ数）には影響しない（詳細は `.claude/specs/multi-part-beat-alignment/design.md` 追補6・追補7を参照）

### 段ごとの小節数の個別調整
- **どこで変えるか**: 譜面エリアの下（各段の一覧）に並ぶ「段N ◀ N小節 ▶」コントロールで、段ごとに小節数を1つずつ増減できる。▶ で次段の先頭小節をこの段へ引き込み（+1）、◀ でこの段の末尾小節を次段へ送る（−1）。編集モードのときだけ表示し、印刷には出ない（`.system-measure-override-controls` を `@media print` で非表示にしている）
- **リセット**: その他タブの「段割りをリセット」ボタンで、手動調整をすべて解除して自動計画（幅ベースの `planSystemMeasureRanges`）に戻せる
- **データモデル**: `SavedScoreData.systemMeasureOverrides?: { startMeasure: number; count: number }[]`（`src/types/storage.ts`）。「絶対小節インデックス `startMeasure` から始まる段は `count` 小節」という意味で保持し、段の並び順ではなく小節番号をキーにしているため、他の段の編集で多少ずれても意味を保ちやすい。旧データ互換のため省略可（省略時は自動計画のみ）
- **計画ロジック**: `planSystemMeasureRanges`（`src/utils/measureLayoutUtils.ts`）が、貪欲法で段の開始位置を進める際に上書き一覧を参照する。開始位置が上書きの `startMeasure` と一致する段はその小節数をそのまま使い（使用可能幅を超えても許容し、`overflow: true` を返すだけで縮めない＝はみ出しはユーザー判断）、一致しない段は従来どおりの自動計画が続く。そのため上書きした段より後ろは自動的に続きから再計画される
- **描画時の右端揃え**: 上書きで最低幅の合計が使用可能幅を超えた段は、`allocateCombinedMeasureWidths`（同ファイル）が小節の割り当て幅だけを比例圧縮し、他の段と同じ右端（SVG幅）に揃えて描画する。フォント・五線の縦サイズ（`renderScale`）は変えないため、「音符の大きさ」スライダーの値に関わらず全段の SVG 幅が一致する。圧縮後は必ず使用可能幅に収まるため `svg[data-layout-overflow]` は `false` になる（詰め込みすぎて符頭同士が近づく見た目上の詰まりは許容する設計）。自動計画のみの段（上書きなし）は元々収まる幅しか選ばれないため、圧縮は発動しない
- **Undo/Redo・保存/読込との整合**: 上書き一覧は `ScorePage.tsx` の Undo/Redo スナップショット（`ScoreSnapshot.systemMeasureOverrides`）に含め、＋1/−1・リセットの操作も他の編集と同様に元に戻せる。保存（`saveScoreData`/`createSavedScoreData`）・読込（`loadScoreData`）・ファイル書出/読込（`fileStorage.ts`）でも他のフィールドと同様に往復する。`storage.ts` の `validateSystemMeasureOverrides` が `startMeasure` の重複・負数・`count<1` を弾く
- 詳細は `.claude/specs/system-measure-override/design.md` を参照

### 画面表示のズーム調整
- **どこで変えるか**: **その他タブの「画面表示のズーム」スライダー**（50〜150%、5%刻み）で画面の表示サイズを調節できる。設定はブラウザ（localStorage キー `score-view-zoom`）に保存され、リロード後も維持される
- **既存の自動縮尺との関係**: このアプリはもともと `useAutoPageScale`（`src/components/useAutoPageScale.ts`）が画面幅に合わせて自動で縮尺（`--scale`）を計算し、`ScaledPageWrapper`（`src/components/ScaledPageWrapper.tsx`）が `transform: scale(var(--scale))` で画面表示だけを縮小している（issue #13: CSS `zoom` は Safari で `getBoundingClientRect` に反映されず音符のクリック座標がずれるため、全ブラウザで座標に反映される `transform` を採用）。ズームスライダーはこの自動縮尺に**倍率として掛け合わせる**だけで（`ScorePage.tsx` の `effectiveScale = scale * viewZoom`）、既存の縮尺計算・座標変換の仕組みはそのまま利用する。100% がスライダー未操作時の従来どおりの表示（自動縮尺そのまま）
- **印刷への影響**: 印刷は `@media print` で `.page-wrapper { transform: none !important; width: auto !important; height: auto !important; }` により画面用の縮小・ズームを丸ごと解除する既存設計（`src/App.css`）に従うため、ズームの値に関わらず印刷結果は変わらない
- **座標系への影響**: 音符クリックなどのヒットテストは `.page-wrapper` の `--scale`（Safari 対策で `closest('.page-wrapper')` から読む実装、`StaffCanvas.tsx` / `PianoSystemCanvas.tsx`）を経由するため、ズームで `--scale` の値が変わっても座標変換は自動的に追従する

### 音符の大きさ調整（印刷にも反映）
- **どこで変えるか**: **その他タブの「音符の大きさ」スライダー**（80〜200%、5%刻み）で音符・五線・記号そのものの物理サイズを調節できる。設定はブラウザ（localStorage キー `score-notation-size`）に保存され、リロード後も維持される
- **「画面表示のズーム」との違い**: 「画面表示のズーム」は `--scale`（`transform: scale()`）による**画面表示だけ**の拡大縮小で、印刷結果には一切影響しない。一方この「音符の大きさ」は `SCORE_LAYOUT_RENDER_SCALE`（`measureLayoutUtils.ts`、VexFlow の論理座標→物理SVG座標の倍率）そのものに掛け合わせる倍率のため、画面表示と印刷結果の両方に反映される。用途が異なるので、目的に応じて使い分ける（画面だけ大きく見たい→ズーム／実際に大きい・小さい音符で印刷したい→音符の大きさ）
- **実装**: 定数 `SCORE_LAYOUT_RENDER_SCALE` 自体は書き換えず、`ScorePage.tsx` の `effectiveRenderScale = SCORE_LAYOUT_RENDER_SCALE * notationSizeMultiplier` を段組み計画（`planEffectiveMeasuresPerSystem` / `planSystemMeasureRanges`）と各 Canvas への `scale` prop の両方に一貫して渡す。100%（notationSizeMultiplier = 1）のときは従来どおりの見た目・印刷結果になる
- **自動改段への反映**: 音符が大きくなれば1段に入る小節数は減り、小さくなれば増える。`effectiveRenderScale` が段組み計画の `useMemo` 依存に含まれているため、スライダーを動かすたびに段・ページ割りが自動で再計算される（詳細は `.claude/specs/view-zoom/design.md` の「音符・記号の大きさ調整（notation-size）」章を参照）
- **段数/ページ上限との連動**: 音符が大きくなると1段の高さも比例して増えるため、`ScorePage.tsx` の `maxSystemsPerPage` は固定値ではなく `notationSizeMultiplier` に連動した動的計算（`Math.floor(SCORE_AREA_BUDGET_PX / (楽譜種別ごとの基準段高 × notationSizeMultiplier))`）になっている。ユーザーが設定した「段数/ページ」が新しい上限を超えたら自動でクランプされ（既存の `Math.min(maxSystemsPerPage, …)` がそのまま効く）、入力欄の `max` 属性・ツールチップの上限表示も追従する。基準段高（単旋律 114px / ピアノ 180px / 四重奏 340px / 編成譜 400px・800px）は音符の大きさ100%時の実測値で、`SCORE_AREA_BUDGET_PX`（938px）はタイトルページ（ヘッダー分が狭い）基準の安全側の予算を全ページ共通で使う

### ページレイアウトの実装ポイント

- `ScaledPageWrapper` は共通高さを紙面と外側ラッパーへ反映するため、タイトル欄の有無でページサイズが分かれない
- A4を超える大編成譜では、必要な高さを保ったまま全ページを同じ高さへそろえる

### Safari 座標補正
- **根本対策（issue #13）**: ページ縮小を CSS `zoom` から `transform: scale` へ変更。`transform` は全ブラウザで `getBoundingClientRect` に反映されるため、Safari 内蔵ディスプレイでの座標ズレが原理的に発生しなくなる
- **旧Y補正の自動リセット**: zoom 時代に設定した手動Y補正（例: +24）が残っていると逆方向へずれるため、transform ビルドの初回起動時に一度だけ自動で破棄する（その後に設定し直した補正は維持される）
- **Y補正ボタン**: それでも音符配置位置がカーソルとずれる場合に手動で補正
- **操作**: ↑/↓ボタンまたはキーボード矢印キーで調整（低音方向=プラス）
- **保存**: 設定はLocalStorageに保存、次回起動時も維持

### Safari 音声メモ
- **症状**: Safari だけ `音符再生開始` まで進むのに無音になることがある
- **主な要因**: 別タブの動画再生、ホットリロード、タブ復帰後の `AudioContext` の不安定さ
- **参照先**: `docs/audio-safari-notes.md`

### 音色データ（SoundFont）の取得先について

音符再生で使う SoundFont の音色サンプルは、初回再生時に外部 CDN（`soundfont-player` の既定配信元）からダウンロードします。オフラインでは SoundFont 音源が鳴らない点と、外部サーバーへアクセスが発生する点に注意してください。パック名は許可リストで検証しているため、保存データ経由で任意の URL へアクセスさせることはできません（`src/audio/SoundFontEngine.ts`）。

## 使い方

Git の作業ルールは [GIT_RULES.md](/app/GIT_RULES.md) にまとめています。

### 基本操作
1. **スコアタイプ選択**: ツールバーで「単旋律」「ピアノ」「弦楽四重奏」「編成譜」を選択します
2. **音価選択**: 画面上の Palette で音価（全音符・二分音符・四分音符・八分音符など）や休符を選びます
3. **音符配置**: 五線譜の置きたい位置をクリックします。線／間／五線の外（加線域）も 0.5 行刻みでスナップします
4. **拍数制限**: 選択中の拍子で許される小節長を超える配置は無視されます
5. **休符の編集**: たとえば 16分音符ツールで 16分休符をクリックするとそのまま 16分音符へ置き換わり、8分休符の右半分をクリックすると `16分休符 + 16分音符` に分割できます

### 弦楽四重奏
- 「弦楽四重奏」ボタンを選択すると Vn. I / Vn. II / Va. / Vc. の 4 段譜面が表示されます
- Viola 段はアルト記号（ハ音記号）が表示され、中央線が C4 になります
- 各段独立して音符を配置でき、再生ボタンで 4 パート同時に再生されます

### 編成譜
- 「編成譜」を選ぶと、編成テンプレートに沿った複数パート譜が表示されます
- 「編成」セレクトで室内オーケストラ、二管編成オーケストラ、吹奏楽などを切り替えられます
- 先頭システムの左側には、各パートの略称が表示されます
- パート編集では、パート名、略称、楽器族、音部記号、移調、括弧グループ、サブ括弧を変更できます
- パート編集は「パート編集」ボタンから別ウィンドウで開き、総譜を見ながら編集できます
- 括弧グループの `単独` は、ほかの単独パートと連続していても括弧でまとめません
- 各パートの再生音色を選ぶと、譜面全体再生時と音符入力時の確認音にそのパートの音色が使われます
- 「追加」「削除」「↑」「↓」でパート数と並び順を変更できます
- プリセットを編集すると `カスタム編成` として保存されます

### 和音入力
- **基本操作**: まず通常クリックで音符を配置し、その後 **同じ音符の上をクリック**（Y 位置が和音ゾーン内）で音を追加。Shift キーは不要
- **和音ゾーン**: 音符の描画 X 範囲（単旋律は左右 ±1.2px、ピアノ/複数パートは左右 ±1.5px）かつ五線 ± 3加線の固定 Y 範囲内がゾーン。ゾーン外のクリックは新規音符挿入になる
- **個別選択**: 和音内の既存音と同じ高さをクリックすると、その1音だけが青枠で選択される
- **音の移動**: 和音全体を選択しているときは矢印キー（↑/↓）で全音を同時シフト。和音内の1音を選択しているときは、その音だけを移動（`Alt` で半音、`Shift` でオクターブ）
- **音の削除**: 和音内の1音を選択して Delete / Backspace を押すと、その音だけを削除。最後の1音だけの場合は音符イベント全体を削除
- **同時再生**: PolySynth が和音を1コールで同時発音。スコア再生時も全音が正確に再生される

### 自動休符補完
- **補完タイミング**: ある小節へ音符や休符を入れ始めたとき、その前にある未完成小節を拍子ぶんの長さまで休符で埋めます
- **休符編集時も補完**: 空小節や既存休符を音符へ置換・分割するときも、先に過去小節を補完してから譜面を再レイアウトします
- **対象範囲**: 編集中の小節そのものは触らず、それ以前の小節だけを補完します
- **複数パート譜**: 編成譜では、編集しているパートの過去小節だけを補完します。ほかのパートへ勝手に休符は入りません
- **設計メモ**: 詳細は `docs/editing-selection-and-rests.md` にまとめています

### 臨時記号
- **パレット操作**: `♯ / ♭ / ♮` ボタンを選んだあと、対象の音符セルをクリックすると臨時記号を適用します
- **背景クリックでは挿入しない**: `♯ / ♭ / ♮` ツール中に小節背景をクリックしても、新しい音符は置かれません
- **和音への適用**: 和音をクリックした場合は、そのイベントに含まれる音すべてへ同じ臨時記号を適用します
- **半音入力**: キーボード派向けに `Alt + ↑/↓` の半音移動も引き続き使えます
- **ナチュラル表示**: 同じ小節内で先に変化していた同音名・同オクターブの音を自然音へ戻すと、ナチュラル記号（`n`）を自動表示します
- **重複抑制**: 同じ小節内で同じ臨時記号状態が続く場合、不要な `#` / `b` の重複表示を省きます
- **確認音の切替**: 音色詳細内のチェックボックスで、臨時記号を付けた直後の確認音を ON/OFF できます

### 微分音（四分音）の臨時記号
- **パレット操作**: `♯ / ♭ / ♮` の隣にある「四分音上げ（𝄲）」「四分音下げ（𝄳）」ボタンを選び、対象の音符セル（和音の場合は個別音）をクリックすると付与します。もう一度同じ音をクリックすると解除できます
- **通常の臨時記号と排他**: 四分音を付けるとその音の `♯ / ♭` は自然音へ戻り、逆に `♯ / ♭ / ♮` を適用するとその音の四分音は外れます（同じ音に両方が同時に付くことはありません）
- **描画**: VexFlow の四分音上げ（`+`）・四分音下げ（`d`）の臨時記号（Stein のクォータートーン記号）を符頭の左に表示します。単旋律譜・ピアノ大譜表の両方で対応
- **再生（内蔵音源）**: クリック確認音（`NotePlayer`）は和音全体の四分音を反映して ±50セントのピッチシフトで鳴ります。譜面全体再生（`SimpleAudioEngine`）は先頭音（和音の1音目）のみ反映する既知の制限があります
- **再生（SoundFont）**: `soundfont-player` はセント単位のピッチシフト手段を持たないため、SoundFont 再生では四分音は半音に丸まって鳴ります（既知の制限）
- **保存**: `NoteEvent.microtones`（`{ keyIndex, type: 'quarterSharp' | 'quarterFlat' }[]`）に保存され、旧セーブデータとの互換を保ちます
- **MusicXML書き出し**: `<alter>0.5</alter>` / `<alter>-0.5</alter>` と `<accidental>quarter-sharp</accidental>` / `<accidental>quarter-flat</accidental>` を出力します。読み込み（import）側の四分音復元は対象外です
- **対象外**: 3/4音（3 quarter tones）の記号は今回のスコープ外です
- **設計メモ**: 詳細は `.claude/specs/microtone-implementation/design.md` を参照してください

### 強弱記号
- **パレット操作**: `pp / p / mp / mf / f / ff / cresc. / dim.` ボタンを選び、対象の音符セルをクリックします
- **解除方法**: 同じ強弱ボタンを選んだまま同じ音符をもう一度クリックすると、その種類の記号を外せます
- **共存ルール**: 絶対強弱（`p` など）と変化強弱（`cresc.` / `dim.`）は同じ音符に併記できます
- **再生反映**: 再生ボタンの譜面全体再生では強弱記号をベロシティへ変換し、`cresc.` / `dim.` は次の絶対強弱へ向かって段階的に増減します

### 松葉（ヘアピン、クレッシェンド＜／ディミヌエンド＞）
- **パレット操作**: 「演奏記号」タブの `＜`（cresc.）/ `＞`（dim.）ボタンを選び、開始音符から終了音符へドラッグして設置します（タイ/スラーと同じ操作系）
- **表示位置**: 五線の下、強弱記号テキストと同じ高さ帯に描画されます。小節またぎ・段またぎに対応します
- **削除方法**: 描画済みの松葉をクリックすると青くハイライトされ、Delete / Backspace キーで削除できます（Escape で選択解除）
- **再生反映**: テキストの `cresc.` / `dim.` と同じ扱いで、次の絶対強弱へ向かって段階的にベロシティが増減します
- **最小チェック**: 音符を4つ入力 → `＜` で1音目から4音目へドラッグ → 開く松葉が五線下に表示される → クリック選択 → Delete で消える → 保存 → 読込で復元される

### アーティキュレーション（奏法記号）
- **パレット操作**: `•`（スタッカート）/ `>`（アクセント）/ `‒`（テヌート）/ `^`（マルカート）/ `𝄐`（フェルマータ）ボタンを選び、対象の音符セルをクリックします
- **解除方法**: 同じボタンを選んだまま同じ音符をもう一度クリックすると、その記号を外せます（トグル）
- **重ね付け**: スタッカート＋アクセントのように、種類が違う記号は同じ音符に重ねて付けられます
- **休符には付かない**: 奏法記号は「鳴らし方」の指示なので、休符をクリックしても何も起きません
- **再生反映**: 譜面全体再生では、スタッカート＝音を短く / アクセント・マルカート＝音を強く / フェルマータ＝長く伸ばす、として音の長さ・音量へ変換します（複数付いていれば倍率を掛け合わせます）

### リピート記号
- **パレット操作**: `||:` で開始リピート、`:||` で終了リピートを選びます
- **配置方法**: 記号を置きたい小節の背景または音符セルをクリックすると、その小節線にリピート記号が付きます
- **解除方法**: 同じ記号ツールを選んだまま、同じ小節をもう一度クリックすると外せます
- **両方配置**: 同じ小節に `||:` と `:||` を別々に付けることもできます
- **再生反映**: `||:` から `:||` までは、譜面再生時に 1 回だけ折り返して再生します
- **開始記号省略**: `:||` だけ置いた場合は、譜面の先頭からその小節までを折り返します

### 調号
- **調号選択**: ツールバーの `調号` セレクトで、調号なし / ♯系 / ♭系の調号ファミリーを選べます
- **行頭クリックでも変更**: `♯ / ♭ / ♮` ツールを選んで各段の行頭をクリックすると、調号を1段ずつ増減できます。`♮` は調号なしへ戻します
  拍子記号がある段では、その右側から音符の手前までを調号クリック領域として扱います
  `♯ / ♭ / ♮` ツール中は、調号クリック領域を薄いオレンジ色で表示し、クリック時にブラウザコンソールへ診断ログを出します
  既存の音符セルを押したときは常に臨時記号、音符の無い小節背景の調号領域を押したときだけ調号として扱います
  `♯` はシャープ系の調号を、`♭` はフラット系の調号を増やしていき、別系統へ切り替えるときはまず `♯1つ` / `♭1つ` から始めます
  初期表示の全休符は見た目だけのガイドとして描画し、巨大な編集ヒット領域は持たせません
- **表示位置**: このエディタでは先頭行の調号を拍子記号の右側へ表示します
- **入力への反映**: 調号に含まれる音は、新規入力や通常の上下移動で既定の `f#` や `bb` を自動反映します
- **表示の省略**: たとえば G 系（♯1つ）で `f#/4` を置いた場合、臨時記号は毎回は出ず、調号に含まれる音として扱います
- **ナチュラル表示**: 調号で `F#` が既定のときに `f/4` を置くと、必要な位置にだけナチュラルが表示されます

## 実装のポイント（要点）

### 1. クリック座標と描画座標の基準を統一（Safari 対応済み）
- クリックはクライアント座標、VexFlow は SVG viewBox 座標です。
- ページ縮小は CSS `zoom` ではなく **`transform: scale`** で行います（issue #13 の根本対策）。`transform` は Safari を含む全ブラウザで `getBoundingClientRect` へ視覚座標として反映されるため、**BCR との単純差分 × viewBox 比率**だけで正確に変換できます。
- `transform` はレイアウト上の占有サイズを変えないため、`ScaledPageWrapper` がページの実測高さ × scale をラッパーへ設定し、ページ間の余白を保ちます。
- 旧 `zoom` 方式（Safari が論理サイズを返す）へ退行した場合に備え、`getAccumulatedCSSZoom()` + 動的判別の補正コードはフォールバックとして残しています。
- 自動補正で解消しない場合はツールバーの **「Y補正」** で手動キャリブレーション可能（設定 localStorage 保存）。

### 2. Y 方向スナップ（音高決定）
- `stave.getSpacingBetweenLines()` を基準に **0.5 行刻み**でスナップ。
- 線に置きやすいよう **線バイアス**（`LINE_PAD_RATIO`, `LINE_BIAS`）を適用。

### 3. X 方向の挿入位置
- 各音符の `getAbsoluteX()` と幅（BoundingBox）を使い、クリック X に最も近い隙間へ挿入。
- 音符/休符のクリック判定は透明な `.vf-note-hit` が受け、青い `.vf-note-selected` は表示専用。クリック範囲と青枠の大きさは別々に調整できる。

### 4. 小節幅の自動割り付け
- `measureMinimumContentWidth` で小節ごとの最低幅を計算し、全・二分を含む小節は下限幅を広めに確保。
- 16 分や 32 分が並ぶ小節は最低幅の合計で先に改段判定するため、符頭やビームが重なりにくい。
- ピアノ大譜表・編成譜の合同フォーマットでは、推定幅に加えて VexFlow の `preCalculateMinTotalWidth()` で付点・連符・和音・表示済み臨時記号を含む実測最低幅を取得する。臨時記号は `noteKeyUtils` の調号・小節内状態・前小節courtesy判定を本描画と共用し、実際に表示する記号だけを仮ノートへ付ける。`ScorePage` は全小節を先に検査して、保存された希望値を上限に `4→3→2→1` の共通 `effectiveMeasuresPerSystem` を選ぶため、Canvas 単位の無制限縮小やページ外へのはみ出しを起こさない。画面の viewport 縮小はページラッパーだけが担い、譜刻・印刷の内部倍率は固定の等倍で一致する。付点は Note の `dots`、連符は `Tuplet` を Voice/Formatter の前に作成して tick も一致させるため、右手・左手の拍揃えと密な小節の自動幅調整を両立する。

### 4.5 連符（tuplet）: 3連符・5連符・6連符・7連符
- `NoteEvent.tuplet = { id, numNotes, notesOccupied }` で連符グループを表現（同じ id を持つ連続イベントが1グループ）。`numNotes`/`notesOccupied` は最初から一般化されており、3連符(3:2)に限らず任意の N:M 比を表現できる。
- `src/utils/tupletUtils.ts` の `buildTupletGroupPlan(duration, dots, noteKeys, restKey, tupletSpec?)` が第5引数 `tupletSpec: { numNotes, notesOccupied }` を受け取り、「音符1つ＋連符内休符 numNotes-1 個」のグループを組み立てる。省略時は3連符(3:2)がデフォルト（既存呼び出しの後方互換）。`TUPLET_KINDS`（3:2 / 5:4 / 6:4 / 7:4）としてパレット用の一覧も公開している。
- パレット（`Palette.tsx`）の `Tool.tuplet` フィールドは `boolean` から `{ numNotes, notesOccupied } | undefined` へ拡張。「3連符」「5連符」「6連符」「7連符」の4ボタンが並び、それぞれ対応する `TupletKind` をトグルする。
- 拍数計算は `voiceMeasureUtils.tupletBeatsMultiplier()`（`notesOccupied/numNotes` 倍、比率に関わらず汎用）を中心に、`StaffCanvas`/`PianoSystemCanvas`/`RestOverlapFixV2`/`ScorePlayer`/`SoundFontEngine`/`midiExport`/`musicXmlExport` それぞれで同じ倍率を反映（dur から直接拍数を再計算している箇所が複数あるため、中心ヘルパーの変更だけでは不十分）。これらは3連符実装時点からすでに numNotes/notesOccupied 汎用の式だったため、5/6/7連符でも変更不要だった。
- 描画は VexFlow 5 の `new Tuplet(notes, { numNotes, notesOccupied })` を使用。コンストラクタが自動で各音符の `tupletStack` を更新するため Voice のフォーマット計算（ticks合計）は自動対応するが、ブラケット描画自体は `tuplet.setContext(ctx).draw()` を明示的に呼ぶ必要がある。数字表示は VexFlow が自動判定し、3連符は「3」、5/6/7連符は「N:4」（比率表示）になる。
- `StaveNote` の `dots` は tick（拍の内部単位）を伸ばし、`Dot.buildAndAttach()` は点の見た目だけを追加する。そこで両方を指定し、さらに `Tuplet` は Formatter 後ではなく Voice に追加する前に生成する。これにより、付点・連符と右手/左手の合同拍位置が食い違わない。
- 削除は「連符グループ内のどれか1つを消すとグループ全体を通常の休符に置き換える」というシンプルな仕様（詳細は `.claude/specs/tuplet-implementation/design.md`）。
- 入力（配置・休符置換・グループ削除）のロジックは `src/utils/tupletUtils.ts` に共通化し、`StaffCanvas`（単旋律譜）・`PianoSystemCanvas`（多段譜）の両方から呼び出している。クリックのヒット判定や `setScore`/`setPartsScore` への反映は各キャンバス側に残し、「共通化はロジックのみ」という方針（`customSymbolRenderUtils.ts` と同じ）。tuplet id は `generateTupletId()`（時刻＋モジュール内カウンタ＋乱数）で発行し、パートをまたいで呼んでも衝突しない。
- 2連符（2:3）は複合拍子（8分の6拍子など）でしか自然に意味を持たず、単純拍子では「2連符なのに音価が伸びる」という直感に反する挙動になるため、今回のスコープからは除外した。

### 5. 🎵 音符再生システム
- **SimpleAudioEngine**: Web Audio APIを直接使用した軽量な音声エンジン
- **SoundFontEngine**: 既存の楽器サンプルを読み込み、より楽器らしい音で再生するエンジン
- **音色確認用サンプル**: ピアノ説明用、金管テスト、弦テストを切り替えて聴き比べできる
- **ピアノサンプルの更新**: 固有曲名ベースのサンプルではなく、`3/8`・休符・リピート・終止括弧・強弱をまとめて確認しやすいピアノ用デモフレーズへ差し替えた
- **複数声部の基盤**: ピアノ譜では 2 voice を保持できるデータ構造と入力UI（声部切り替えトグル）を用意している。現在のデモフレーズは、機能確認を優先して単声部寄りに整理している
- **簡易音色プリセット**: ピアノ、ギター、木管群、金管群、弦群、打楽器群を含むフルオケ寄りの楽器一覧を切り替え可能
- **音色詳細UI**: 明るさ / アタック感 / 余韻 / 厚みをスライダーで調整可能
- **音源方式**: `内蔵音源 / SoundFont / プラグイン連携` を切り替えられる
- **SoundFont 実装**: 既定では `FluidR3_GM` を選択し、必要に応じて `MusyngKite` など別パック名へ切り替えられる
- **フォールバック表示**: SoundFont 失敗時は保存設定を残したまま、再生パネル上では一時的に `内蔵音源` 表示へ切り替えて現在の実動作を伝える
- **音高変換**: Vexflow形式（`c/4`）からMIDI形式（`C4`）への自動変換
- **調号つき入力**: 調号に含まれる線・間へ通常入力した場合は、内部キー文字列も `f#/4` や `bb/3` に補正して再生音と表示を一致させる
- **音価計算**: BPMに基づく正確な再生時間計算
- **ブラウザ対応**: 自動再生ポリシーに完全対応（ユーザーインタラクション後に初期化）
- **Safari対策**: `running` に見えても無音になるケース向けに、出力経路ウォームアップと失敗時のみの一時的な内蔵音源フォールバックを実装
- **再生成の抑制**: `ScorePage` では built-in の通常再生で毎回エンジンを捨てず、`AudioContext` の作り直しは方式切替・背景復帰・実失敗時に限定して Safari の不安定さを避ける
- **強めの音声復旧**: `音声復旧` は無音時に `built-in + ピアノ + 既定プロファイル` へ安全に戻して、壊れた保存設定を持ち越さないようにする
- **最小テスト音**: 再生エンジンを通さない純粋な Web Audio の確認音を鳴らし、ブラウザ出力とアプリ経路の切り分けに使える
- **設定読込の安全化**: localStorage の再生設定は型と値域を検証し、不正値は既定値へ戻す
- **多段譜の描画耐性**: ピアノ譜・四重奏譜・編成譜ラッパーは描画を `PianoSystemCanvas` に委譲して共通の描画直前安全化を共有し、`EnsembleStaff` の記譜音モードでも移調前処理で壊れた小節・音符を素通りさせて譜面全体を止めない
- **カッコ付き臨時記号（courtesy accidental）**: 前の小節で `#` や `b` が付いた音が小節線を越えて自然音（調号の音）に戻るとき、読者への注意としてカッコ付き臨時記号を自動表示する。単旋律譜・ピアノ譜・四重奏譜・編成譜のすべてで同じロジックが動く
- **リピート記号の保存**: 開始/終了リピートは `MeasureData` の小節属性として保存し、音符編集時も落とさない共通複製関数で守る
- **リピート再生順の展開**: `ScorePage` は再生前に小節順を安全に展開してから各音源へ渡し、各 `:||` で 1 回だけ折り返す。想定外データでは安全上限で打ち切って無限ループを防ぐ
- **新規作成の初期化範囲**: `ScorePage` の新規作成処理は、保存済みスロット、譜面データ、メタ情報、楽譜種別、調号・拍子、選択範囲、Undo/Redo、再生状態をまとめて初期化する。ファイル保存ハンドルも破棄し、次回のファイル保存で古いファイルを上書きしないようにする
- **1番括弧 / 2番括弧の再生分岐**: `MeasureData.ending` をもとに、1周目は 1番括弧、2周目は 2番括弧だけを鳴らす基本分岐へ対応
- **サンプル譜での記号体験**: ピアノ用デモフレーズにはリピート、1番括弧 / 2番括弧、強弱記号を実際に入れてあり、見た目と再生の両方で確認できる
- **再生位置の視覚化**: 再生ボタンの進行に合わせて現在の音符を青くハイライトし、スクロール外に出たときは自動追従する
- **拍子の保存と復元**: localStorage には score ごとの `timeSignature` も保存し、読み込み時は無効値を安全な 4/4 へ戻す
- **拍子ごとの入力上限**: `StaffCanvas / PianoSystemCanvas` は `3/8` なら 1.5 拍まで、`6/8` なら 3 拍まで、という形で小節長を判定する
- **途中拍子変更の描画**: `effectiveTimeSig` 変数を段ループの外で追跡し、`MeasureData.timeSignature` が設定されている小節では更新する。Voice 作成時にその値を使うことで、VexFlow の拍数バリデーションが正しく通る。VexFlow Voice は SOFT モードにして、拍子が変わった小節でも強制終了しないようにする
- **途中拍子変更の継続**: 小節ループ内で変更された拍子は次の小節以降も `effectiveTimeSig` として引き継がれ、新たな変更か楽譜終端まで有効になる。休符補完（`fillPriorMeasureRests`）でも `measure.timeSignature` を参照して正確な拍数で埋める
- **途中調号変更の解決**: `resolveMeasureKeySignature(measures, index, globalKey)` が「指定小節までを先頭から走査し、最後に見つかった `keySignature` を返す」共通ロジックを提供する。段頭の調号表示・臨時記号の既定状態・新規入力の既定♯♭付与のすべてがこのヘルパーの結果（`effectiveKeySig`）を参照するため、画面のどこで見ても同じ調号になる
- **編成譜での調号変更**: `PianoSystemCanvas` では調号は最上段（`partsScore[0]`）の小節データにのみ保存し、`repeatStart` / `ending` と同じ「見た目の基準は最上段」パターンに寄せる。各パートは `part.keySignature`（移調楽器用の固定シフト値）との fifths 差分を `effectiveKeySigPerMeasure` にも適用することで、既存の五度圏シフトが途中調号変更にも自動的に対応する
- **途中クレフ変更の解決**: `resolveMeasureClef(measures, index, partClef)`（`src/utils/clefMeasureUtils.ts`）が調号版と同じロジックを提供する。調号と違い、クレフは楽器ごとに別々のタイミングで変わりうるため、`PianoSystemCanvas` では最上段ではなく各パート自身の `part.data` に対して解決する。クリックハンドラなど後から呼ばれる処理では、ループ共有の `let effectiveClef` ではなく、ハンドラのスコープで確定している絶対小節インデックスから都度 `resolveMeasureClef` を呼び直すことで、クリックした小節と異なるクレフを誤って使わないようにしている
- **終止括弧の描画**: 終止括弧の保存データは小節番号だけにとどめ、描画時に前後小節を見て `BEGIN / MID / END / BEGIN_END` を自動決定する
- **現状のサンプル制限**: ピアノ用デモフレーズは編集・再生の確認を優先した短い説明用データであり、独立テキスト記号や曲全体の完全採譜までは含めていない
- **固定ヘッダーの高さ自動計測**: タブ切り替えでツールバーの高さが変わっても、本文が下へ潜り込まないよう `ResizeObserver` で余白を同期する
- **ページ段数の同期計算**: 編成譜と単旋律で 1 ページあたりの段数が違うため、表示ページは state に残さず現在の楽譜種類と画面幅から毎回計算する
- **強弱の保存検証**: `dynamics.value` は許可済み文字列だけを localStorage から受け入れ、未知の値が描画や再生へ流れないようにする
- **強弱の再生解決**: `dynamicMarkingUtils.ts` で絶対強弱と `cresc.` / `dim.` の段階変化を共通計算し、`ScorePage -> PlaybackEngine.playParts()` の現在経路でも譜面再生音量へ反映する
- **奏法記号の保存と描画**: `NoteEvent.articulations` に文字列の配列で保持し、`storage.ts` で許可済みの値だけを受け入れる。描画は VexFlow の `Articulation` モディファイアを `makeVFNote` で符頭へ付ける（フェルマータ・マルカートは上付きに固定）
- **奏法記号の再生反映**: `articulationMarkingUtils.ts` が各記号を「音の長さ倍率 / 音量倍率」へ畳み込み、`ScorePage` で強弱由来のベロシティへ掛け合わせる。長さ倍率は `PlaybackMeasureEvent.durationScale` として両エンジンへ渡し、発音の長さだけ伸縮させる（次の音までの間隔は変えない）
- **編成データの保存**: `SavedScoreData.instrumentation` に編成テンプレートとパート定義を保存し、旧データでは省略可能として後方互換を保つ
- **可変編成の描画**: `ScorePage` で `ensemble` モードを持ち、`EnsembleStaff` から既存の N 段対応 `PianoSystemCanvas` へパート配列を渡す
- **カスタム編成の同期**: パート追加・削除・並び替え時は、編成定義と実際の小節データ配列を同じ順序で更新し、表示と保存のずれを防ぐ
- **パート編集の別ウィンドウ化**: `window.open()` した別ウィンドウへ `createPortal()` で編集 UI を差し込み、総譜画面を残したまま編成を調整できる
- **パート別音色の再生**: `PlaybackPart.instrument` を通して各パートの音色を再生エンジンへ渡す。内蔵音源は同じ開始時刻へ楽器別に予約し、SoundFont はパートごとのプレイヤーを読み込んで同時刻に予約する

### 6. 和音（複数音符の同時配置・再生）
- `NoteEvent.keys: string[]` が単音・和音の両方を表現（単音も長さ1の配列）。v2→v3マイグレーションで旧データを自動変換。
- 音符の上をクリックすると和音追加になる。Shift キー不要。追加後は `keyToLine` で昇順ソートし、VexFlow が期待する「低音から高音」の配列順を維持。
- **和音ゾーン判定**: X方向は `getBoundingBox()` で取得した実際の符頭描画範囲（単旋律は左右 ±1.2px、ピアノ/複数パートは左右 ±1.5px）。Y方向は五線 ± 3加線の固定範囲（`getYForLine(-3)` 〜 `getYForLine(7)`）。ゾーン外のクリックは新規音符挿入になる。
- `vf-note-hit` rect を和音ゾーン全体の高さに設定することで、加線域へのクリックも正しく捕捉する。
- 個別音選択では、クリックYを五線の線/間へ丸めたあと `keys[]` の何番目かを `keyIndex` として保存する。
- キーボードハンドラは `keyIndex` があるとその1音だけ、ないときは `ev.keys.map(k => ...)` で全音を均等にシフト（音程を保ったまま移動）。
- PolySynth の `triggerAttackRelease(noteArray, ...)` が和音を1回の呼び出しで同時発音。`ScorePlayer` も `note: string[]` を保持し、スコア再生でも和音が鳴る。

### 6.5 自動休符補完
- `fillPriorMeasureRests()` が、現在編集しようとしている小節より前の小節だけを確認する。
- 小節内の既存イベントの拍数合計を出し、拍子に対して足りないぶんを `buildRestEventsForBeats()` で休符へ変換して末尾へ追加する。
- 休符は大きい音価から順に作るため、空の 4/4 小節は全休符 1 個になり、1.5 拍不足なら 4分休符 + 8分休符のように分かれる。
- 背景クリックだけでなく、休符本体の置換・分割でも補完を先に行い、補完後の小節密度で幅調整が走るようにしている。
- 単旋律譜は `StaffCanvas.tsx`、複数段譜は `PianoSystemCanvas.tsx` に同じ考え方の実装がある。

### 7. 臨時記号（シャープ・フラット・ナチュラル）
- 音高データは既存どおり `keys` に保存し、`f#/4` や `bb/3` のように表現する。
- 描画時は小節ごとに `Map<音名/オクターブ, 現在有効な臨時記号>` を持ち、必要な位置にだけ `# / b / n` を付ける。
- 同じ小節内で同じ状態が続く場合は記号を省略し、変化した音を自然音へ戻したときだけ `n` を表示する。
- 保存時は `src/utils/storage.ts` で音高キー文字列を検証し、未知の文字列が描画系へ流れ込まないようにしている。

### 7.5 微分音（四分音）の臨時記号
- `keys`（音高文字列）は変えず、`NoteEvent.microtones?: { keyIndex: number; type: 'quarterSharp' | 'quarterFlat' }[]` という独立フィールドで持つ。keyIndex は `keys` 配列のインデックス（和音の何番目の音か）に対応する。
- 通常の `♯/♭/♮` とは排他: 片方を適用するともう片方はその keyIndex から取り除かれる（`StaffCanvas.tsx` / `PianoSystemCanvas.tsx` の `applyAccidentalToEvent` / `applyMicrotoneToEvent`）。
- 描画は VexFlow の Accidental に `'+'`（四分音上げ）/ `'d'`（四分音下げ）を渡すだけ。通常の臨時記号の「小節内で持続する」ロジックとは独立させ、毎回明示的に表示する。
- 再生は `frequency *= 2 ** (cents / 1200)` で ±50セントを反映する（`SimpleAudioEngine.noteToFrequency` の `centsOffset` 引数、`NotePlayer.playNoteEvent` の `Tone.Frequency(...).toFrequency()` 経由の数値周波数）。

### 8. タイ／スラー（TieArc）入力と編集

#### データモデル
- `NoteEvent.arcs?: TieArc[]` に弧情報を保存。`fromKey`/`toKey` で和音内の個別符頭を指定。`kind: 'tie' | 'slur'` で種別を区別。
- 調節量は `cpDyOffset`（曲率）、`startDx/Dy`・`endDx/Dy`（始終点オフセット）、`flipDirection`（向き反転）として保存。すべて optional なので既存データに影響なし。

#### 描画（`arcUtils.ts` / `drawArcPath`）
- タイは二次ベジェ Q、スラーは常に三次ベジェ C で描画（`computeArcGeometry`）。
- 各弧を透明な幅広ヒットパス（`stroke-width:10`）＋可視パス（`stroke-width:1.5`）の2枚重ねで描画。選択中は青（`#3b82f6`）に変色。
- 段またぎ弧は `-1`（開始音符→段末端）と `-2`（次段先頭→終了音符）に分割して描画。

#### インタラクション
- **弧ドラッグ（曲率調節）**: hitPath の mousedown で cpDrag 開始。mousemove で DOM を直接更新（再レンダなし）。mouseup で `cpDyOffset` を保存。
- **向き自動反転**: 曲率ドラッグ中にカーソルが音符クラスタを 20px 超えると `flipDirection` が自動トグル。
- **始終点ドラッグ**: 選択中の弧に青い丸ハンドルを表示。ドラッグで `startDx/Dy` または `endDx/Dy` を調節。
- **Delete キー優先順位**: スラー選択中は Delete で弧のみ削除（音符は残る）。音符選択中は従来通り音符を削除。

#### arcGeomMap
各弧の形状パラメータ（座標・向き・ep オフセット・cpDyOffset）を `useEffect` 内で保持。ライブドラッグ時の再計算に使用し、React 再レンダを経由しないで応答速度を確保する。

### 9. N 段譜表の汎用レンダリング（弦楽四重奏対応）
- `PianoSystemCanvas` を `partsConfig: PartConfig[]` prop で N 段対応に一般化。
- `computeLayout(n)` が段数に応じて `staveYs`・`sysH` を動的に算出（`STAVE_SPACING=80px`）。ピアノ（N=2）は従来値と完全一致。
- `StaveConnector` を N=2 で BRACE（ピアノ）、N>2 で BRACKET（オーケストラ）に自動切替。
- **アルト記号（ハ音記号）**: `clefUtils.ts` の `lineToKey('alto', line)` が `G4=line0, C4=line2` を基準に音高を計算。VexFlow 5 はネイティブで `'alto'` 文字列に対応。

## クリック精度のチューニング

`src/components/StaffCanvas.tsx` の定数で調整できます。

```ts
// 線の中心 ± (spacing * LINE_PAD_RATIO) に入れば即スナップで線確定
const LINE_PAD_RATIO = 0.18; // 例: 0.15〜0.25

// 線候補の距離スコアに掛ける係数（1 未満で線を優遇）
const LINE_BIAS = 0.82; // 例: 0.7〜0.9
```
- 線に置きづらい → `LINE_PAD_RATIO` を上げる、または `LINE_BIAS` を下げる
- 間に置きたいのに線に吸われる → `LINE_PAD_RATIO` を下げる、または `LINE_BIAS` を上げる

### 段/パート間の当たり判定（隣に吸われないようにする仕組み）

小節ごとのクリック当たり判定 rect（`rect.vf-hit`）は、加線域までクリックしやすいように五線の上下へ余白（`StaffCanvas.tsx` の `EXTRA_TOP_LINES`/`EXTRA_BOTTOM_LINES`、`PianoSystemCanvas.tsx` の `EXTRA_TOP`/`EXTRA_BOTTOM`）を持たせています。この余白が段の間隔（`gap`）やパートの間隔（`STAVE_SPACING`）より広いと、隣の段・パートの当たり判定と縦方向に重なり、「2段目をクリックしたのに1段目の超低音として置かれる」ような誤配置が起きます。

これを防ぐため、当たり判定 rect の上端・下端は必ず「隣接する段/パートとの中間点（`line0` 同士の中間）」でクリップしています。中間点は五線の基準位置 `stave.getYForLine(0)` を基準に上下対称に計算する必要があり、上端と下端で異なる基準点（例: 上端は `line0`、下端は `line4`）を使うと五線の高さ分だけ再び重なってしまうので注意してください。段/パートの間隔を変更した場合は、このクリップ計算（`halfGapY`/`halfPartGapY`）が新しい間隔に追従することを確認してください。

## 最小チェック

### 楽譜編集
- scale=1.0 / 0.86 / 0.8 で E4→G4→B4→D5（ミ・ソ・シ・レ）が狙い通り置ける
- その他タブの「画面表示のズーム」を 150%・70% にしても、クリックした位置に狙い通り音符が置けること（自動縮尺との合成後も座標変換が追従すること）
- ズームを変更してリロードしても設定値が保持されること。ズームの値に関わらず印刷結果（`@media print` のレイアウト）が変わらないこと
- その他タブの「音符の大きさ」を 80%・100%・130%・150%・200% にしても、`svg[data-layout-overflow="true"]` が出ないこと（自動改段が追従すること）、クリックした位置に狙い通り音符が置けること、リロード後も設定値が保持されること
- 「音符の大きさ」を 150%・200% にしたとき、「段数/ページ」の上限が自動で下がること（入力欄の `max` とツールチップ表示も追従）、`.print-page` に `scrollHeight > clientHeight`（縦あふれ）が起きないこと、隣接する段の SVG 矩形が重ならないこと
- 線の上クリックでも間に吸われない
- 16 分×3 + 二分 などでも小節から溢れない
- 休符は 1 回目のクリックで選択でき、Delete で削除できること
- 新しく置いた休符と空小節の休符は、初期状態で五線の下から 2 本目の線に見えること
- 選択した休符は ↑/↓ で高さを動かせること
- 音符ツール時は、同じ休符をもう一度クリックすると置換・分割入力できること
- 音符を数個置いてから `Cmd/Ctrl+Z`（または「元に戻す」ボタン）で1操作ずつ取り消せること
- 取り消した後に `Cmd/Ctrl+Shift+Z`（または「やり直す」ボタン）で復元できること
- Undo 後に新しい編集をすると、それより先の redo 履歴が破棄され「やり直す」ボタンが再び無効化されること
- 途中テンポ変更（♩=XXX）を設定してから Undo すると、♩=XXX の表示とデータの両方が元に戻ること（Redo で再度反映されること）
- ピアノ譜の再生では、3/8 のような拍子でも左右手が同じ小節長でそろうこと
- ピアノ譜のリピート記号と 1番/2番括弧は、片手だけに入っていても全段が同じ順番で再生されること
- ピアノ譜では、現在の編集中譜面を「いまの譜面」サンプルとして保存し、あとでサンプル欄から再読込できること
- 拍子記号はいまの仕様では譜面全体のいちばん最初だけに表示されること
- 音符を新規配置したときや、休符を音符へ置換・分割したときに確認音が鳴ること
- 音符を新規配置した瞬間の確認音も、再生パネルで現在選んだ楽器音色に追従すること
- 次の小節を編集し始めると、前の未完成小節に休符が自動で入ること
- 五線外へ音符を置くプレビューで、短い加線も一緒に表示されること
- 3連符トグルON＋8分音符ツールで五線をクリックすると、音符1つ＋休符2つの3連符グループ（ブラケットと「3」表示）が一度に置かれること
- 5連符/6連符/7連符トグルON＋音価ツールで五線をクリックすると、音符1つ＋連符内休符(N-1)個のグループ（ブラケットとN:4表示）が一度に置かれ、1拍にちょうど収まること
- 3連符内の休符を同じ音価の音符ツールでクリックすると、tuplet情報を保ったまま音符に置き換わること
- 3連符内のどれか1つをDeleteすると、グループ全体が同じ長さの通常の休符に置き換わること
- 3連符を含む譜面を保存→再読込しても連符表示が保たれること
- 3連符を含む譜面をMusicXMLとして書き出し→読み込みしても連符情報が保たれること
- 5連符を含む譜面を保存→再読込しても連符表示・比率が保たれること
- ピアノ譜で声部トグル（またはVキー）を声部2に切り替えて音符を入力すると、符幹が下向きで既存の声部1に重ねて表示されること
- 声部2に切り替えると、声部1の音符がグレーに淡色表示され、声部1に戻すと逆に声部2がグレーになること（声部1しかない小節・単旋律譜/弦楽四重奏では常に黒のままであること）
- 声部2でクリック位置に音符を挿入できること、既存の声部2音符の真上をクリックすると和音が追加されること
- 声部2の音符に臨時記号・強弱記号・カスタム記号の付け外しができること
- 声部2の音符はクリックで選択でき、Delete/Backspaceで削除できること
- 声部1・声部2を両方入力した小節を再生すると、両声部が同じタイミングで同時に鳴ること
- 声部を使った譜面を保存→再読込しても声部2の音符が復元されること
- 声部1しかない小節・単旋律譜・弦楽四重奏で、これまで通りクリック位置への挿入・和音追加ができること（リグレッション確認）
- 小節選択ツールで小節を選ぶと、その他タブに「移調」ボタンが現れること
- 「移調」→「全音上」で選択小節の全音符が2半音上がること（例: a/4 → b/4）
- 「移調」→「オクターブ下」で1オクターブ下がること
- 和音・臨時記号付きの音を含む小節でも、全音がまとめて正しく移調されること

### 🎵 音符再生
- 異なる高さの音符で音高が変わることを確認
- 異なる音価で再生時間が変わることを確認
- 再生ボタンで譜面全体が順次再生されることを確認
- 音符クリックで個別再生されることを確認
- スウィング再生トグルOFFで8分音符を8つ並べて再生すると均等に鳴ること
- スウィング再生トグルONで同じ譜面を再生すると「タッタ・タッタ」と跳ねて聴こえること
- スウィングONでも4分音符・3連符・付点音符・16分音符は均等なままであること
- スウィング設定はリロード後も保持されること（LocalStorage）
- 内蔵音源・SoundFontのどちらに切り替えてもスウィングが効くこと

### 和音
- 音符を配置後、同じ音符の上（和音ゾーン内）をクリックすると和音に追加されること（Shift 不要）
- ゾーン外（セル内の空白部分）をクリックすると新規音符が挿入されること
- 矢印キーで和音全体が移動し、音程が保たれること
- 和音内の1音をクリックすると、その音だけ小さい青枠で選択できること
- 和音内の1音を選択して Delete / ↑/↓ / 臨時記号を使うと、その音だけが変わること
- 和音クリック時に全音が同時に鳴ること
- 保存 → 読み込みで和音データが正しく復元されること（旧データの単音も自動変換）
- その他タブの「新規作成」で、確認後に空の単旋律譜へ戻り、古い保存譜面が読込で戻らないこと

### タイ／スラー
- タイモードで同音をドラッグ → タイ（同じ音高間の黒い弧）が描画されること
- タイモードで異音をドラッグ → スラー（異なる音高間の弧）が描画されること
- 弧をクリックすると青くハイライトされ、始終点に青いハンドルが表示されること
- 弧をドラッグすると形状（曲率）がリアルタイムで変わり、離すと保持されること
- 始点または終点ハンドルをドラッグすると接続位置が移動すること
- 段またぎ弧では切れ目の上下ハンドルをドラッグして分割位置を調節できること
- 弧を大きく音符の反対側へ引っ張ると弧の向きが反転すること
- Delete キーで選択中の弧のみが消え、音符は残ること
- Escape で弧の選択が解除されること
- 保存 → 読み込みでタイ／スラーと全調節量が正しく復元されること

### 弦楽四重奏
- 「弦楽四重奏」ボタンで 4 段譜面が表示されること
- Viola 段にアルト記号が表示され、中央線が C4 になること
- Vn. I / Vn. II / Va. / Vc. それぞれ独立して音符を配置できること
- 角括弧（BRACKET）が 4 段全体に表示されること
- 全体再生で 4 パート同時に音が出ること
- 保存 → 読み込みで各パートが正しく復元されること
- ピアノモードに切り替えても BRACE とレイアウトが崩れないこと

### パート譜の抽出
- 弦楽四重奏・編成譜で「その他」タブの「パート譜表示」からパートを選ぶと、単一五線＋パート名の表示に切り替わること（弦楽四重奏の Viola はアルト記号のまま表示されること）
- パート譜表示中に音符クリックしても編集が反映されない（閲覧・印刷専用）こと
- 「総譜（通常）」に戻すと、元の総譜（括弧・全パート）がそのまま表示されること
- 単旋律譜・ピアノ大譜表では「パート譜表示」セレクト自体が表示されないこと
- 保存・読込・リロード後は必ず「総譜（通常）」に戻ること（表示モードは保存されない）
