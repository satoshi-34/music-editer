# 設計書: 調号（Key Signature）実装

## 概要

臨時記号の基盤は入っていたが、譜面全体の前提となる調号は未実装だった。  
このため、`G` 系なら本来 `F#` が既定になる場面でも、入力・再生・表示のすべてが「自然音前提」で動いていた。

今回の実装では、**調号の保存**, **各システム先頭への描画**, **新規入力と通常の上下移動への既定反映**, **臨時記号表示ルールとの統合** を追加する。

## 変更方針

### 1. 保存形式に `keySignature` を追加する

`SavedScoreData` に `keySignature` を追加する。  
ただし旧データ互換のため、読み込み時に値が無ければ `C`（調号なし）として扱う。

- 現行保存時は必ず `keySignature` を含める
- 旧データは `normalizeKeySignature()` で `C` に補正する
- 保存フォーマットのバージョンは `3.1.0` に上げる

### 2. 調号は「調名」ではなく「調号ファミリー」として扱う

内部値は VexFlow にそのまま渡せる `C / G / D / A / E / B / F# / C# / F / Bb / Eb / Ab / Db / Gb / Cb` を使う。  
UI 表示では `G dur / e moll` のように、同じ調号を共有する長調・短調を補足する。

この方式にすると:

- 五線冒頭の描画は `stave.addKeySignature()` へそのまま渡せる
- 調号由来の既定 `# / b` を簡単に計算できる
- 長調・短調の区別が未実装でも、最低限「何個の調号か」は正しく扱える

### 3. 調号込みの既定音高を新規入力へ反映する

`lineToKey()` 自体は従来どおり自然音の線・間だけを返す。  
その上で、入力確定時に `applyKeySignatureToNaturalKey()` を通し、

- `G` 系で `f/4` を置こうとしたら `f#/4`
- `F` 系で `b/3` を置こうとしたら `bb/3`

へ自動補正する。

この処理を入れる対象:

- 五線クリックによる新規入力
- 和音追加
- `Alt` なし / `Shift` ありなしの上下移動

`Alt + ↑/↓` の半音移動は明示的な臨時記号操作なので、そのまま MIDI ベースで扱う。

### 4. 小節ごとの臨時記号状態は調号で初期化する

`createMeasureAccidentalState()` を調号対応に広げ、小節開始時点の既定状態を seed する。

例:

- `G` 系なら各オクターブの `f/*` を `#` で初期化
- `F` 系なら各オクターブの `b/*` を `b` で初期化

こうすると:

- 調号どおりの `f#/4` は小節冒頭でも臨時記号不要
- 同じ小節で `f/4` を置いたときだけ `n` が出る
- そのあと再び `f#/4` に戻したら `#` が出る

### 5. 五線の各システム先頭に調号を描く

`StaffCanvas` と `PianoSystemCanvas` の各システム先頭小節で:

1. `addClef()`
2. 必要なら `addTimeSignature()`
3. `addKeySignature()`

の順で追加する。

`C` のときは見た目上の調号が無いので `addKeySignature()` を省略する。

## UI/操作ルール

- ツールバーに `調号` セレクトを置く
- `♯ / ♭ / ♮` ツール選択中に各システム先頭の行頭をクリックした場合は、音符入力ではなく調号変更として扱う
- 既存の音符セルをクリックした場合は臨時記号を優先し、音符が無い場所や空小節の調号領域だけを調号変更として扱う
- 拍子記号がある段では、調号領域を「拍子記号の右から音符開始位置まで」に合わせる
- 調号領域が狭すぎて押せない状態を避けるため、最小クリック幅を確保し、臨時記号ツール中は薄い帯で領域を可視化する
- 調号クリック時はコンソールへ現在値・次値・クリック座標・判定範囲を出し、Safari などブラウザ差異の切り分けをしやすくする
- 行頭の `♯` はシャープ系調号を1段進め、`♭` はフラット系調号を1段進める
- 反対系統へ切り替える場合は、いったん `♯1つ` または `♭1つ` から始める
- `♮` は `C` へ戻す
- 既存音の一括移調は行わず、調号変更後の**新規入力と通常移動**から既定音高へ反映する
- 臨時記号ボタンは従来どおり使え、調号に逆らう音では必要な `n / # / b` が自動表示される

## セキュリティと堅牢性

- 保存データの `keySignature` は許可リストで検証する
- 旧データや不正値は `C` に正規化し、未知文字列を描画 API に渡さない
- 調号表示の有無だけでなく、内部キー文字列も補正して再生音との食い違いを防ぐ
