# 設計書: 音符選択中の ←/→ で選択を隣の音符へ移す（Issue #442）

弟フィードバック（2026-08-28）「音符選択時に左右矢印で選択している音符を変更したい」への対応。

## 問題

音符を選ぶ手段はクリックだけだった。↑/↓ で音高を直せるところまでは来ているのに、
「次の音符を直す」にはマウスへ手を戻して符頭を狙い直す必要がある。
入力のテンポを落とすうえ、符頭は小さく、和音や連符では狙いづらい。

一方 ←/→ には既存の割り当てがある（小節選択のカーソル移動）。
音符選択と小節選択のどちらが対象かをはっきりさせないと、押すたびに両方が動く。

## 修正設計

### 1. 「隣を探す」規則は純粋関数へ（`src/utils/noteNavigationUtils.ts`）

`findAdjacentNotePosition(measures, voiceIndex, current, direction)` が
移動先の `{ measure, index }`（無ければ `null`）を返す。規則は次のとおり。

- 同じ声部だけをたどる（`getVoiceEvents` 経由。声部2の選択は声部2の中だけを動く）
- 音符・休符の区別はしない（どちらも選択でき、Delete や ↑/↓ の対象になるため）
- 小節の端まで来たら隣の小節の先頭 / 末尾へ移る
- **まだ何も書いていない小節は飛ばす**（空小節で止まると書きかけの譜面で先へ進めない）
- 曲頭・最後のイベントでさらに進もうとしたら `null`（呼び出し側が通知する）

選択が譜面の外の小節を指したまま残っている場合（Undo で小節数が縮んだ直後など）に備え、
探索の開始位置は配列の中へ丸める。丸めないと後方探索の for 文が1周もせず、
手前に音符があるのに「もう前が無い」と誤って答える。

### 2. 段（システム）をまたぐ移動は引き継ぎイベントで

譜面は1段ごとに別の `PianoSystemCanvas` インスタンスが描いており、
**選択状態（青枠）もインスタンスごとに持っている**。自分が描いていない小節へは
自分で青枠を出せないため、移動先が自分の段の外なら
`requestNoteSelectionMove()`（`SCORE_NOTE_SELECTION_MOVE_EVENT`）で引き継ぎを頼み、
その小節を描いている段が受け取って選択する。

props ではなく window の CustomEvent なのは、通知（`notifyScoreEdit`）・声部切り替えと同じ理由
（あいだに5つのラッパーが挟まっており、コールバックを通すと5ファイルを機械的に書き換えることになる）。

受け取り側の条件は2つで、**どちらも必要**である。

| 条件 | 無いとどうなるか |
| --- | --- |
| 移動先が自分の段の小節範囲にある | 関係ない段が選択を主張する |
| その小節の、その位置に実際にイベントがある | **空の段**（Issue #41 のフィラー）が範囲だけ名乗って選択を主張し、選択の一意化（`SELECTION_CLAIMED_EVENT`）で本物の段の青枠まで消し合う |

2つ目は実装中に実際に踏んだ。空の段は譜面データを持たないまま `startMeasureIndex=0` /
`measuresPerSystem=4` を名乗るため、範囲だけの判定では複数の段が同時に選択を主張し、
互いに解除し合って**どこにも青枠が残らない**状態になった。

パート譜編集は別ウィンドウ（`window.open` + `createPortal`）へ描かれるがリスナーは同じ window に並ぶため、
要求元の `document` を detail に載せ、違う document の段は無視する。

### 3. 小節選択の ←/→ との棲み分け

音符が選択されているときは音符側が優先し、`e.preventDefault()` でキーを消費する。
`ScorePage` 側の keydown ハンドラは先頭で `if (e.defaultPrevented) return;` を見ており
（PR #414 で入った既存の仕組み。リスナーの登録順は常に「キャンバス → ScorePage」で安定）、
青枠と小節ハイライトが同時に動くことはない。

修飾キー付き（`Shift+←/→` の範囲拡張など）は従来どおり `ScorePage` 側へ渡す。
音符選択中の ←/→ に修飾キーの意味を新設しない、という線引き（Issue の「既存挙動を変えない」）。

移動先では `keyIndex`（和音の中の1音）を落として**イベント全体の選択**に戻す。
移動先の和音に同じ位置の符頭がある保証がないため。

### 4. 端では喋る（#318）

`describeNoteNavigationEdge(direction)` を `scoreEditorNotices.ts` に置いた。

- → の端: 「最後の音符です（続きを書くには、次の小節の五線をクリックして音符を置いてください）」
- ← の端: 「最初の音符です（前に足すには、手前の小節の五線をクリックして音符を置いてください）」

譜面は変わらないので `UNDO_HINT` は付けない（`dead-end-speaks/design.md` の線引き）。

## 影響範囲

| ファイル | 変更 |
| --- | --- |
| `src/utils/noteNavigationUtils.ts` | 新規。隣を探す純粋関数 |
| `src/utils/scoreEditorNotices.ts` | 引き継ぎイベント（名前・型・`requestNoteSelectionMove`）と端の文言を追加 |
| `src/components/PianoSystemCanvas.tsx` | keydown に ←/→ の分岐、引き継ぎイベントの受け取り、`latestRef` に段の小節範囲を追加 |
| `README.md` | キーボードショートカット表の `←/→` の行を更新 |

`ScorePage.tsx` は変更していない（`defaultPrevented` の仕組みが既にあるため）。

## 最小チェック（手動）

- [ ] 音符をクリックして選択 → → を押すと青枠が右隣の音符へ移る
- [ ] 小節の最後の音符で → を押すと次の小節の先頭へ移る（段が変わっても移る）
- [ ] 曲の最後の音符で → を押すと青枠は動かず、画面下端に「最後の音符です…」が数秒出る
- [ ] 移動した先で ↑/↓ ・ Delete がその音符に効く
- [ ] 小節選択ツールで小節を選んでいるとき（音符は未選択）の ←/→ は従来どおり小節が動く
