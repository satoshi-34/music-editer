## 2. 分類基準の提案（3層）

運用者方針「パレットをごちゃごちゃさせない」（#520 系）を、判定できる形に落とす。

| 層 | 定義（判定基準） | 置き場所 |
| --- | --- | --- |
| **L1: 毎回使う** | 1曲を1回書き上げる間に**ほぼ必ず**使う。使えないと作業が止まる | 表に出したまま（折りたたみ禁止） |
| **L2: たまに使う** | 使う曲と使わない曲がある。無くても曲は完成する | 折りたたみ・詳細パネル・ドロップダウンへ。**1クリックで開ける**こと |
| **L3: 診断・復旧** | 音が出ない等の**異常時にだけ**使う。正常時に押す意味がない | 診断セクション（またはヘルプ）へ集約 |

補助原則:

1. **L2 へ畳んでよいのは「探して見つかる」もの**だけ。名前から場所が推測できない操作は L1 に残すか、
   ヘルプの導線を同時に用意する
2. **同じ意味の記号を2回出さない**（§5 の臨時記号がこれに違反している）
3. **段0 で頻度が確定しないものは L1 に残す**（畳んで困る方が、出ていて困るより実害が大きい）。
   微分音（#89 のインタビュー待ち）はこの規則で当面 L1
4. **キーボードショートカットのあるものは畳みやすい**（`.` 付点・`V` レイヤー切替・`R` 等）。
   畳む判断とショートカットの整備はセットで考える

この基準を §1 の表へ当てると、L3 は現状 **2 個**（音声復旧・最小テスト音）、
L2 候補は **60 個以上**（タイトル書体・表示ウェイト・ツールバー位置・段組・タイトル余白・
装飾音・オッターバ・記号調整・カスタム記号・サンプル系・音色詳細の中身など）になる。

## 3. 具体案

### (a) 音声復旧＋最小テスト音を「診断」へまとめる（L3） — **実施済み（Issue #562・2026-09-03）**

- **現状**: 再生・音色タブの表に常時2つ並ぶ。正常時は一度も押さないボタンが、毎回使う
  再生/テンポ/音量と同じ列にいる
- **案**: 「音の調子がおかしいとき ▾」（仮）1個に畳み、中へ **音声復旧・最小テスト音・
  現在の音源方式の表示**をまとめる。無音検知の通知（silent-failure-detection）から
  この折りたたみを開くリンクを張れば、必要な人には最短で届く
- **効果**: 表の常設が 10 → 9（#545 追加後は 11 → 10）
- **注意**: 音が出ない状況＝利用者が困っている状況なので、**畳んだせいで発見できないと逆効果**。
  通知からの導線を同時に用意することが条件

### (b) 音色詳細系の折りたたみ — **実施済み（Issue #562・2026-09-03）**

- **現状**: 「音色詳細」は既に折りたたみ済みで、この点は方針どおり。ただし中身9個が
  平坦に並んでおり、音源方式（接続の設定）と音作り（明るさ・アタック感・余韻・厚み）が
  同列に見える
- **案**: 音色詳細の中を「音源」（方式・パック名）と「音づくり」（4スライダー・スウィング・
  確認音）の2見出しに分ける。**開閉の状態を覚える**（localStorage）と、音作りを詰める人の
  往復が減る
- **効果**: ボタン数は変わらないが、探す時間が減る。移行リスクが最も小さい案

### (c) #544/#545 追加後の再生・音色タブのレイアウト案 — **実施済み（Issue #562・2026-09-03）**

追加予定を織り込んだ表の並び（左から）:

```
[▶ 再生] [■ 停止] | [♩=___ ＋スライダー] [小節 ___ から] | [音色 ▼] [🔊] [音量 ▬] | [音色詳細 ▾] [音の調子がおかしいとき ▾]
```

- 3つの区画（**トランスポート / テンポ・位置 / 音**）に分け、区切りを見せる
- **再生速度（%）の欄は置かない**（#588 で #544 ごと撤去。当初案では「♩=N が譜面の属性、
  % が再生時の倍率」という対比が並びから読めるようテンポの隣に置く予定だったが、
  運用者裁定で速度そのものが無くなったため、テンポ・位置の区画は
  「作品の基準テンポ」と「小節番号ジャンプ」の2つになる）
- #545 の「小節番号ジャンプ」は**トランスポートの一部**。ただし既存の「小節を選択してから
  再生するとそこから鳴る」（playback-from-measure）と機能が重なるため、**入力欄を常設するか、
  再生ボタンの長押し/横の ▾ に畳むか**は #545 側で決める。段0としては「重複した入り口を
  2つ常設しない」ことだけを条件にする
- 「音色プレビュー（🔊）」は音色セレクトの直後に置いて**セレクトの付属品**に見せる（独立ボタンに
  見せない）

### (d) 音符・休符タブの分割（最大の過密・§5 とセット）

49個は6タブ中で最多。§5 の臨時記号統合（-5〜-7個）に加えて:

## 5. 最優先: 臨時記号の列（案A〜D の比較と推奨）

> **続き**: 案D の詳細設計は `.claude/specs/accidental-palette-unification/design.md`（#548）へ引き継いだ。
> 本節の受入テスト草案10ケースは、そちらで14ケースへ更新している。

### 現状の問題

音符・休符タブに、**同じ記号が意味違いで2家族・13個以上**並んでいる:

- 付与家族（5個＋微分音2個）: 選択して**既存の音符をクリック**すると、その音符に付く
- 入力家族（5個・#470）: ONにしておくと、**これから置く音符**に付く（表記は ♩♯ のように ♩ 付き）

見た目の差は先頭の ♩ だけで、初見で区別できない。テスト会で実際に戸惑いが観測された箇所。

### 案の比較

| 案 | 内容 | ボタン数 | 長所 | 短所 |
| --- | --- | --- | --- | --- |

### 案D で詰める点（#547 コメントの5点への回答案）

1. **音価ツールとの共存**: 臨時記号は音価・付点・連符と**独立したトグル**のままにする
   （現行の入力家族と同じ）。臨時記号ONのまま音価を変えても記号は保持する
2. **トグルOFFの規則**: 現行踏襲（同じ記号を再クリックでOFF・別の記号を押すと切替）
3. **誤クリック対策**: 空きクリックで音符が生えるのは**現行の入力家族と同じ挙動**なので、
   新しい危険は増えない。Undo 1回で戻ること（undo-redo）と、既存のドラッグしきい値
   （#522 の 3px）をそのまま使うことを受入条件に入れる
4. **ショートカット（#547 コメントの記述を実装で確認して訂正）**: コメントには
   「`R` キー（臨時記号なし入力）」とあるが、実際の `R` は**休符入力モードのトグル**
   （`ScorePage.tsx:3274`）である。そして休符へ切り替えるときに**入力用臨時記号を捨てる**
   処理が入っている（#470 round1 P2・#318: 残すと「♯がONなのにクリックしても効かない」
   無言の行き止まりになるため）。
   案Dでは付与と入力が1組になるため、この「休符に切り替えたら記号を落とす」規則を
   **どう引き継ぐか**を決める必要がある。推奨は現行踏襲（休符へ切り替えたら臨時記号は解除）。
   統合後は同じボタンが付与ツールも兼ねるので、「休符ツール中に臨時記号を押したら音符へ戻す」
   （現行 #470 の挙動）と合わせて、往復しても迷子にならないことを受入条件（ケース6）で固定する
5. **既存テストの移行**: `ScorePageInputAccidentalWiring.test.tsx` ほか、`aria-label` の
   「入力時に付ける臨時記号: シャープ」に依存するテストが移行対象（§6）

### 8-2. 設計判断のメモ

- **区画は `<section aria-label>`（暗黙の role=region）にした**: 見た目の区切り線だけでは、画面を読み上げで使う人にまとまりが伝わらない。名前付きの region にしておけば「今どのまとまりを触っているか」が伝わり、テストからも `getByRole('region', { name })` で区画ごとの中身を固定できる
- **診断の開閉は記憶しない**: 音色詳細と違い、前回の異常時に開いたまま残ると「正常なのに毎回診断が開いている」状態になる。異常時に開く道具なので、既定は常に閉じる
- **診断の中身が0個なら折りたたみ自体を出さない**: `onAudioRecovery` も `onEmergencyBeep` も渡らない使い方では、押しても何も無い見出しだけが残って空振りさせるため
- **音源方式の表示名を `SOUND_ENGINE_MODE_LABELS` に集約**: セレクトの選択肢と診断の「現在の音源方式」で同じ日本語を2か所に書くと、片方だけ直る事故になる（「同じロジックの2枚目を作らない」原則）
- **再生速度（%）は #588（#544 の取り下げ）で撤去済み**: 本PRの実装当初は「テンポ・位置」区画に含めていたが、main 統合（#590）で欄ごと無くなった。区画整理で復活していないことはテストで固定している

### 8-3. 影響範囲

- **移行したテスト**: `PlaybackControls.test.tsx` の2件（「すべての制御要素が表示される」「音声復旧ボタンのクリックで…」）は、`音声復旧` が常設ではなくなったため折りたたみを開く操作を足した。`aria-label` は既存のまま変えていないので、それ以外の参照箇所は無改修

## 9. 実装記録: 音価グリッド（音符の下に同じ音価の休符）（Issue #577・2026-09-05）

運用者指示「四分音符ボタンの下は四分休符、全音符の下は全休符みたいにできないかな」。
§3(d)（音符・休符タブの過密）に対する、**畳まずに横幅を減らす**方向の手当てでもある。

### 9-1. 問題

音価ボタンは「音符7個」と「休符7個」が**同じ折り返し行に一列**で並んでいた
（`Palette.tsx` の `ROW1` の map と `ROW2` の map が、あいだに付点・連符・タイ・臨時記号を
はさんで別々に置かれていた）。そのため:

- **同じ音価の音符と休符が離れる**。8分休符を置きたいとき、8分音符の位置を頼りに探せない
- 横1行に14個の音価ボタンが並ぶので、この行だけで横幅を大きく使う（#547 の過密指摘）

### 9-2. 修正設計

「1列＝1つの音価」を単位にし、列の中に **上=音符 / 下=同じ音価の休符** を縦に積む。

```
[全] [2分] [4分] [8分] [16分] [32分] [64分]   ← 上段: 音符
[全] [2分] [4分] [8分] [16分] [32分] [64分]   ← 下段: 同じ音価の休符
```

- 実装は `Palette.tsx` の音符・休符セクションのみ。`ROW1`（音符）と `ROW2`（休符）の
  同じ添字どうしを1つの列（`DURATION_COLUMN_STYLE` の縦 flex）にまとめ、
  列を横に並べる入れ物（`DURATION_GRID_STYLE`）を1つ置く
- **CSS Grid ではなく「列の flex を横に並べて折り返す」形にした**。行ごとに7個ずつ並べる作りや
  固定列数のグリッドだと、狭い画面で折り返した瞬間に上下の折り返し位置がずれて
  「四分音符の下が四分休符」という対応が崩れる。列を単位に折り返せば対応は常に保たれる
- 音符・休符行の `div` に `alignItems: 'center'` を足した。この行で2段ぶんの高さを持つのは
  音価グリッドだけなので、他のボタン（小節選択・付点・連符・タイ・臨時記号・リピート・括弧）は
  縦中央にそろえたほうが読みやすい
- **ツールの意味は変えていない**。休符ボタンは従来どおり `onChange(restTool)` をそのまま呼ぶ
  （音符側だけが `carryInputAccidental` を通る。休符に臨時記号は付かないため）。
  `aria-label`（`音符 4分` / `休符 4分`）も変えていないので、既存テスト・キーボード操作・
  文脈バー（`uiContextBar`）はすべて無改修で通る

### 9-3. 受入テスト

| 受入条件 | テスト |
| --- | --- |
| 同じ列の上下が同じ音価で対応している | `PaletteDurationGrid.test.tsx`「同じ音価の音符と休符が同じ列に、音符→休符の順で入っている」「列は左から 全→…→64分 の順に並ぶ」 |
| 選択中がどちらか分かる | 同「音符と休符のどちらが選ばれているかが、上下それぞれの強調で分かる」 |
| 既存の入力フローに回帰なし | 同「列の音符・休符を押すと、その音価のツールへ持ち替わる」＋ `BackwardCompatibility.test.tsx` のボタン一覧（無改修で通る） |
| 実マウント配線 | `ScorePageDurationGridWiring.test.tsx`（ScorePage ごとマウントして、列の対応と下段クリックでの持ち替えを確認。**ファイルにテスト1件だけ**＝ScorePage の多重マウントで実行が終わらなくなるのを避けるため） |

### 9-4. 影響範囲・既知の限界

- 変更したのは `Palette.tsx` の `section === 'notes'` の描画のみ。ツールの型・状態・
  キーボードショートカット・`toolChangeUtils` などのロジック層は一切触っていない
- **選択中のボタンだけ 2px 大きくなる**（`btnStyle` は `border` を 1px→2px にするだけで
  `box-sizing: border-box` を指定していないため、外形が縦横 2px 伸びる）。その結果、
  音符側を選んでいる列だけ、下の休符の位置が 2px 下がる。従来も同じ理由で隣のボタンが
  2px 押し出されていた既存の挙動で、今回の並べ替えで新しく生じたものではない。
  直すには全パレット共通の `btnStyle` に `box-sizing` を入れることになり、
  すべてのボタンの実寸が変わるため #577 のスコープ外とした
- ブラウザ確認（共有 dev サーバー・ピアノ譜）: 7音価すべてで音符と休符の `x` が一致し
  （59/100/141/182/225/266/307 px）、休符が 35px 下に並ぶことを実測。8分休符ボタンを押して
  強調が下段へ移り、譜面クリックで実際に8分休符が入ること、コンソールエラーが無いことも確認
