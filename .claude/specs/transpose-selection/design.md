# 設計書: 選択範囲の移調

## 概要

README ロードマップ「選択範囲の移調 — 小節選択→半音/全音/度数単位で移調。既存の小節選択＋クリップボード機構に乗せる」を実装する。
既存の「小節選択（`Tool { mode: 'select' }` → `selectedMeasures` state）＋クリップボード（Cmd+C/V）」の仕組みに、
新しい操作として「選択範囲を半音単位で移調する」を追加する形にした。

## 問題点（実装前の状況）

- `selectedMeasures` と Cmd+C/V によるコピー・ペーストは既にあるが、音高そのものを変える操作（移調）はなかった
- 音高キー（VexFlow 形式の `"c/4"` 等）を半音移調する関数 `transposeKeyBySemitones`（`src/utils/noteKeyUtils.ts`）は既にあるが、
  - 常にシャープ系の綴りで書き戻す仕様で、調号に応じた異名同音の切り替えができない
  - 単一キーのみが対象で、和音・前打音・小節配列への適用はしていない
  - 移調結果の音域チェック（オクターブが 0〜9 の範囲を超えないか）を行っていない
- 移調楽器の実音/記譜音変換（`getKeySignatureFifths` 等）は「調号そのもの」を五度圏でずらす変換であり、個々の音符の綴りを都度選び直す機能ではないため、そのまま流用はできない

## 修正設計

### 1. `src/utils/transposeUtils.ts`（新規）

- `transposeKey(key, semitones, preferKeySignature?)`: 単一の音高キーを半音移調する。
  - 異名同音の綴りは「調号が♭系（fifths < 0）ならフラット寄り、♯系または C ならシャープ寄り」という単純規則にした（本格的な五線譜アルゴリズムではなく実用上の近似）。
    理由: 既存の移調楽器ロジックは調号自体をずらす変換であり、個々の音符ごとの綴り選択には使えないため、`getKeySignatureFifths()` で♯♭方向だけを取り出して再利用する形にした。
  - 移調結果のオクターブが 0〜9 の範囲（`noteKeyUtils.ts` の `parseNoteKey` と同じ制約 = VexFlow が扱える範囲）を外れる場合は `null` を返す。
- `transposeKeys` / `transposeNoteEvent` / `transposeMeasure` / `transposeMeasureRange`: 和音（keys 配列全体）、前打音（`graceNotes[].keys`）、1小節（`events` と `voices` の両方）、小節範囲全体、と対象を広げていく形の合成関数。
  - 休符（`isRest`）は対象外（keys を変更しない）
  - `microtones`（四分音）は `keyIndex` で紐づくだけで音高情報自体を持たないため、そのまま維持する
  - 1音でも音域を外れたら、その時点で `null`（または `{ ok: false, error }`）を返し、**呼び出し側は一切 state に反映しない**（部分適用を防ぐ）

### 2. 対応音域（音域チェックの基準）

このアプリには「加線◯本まで」のような音域バリデーションは元々存在しない（`noteKeyUtils.ts` の `parseNoteKey` がオクターブ 0〜9 の文字列パースしか制約していない）。
新規に音域制約を作るのではなく、**既存の唯一の制約であるオクターブ 0〜9（VexFlow が受け付ける範囲）** を「対応音域」として採用し、これを外れたら移調操作全体を中止する設計にした。

### 3. 適用対象パート（単声部/複数パート/複数声部の扱い）

既存の Cmd+C/V のコピー・ペースト実装（`ScorePage.tsx` の keydown ハンドラ）は、選択小節範囲を「その小節位置にある全パート」に対して適用している（ピアノ譜なら右手・左手の両方、四重奏・編成譜なら全パート）。
移調も同じ意味に揃え、`selectedMeasures` の範囲 × 全パートを対象にした（「アクティブパートのみ」ではなく「小節位置」を選択の単位として扱う既存の考え方に合わせた）。

- ピアノ譜: `rightHandData` と `leftHandData` の両方
- 四重奏・編成譜: `quartetParts` / `ensembleParts` の全パート
- 単旋律: `rightHandData` のみ

各パートの移調結果は、実際に反映する前に**すべてのパートぶんを計算してからまとめて適用**する2段階処理にした。1パートでも音域を外れる場合、他のパートも含めて一切反映しない（「途中まで移調されたパートと元のままのパートが混在する」事故を防ぐため）。

### 4. 調号の解決

移調先の綴り（♯系/♭系）の基準にする調号は、小節ごとに `resolveMeasureKeySignature()`（`src/utils/keySignatureMeasureUtils.ts`、既存）で「その小節時点で有効な調号」を解決し、`transposeMeasureRange` にコールバックとして渡す。途中で調号が変わる曲でも、各小節ごとに正しい調号を基準に綴りを選べる。

### 5. UI

「その他」タブに、選択中の小節があるとき（`selectedMeasures != null`）だけ表示される「移調」ボタンを追加した（`ScorePage.tsx`）。
既存の「Y補正」ポップオーバーと同じ `coord-correction-wrap` / `coord-panel` パターンを再利用し、クリックでポップオーバーを開く。

ポップオーバーの内容:
- 「半音上・半音下・全音上・全音下・オクターブ上・オクターブ下」の6ボタン
- 「半音数指定」の数値入力（-12〜+12）＋「半音数指定で移調」ボタン
- 音域エラー時は赤字でエラーメッセージを表示（ポップオーバーは閉じずに残す）

移調が成功したら `pushHistory()` を呼んでから state に反映するため、Undo（Cmd+Z）で元に戻せる。

### 6. キーボードショートカット

`Cmd/Ctrl+Shift+↑/↓` で半音移調（↑が半音上、↓が半音下）を割り当てた。

**キー割り当ての判断**: 単音選択時の `Alt+↑/↓`（半音シフト）、`Shift+↑/↓`（オクターブ相当の大きなシフト）と衝突しないように、修飾キーをもう1つ増やして区別する方針にした。
これらは `StaffCanvas.tsx` 内の別のキーボードハンドラ（音符が選択されているときのキー編集）で、`selectedMeasures` による小節選択とは独立した機能のため、そのままでは共存できても判別がつきにくく、ユーザーが誤操作しやすいと判断した。

## 影響範囲

- 新規ファイル: `src/utils/transposeUtils.ts`, `src/utils/transposeUtils.test.ts`
- 変更ファイル: `src/components/ScorePage.tsx`（state・ハンドラ・UI・キーボードショートカットの追加のみ。既存のコピー・ペースト・小節選択のロジックは変更していない）
- データモデル（`MeasureData` / `NoteEvent`）への変更なし。既存の保存データ・MusicXML 入出力への影響なし。

## 動作確認（ブラウザ）

- 音符を入力 → 小節選択（select ツールでその小節の空白部分をクリック） → 全音上 → 表示が正しく2半音（全音）上がることを確認（a/4 → b/4）
- Undo で元に戻ることを確認（b/4 → a/4）
- オクターブ上を6回連続で適用し、a/4 → a/9 まで正常に移調できること、そこからさらに1回（a/10 相当）を試みると
  「14小節目に対応音域（オクターブ0〜9）を外れる音があるため、移調できませんでした。」というエラーが表示され、データが変更されないことを確認
- コンソールエラーなし
