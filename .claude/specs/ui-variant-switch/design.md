# 設計書: テスト会用のUI案切替（Issue #405 段1）

Issue #405。弟テスト会でUI案を「その場で」切り替えて反応を比べられるようにするための土台。
この設計書は **段1（切替の仕組みと、いまどの案かの表示）** を対象とする。
段2（A1 文脈バー）・段3（A2 譜面側表現）は、ここで作った土台の上に別PRで載せる。

## 目的と前提

- UI は議論より実物を触ってもらう方が早く、テスト会は**一度きりの機会**なので、
  案を変えるたびに再ビルドしていては間に合わない
- 「新UIが良いか」ではなく「**現状より良いか**」を見るため、現状（`current`）を対照群として必ず含める
- テスト会用の未完成UIが本番（Vercel Production）へ漏れてはいけない

## 問題点（実装前の状況）

UI案を差し替える手段が「ブランチを切り替えて再ビルドする」しか無かった。
テスト会の場で「じゃあもう一方も見せて」と言われても即座に応えられない。

## 修正設計

### 切替の経路

`?ui=a1|a2|current` というURLパラメータで選び、`localStorage` に記憶する。
弟の端末にはURLを送るだけでよく、リロードだけで切り替わる。

### 適用する案の決め方（`resolveUiVariant`）

判定は `src/utils/uiVariant.ts` の純粋関数 1 本に閉じている。
「URLパラメータ」「記憶している値」「開発ビルドかどうか」の3つだけを入力に取り、
`window` や `import.meta.env` を直接読まない。**本番ビルドで `current` に固定されること**を
テストから直接確かめられるようにするための構造。

| 条件 | 適用する案 | 記憶を更新するか |
| --- | --- | --- |
| 本番ビルド（`isDev=false`） | `current` | しない |
| `?ui=` が有効値 | その案 | する |
| `?ui=` が不正値 | `current` | する |
| `?ui=` が無く、記憶が有効値 | 記憶している案 | しない |
| `?ui=` が無く、記憶も無い／壊れている | `current` | しない |

判断が分かれる2点について、採った解釈と理由:

- **「未指定は `current`」の解釈**: Issue 本文には「不正値・未指定は `current`」とあるが、
  同じ本文に「localStorage に記憶する」「リロードで維持される」ともある。
  未指定を常に `current` にすると記憶が一切効かなくなり、後者と矛盾する。
  そこで「**パラメータでは何も選ばれていない**」の意味に取り、記憶 → `current` の順で
  フォールバックする形にした。テスト会中にURLからパラメータが落ちても、
  選んだ案のまま触り続けられる方が目的に合う
- **不正値のときに記憶も `current` へそろえる**: 打ち間違い（`?ui=a11` 等）のときに
  「画面は `current` なのに記憶は `a1`」という見えない食い違いが残ると、
  次にパラメータ無しで開いたとき勝手に案が変わって観察記録が濁る

### 開発時のみ有効にする二重の防御

1. `resolveUiVariant` が `isDev=false` のとき問答無用で `current` を返す
2. 隅の表示は既存のサンプル読込ボタンと同じ `import.meta.env.DEV && ...` で囲う

2 のおかげで本番バンドルからは表示コンポーネント自体が落ちる
（`npm run build` 後の `dist/assets/*.js` に文字列「UI案」が含まれないことを確認済み）。

### いまどの案かの表示

画面右下に固定の小さなバッジ（`.ui-variant-badge`）を出す。テスト会の写真・録画から
「詰まった場面がどの案のときだったか」を後から突き合わせるための観察記録用。

- **対照群 `current` でも出す**。出る案と出ない案があると、「表示があること自体」が
  案の違いになってしまい、比較の条件がそろわない
- `pointer-events: none` でクリックを素通りさせる（バッジの下にある譜面を触れなくしない）
- `@media print` で `display: none`（画面専用の開発用表示なので紙には出さない）

### 段2・段3への引き渡し

- `useUiVariant()` の戻り値を見て「自分の案のときだけ描く」形にする（A1 文脈バー向け）
- `.app-root` に `data-ui-variant="a1|a2|current"` を付けてあるので、
  CSS だけで済む表現（A2 の淡色化など）は `[data-ui-variant="a2"] ...` を目印にできる

`current` のときは属性が `current` になるだけで、見た目は 1px も変わらない。

## ブラウザ確認（2026-08-25 夜間）

worktree を共有 dev サーバー経由で開いて確認した。

- `?ui=a1` → バッジ「UI案: A1 文脈バー」、`.app-root[data-ui-variant="a1"]`、記憶 `a1`
- パラメータ無しでリロード → `a1` のまま維持
- `?ui=a2` → 「UI案: A2 譜面側」、記憶 `a2`
- `?ui=zzz`（不正値） → 「UI案: 現状」、記憶 `current`
- バッジ中心の `document.elementFromPoint` が譜面のSVGを返す（クリックを遮っていない）
- コンソールエラーなし

音符入力そのものの実操作確認は、この経路で読み込まれた既存譜面の1段目に空き拍が無く
（空き拍はビューポート外）、有効なクリック先を作れなかったため未実施。
同じ経路で本体checkout側のアプリでは音符入力が動くことは確認しており、経路自体の問題ではない。
