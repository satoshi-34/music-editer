# 設計書: 「行き止まりは喋る」原則と無言行き止まりの棚卸し（Issue #318）

## 問題

月光の清書中に #315（またぎ音符の当たり判定が左手クリックを飲む）を踏んだとき、
回避手順（またぎ解除 → 左手を先に入力 → 再度 ⇵）は**レビュアーが口頭で伝えて**初めて使えた。
アプリだけを触るユーザーは同じ場面で行き止まりになる。

個別のバグは直せばよいが、本当の問題は「**操作が無反応で、理由も次の一手も示されない**」という
体験そのものである。無言の拒否は、ユーザーからは次のどれとも区別が付かない。

- クリック位置が悪い（もう一度押せば効くかもしれない）
- そもそもこの機能では無理（別の手を探すべき）
- アプリが壊れた（作業を中断すべき）

## 原則

操作が効かない・機能が意図的に制限されている場面では、アプリが必ず

1. **理由**（なぜ効かないのか）
2. **代替手順**（どうすれば目的を達成できるのか＝抜け道）

を通知（`notifyScoreEdit`）またはツールチップで示す。**無言 return の新設を禁止**する。
開発ルールとしての本文は `AGENTS.md` / `CLAUDE.md` の「行き止まりは喋る」節にある。

### 拒否そのものは変えない

この原則は「できないことをできるようにする」ものではない。
拒否の判定は従来どおりに保ち、**黙って終わるのをやめる**だけである。
判定まで一緒に変えると回帰の範囲が読めなくなるうえ、
「なぜ拒否するのか」の設計判断（例: 休符は段またぎの対象外）を無効化してしまう。

### 実装上の約束

- 文言は `src/utils/scoreEditorNotices.ts` の**文言ビルダー**として置く。画面側に文字列を直書きしない
  （同じ意味の文言が2か所に散ると、片方だけ直したときに食い違う。#280 と同じ壊れ方）
- 判定は **`setScore` / `setPartsScore` の updater の外**で行う。
  updater の中で通知すると、React が updater を2回呼ぶ場面（StrictMode など）で通知も二重に出る
  （[`delete-feedback-and-selection-clear/design.md`](../delete-feedback-and-selection-clear/design.md) の記述と同じ理由）
- 通知の出口は #238 で作った `SCORE_EDIT_NOTICE_EVENT`（画面下端中央・`role="status"`・4秒）を使う。
  新しい通知の仕組みを増やさない

### 「元に戻せます」を付けるかの線引き

`UNDO_HINT`（Cmd/Ctrl+Z）は **譜面が実際に変わったとき**だけ付ける。
拒否の通知（何も起きなかった）に付けると「何かが起きて、それを戻せる」と誤読させる。

| 通知の種類 | UNDO_HINT | 例 |
| --- | --- | --- |
| 譜面が変わった | 付ける | 「音符を削除しました（Cmd/Ctrl+Z で元に戻せます）」 |
| 譜面が変わった（が、戻す対象が直感的でない） | 付けない | 「下の五線へ表示を移しました（所属は…）」※トグルなのでもう一度押せば戻る |
| 拒否・何も起きなかった | 付けない | 「この小節は拍がいっぱいで置けません（…）」 |

### #6 だけは「拒否」ではなく「成功」の通知である

運用者の追加提案2（Issue #318 コメント）に対応する。

声部2が空である前提が崩れて #322 の症状を踏んだ。恒久策は #316 の色分け（レイヤー可視化）で、
この通知はその前倒しの1行対策である。したがって文言は「移した」だけで終わらせず、
**「所属は変わらない」まで言い切る**こと。

## B-2 / B-3: Cmd/Ctrl+V（連符グループを小節の末尾へ足す経路）を喋らせる（Issue #331）

### 問題

`PianoSystemCanvas` の Cmd/Ctrl+V は、次の2つの場面で**無言で何も起きなかった**。

1. **B-2**: 何もコピーしていない状態で押したとき（`getTupletClipboardGroup()` が null → 素の `return`）
2. **B-3**: 貼り付け先の小節に空き拍が足りないとき

B-3 に通知を足せなかったのは、容量の判定が `setPartsScore` の updater（`prev => next`）の**中**にあったためである。
updater は React が同じ入力で2回呼ぶことがある（StrictMode 等）ので、その中で `notifyScoreEdit` を呼ぶと
同じ通知が2回出る。#326 はこの理由で見送り、リファクタ込みの別Issue（#331）へ切り出された。

### 修正設計

**判定を updater の外へ出す。** 譜面の読み取りは、同じハンドラの Cmd/Ctrl+C・Delete が既に使っている
`partsScoreRef.current`（毎レンダーで最新の `partsScore` へ同期される ref）から行う。
これで「読む → 判定して通知 → 書き換える」の順になり、updater は純粋な書き換えだけを行う。

**判定式は変えない。** 空き拍は従来どおり `eventOccupiedBeats` の合計で求め、
`usedBeats + tupletGroupBeats(group) > beatsLimit + 0.000001` という比較もそのまま残す。
「貼れる／貼れない」の線引きを変えないのが「行き止まりは喋る」原則の約束（§拒否そのものは変えない）である。

**文言は既存のビルダーを共用する。**

| 場面 | 文言ビルダー | 理由 |
| --- | --- | --- |
| 小節が満杯 | `describeMeasureFull()`（#318 の #1・#2 と同じ） | 拒否の理由も次の一手（次の小節へ置く／音符を減らす）も音符の追加とまったく同じ。同じ意味の文言を2つ作ると、片方だけ直したときに食い違う（#280 の壊れ方） |
| クリップボードが空 | `describeTupletGroupPasteUnavailable('emptyClipboard')`（#329 で追加済み） | 休符クリック側と同じ行き止まり。文言も入口も1つにそろえる |

### 小節を選んでいるときは黙る

`Cmd/Ctrl+V` は「小節の貼り付け」（`ScorePage` 側のハンドラ）とキーを共有している。
小節を選んでいるあいだの Cmd/Ctrl+V はそちらの操作なので、連符側が
「貼り付けられる連符グループがありません」と喋ると、**正しく効いている操作へ的外れな通知をかぶせる**ことになる。
そのため B-2 の通知は `selectedMeasuresRef.current` が null のときだけ出す
（同じ線引きは Cmd/Ctrl+C 側に先例がある。「両方が同じクリップボードを奪い合わない」ための役割分担）。

なお B-2 では `e.preventDefault()` を呼ばない（従来どおり）。ここで握りつぶすと
`ScorePage` 側の小節ペーストやブラウザ本来のペーストまで止めてしまうため。
B-3（満杯）では従来どおり `preventDefault()` する（Cmd+V は連符側が受け取ったうえで拒否した、という扱い）。
