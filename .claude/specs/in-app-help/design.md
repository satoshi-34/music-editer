# アプリ内ヘルプ（Issue #341）

2026-08-22。弟インタビュー回答1（#89）:「あらゆる操作の説明書が欲しい。調べるソースが脆弱だと厳しい」。

## 問題

操作の説明は README にしか無く、アプリを使いながら「やりたいこと」から手順を引けない。

## 修正設計（Issue の Codex レビュー済み方針 = 2層 + ソース一本化）

- **第1層: 目的別ガイド**（タスク起点）: `src/utils/helpContent.ts` の `TASK_GUIDES` が正本。
  「〜したい」形の見出し + 手順 + 検索用キーワード + リファレンスへの参照（seeAlso）
- **第2層: 操作リファレンス**（UI起点）: **README の操作章が唯一の正本**。
  `README.md?raw` を実行時に `parseReadmeSections` でパースして表示する（二重管理しない）。
  対象章はタイトルの内容語（画面/基本操作/応用操作/ショートカット/既知の制限）で選ぶため、
  章番号の振り直しに耐える。開発者向け章は載せない
- **検索**: 1つの検索ボックスで両層を横断。スペース区切りは AND、全角スペース・大文字小文字を正規化
- **UI**: ヘッダータブ行右端（フィードバックの左）に「❓ ヘルプ」を常設 → モーダル
  （HelpPanel）。ガイドは details で開閉、リファレンスは章見出しの下に項目を並べ、
  検索中は自動で開く。ガイドの「詳しく」で該当リファレンス項目へスクロール
- **markdown 描画**: 依存を増やさず簡易レンダラー（見出し/箇条書き/番号リスト/表/強調/コード。
  リンクは表示テキストへ落とす）

## データ構造

- `HelpSection { id, chapter, title, body }`（README パース結果・実行時のみ）
- `TaskGuide { id, title, keywords, steps, seeAlso? }`（コードが正本）
- 保存データへの影響なし

## 影響範囲

- 新規: utils/helpContent.ts・components/HelpPanel.tsx・App.css のヘルプ用スタイル
- ScorePage: ❓ ヘルプボタンと showHelp state のみ
- テスト: helpContent（パース・横断検索・**seeAlso が実物 README に実在すること**）7件、
  HelpPanel（2層表示・絞り込み・見つからない案内・閉じる・詳しくジャンプ）5件

## 経緯・既知の制限

- 「各ツールチップから該当項目へのリンク」（Issue 記載）は、ツールチップが title 属性
  （リンク不可）のため第1弾では見送り。ヘルプ検索で同じ語を引けることで代替
- ガイドの手順は README の記述と突き合わせて書いた。UI 文言を変えたら
  helpContent.test.ts の「seeAlso 実在」テストが README との乖離を検出する

## Codex round1 対応（2026-08-22）

- **モーダルのキー遮断**（P1）: パネル root の onKeyDown で全キーを stopPropagation
  （ConfirmDialog と同じ守り）。検索欄の Backspace/Delete が window のグローバルハンドラへ
  伝播して裏の選択物を消す事故を防ぐ。Escape はヘルプを閉じる。フォーカスは開いた時に
  検索欄へ（autoFocus）— ConfirmDialog と同等の範囲
- **ガイド手順の是正**（P2）: タイ/スラー・松葉は「クリック→クリック」ではなく
  **ドラッグで設置**、途中変更の解除は「解除」（または空欄確定）に修正。
  段またぎの seeAlso（無関係な節を指していた）は削除
- **「詳しく」ジャンプで対象を開いたままに**（P2）: pinnedSectionId state を追加し、
  検索を消しても対象 details だけ open を維持。テストは「正しい対象が open で
  スクロールされる」ことまで検証する形へ強化
- **リスト継続行の保持**（P3）: レンダラーを components/helpMarkdown.tsx へ分離し、
  インデント付き継続行を直前の <li> の続きとして保つ。README「調号」の実形でテスト

## Codex round2 対応（2026-08-22）

- **全画面オーバーレイ**（P2）: dropdown-overlay はヘッダーの下から始まる設計のため、
  ヘルプの裏でタブ切替・Undo/Redo が押せてしまった。専用の .help-overlay（inset:0・
  ツールバーごと覆う・薄い暗幕）へ変更
- **タブ配置の事実誤り**（P2）: タイ・臨時記号（♯/♭/♮）は実装では「音符・休符」タブ
  （Palette section='notes' の音符行）にある。ガイド2件と **README のタブ表**（同じ誤りが
  あった）を是正。README はリファレンスの正本なので、README 側の誤りはヘルプの誤案内に直結する
- **「音が鳴らない」に音声復旧ボタン**（P2）: 再生・音色タブの「音声復旧」
  （AudioContext 異常向け・READMEのトラブル対処にも記載）を手順の2番目へ追加
- 装飾音符ガイドのボタン名を実UI（「前打音」「トリル」等）へ（P3）

## Codex round3 対応（2026-08-22）

- .help-overlay/.help-panel の z-index を 1200/1201 へ（既存ポップアップ群 = 1001 より上。
  リセットメニュー等を開いたままヘルプを開いても裏で操作できない）
- README タブ表の是正の取りこぼし: 微分音・リピート記号/1番2番括弧も実装は「音符・休符」タブ
  （Palette section='notes'）。README を実装に合わせて再修正

## Codex round4 対応（2026-08-22）

- **document.body へ portal**: ヘルプはツールバー（z-index:20 の stacking context）配下で
  描かれるため、z-index を上げても body 直下のポップアップ（パート編集=950）を越えられない。
  createPortal(document.body) で stacking context を離脱
- **フォーカストラップ**: Tab/Shift+Tab をモーダル内で循環（閉じた details の中身は
  巡回から除外）。抜けると以後のキー入力が stopPropagation を通らず譜面へ届くため

## 追記（Issue #114・2026-08-22）: ? キーでヘルプを開く

#114（ツールバーを制作中心に整理）の提案のうち、明確に実装可能な
「? キーで開くショートカット一覧」をヘルプへの導線として実装した
（ショートカット一覧は README 由来リファレンスの「キーボードショートカット」章として
すでにヘルプ内にある）。音価ショートカット群とは別 effect（印刷プレビュー中も
閲覧は妨げない）。テキスト入力中・修飾キー付きは除外。
#114 の残項目（右サイドパネル・常設エリア再編・モバイルのピンチズーム等）は
UX の大規模再設計で運用者裁定が必要なため、Issue 側に棚卸しコメントで記録した。
