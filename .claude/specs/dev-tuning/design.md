# 開発環境限定の定数チューニング — Issue #596

運用者の「市販譜と見比べて初期値を決める」（#589 の圧縮率・#586 の間隔・#550 の余韻）を、
コード書き換えなしのライブ調整にするための上書きレイヤー。**セッション内実装**（運用者「今やって」・2026-09-03）。

## 設計

- **正本はコード側の定数**。`devTuning.ts` は dev 専用の上書きレイヤーで、確定した値は
  「現在値をコピー（コード形式）」→ コードへ貼って本修正にする運用
- `devTuned(key, default)`: 本番（`import.meta.env.DEV` false）では default を直返し。
  さらに**呼び出し位置にも DEV ガード**を置き、本番バンドルから devTuning モジュールごと
  tree-shake させる（round1 P2。build 後の dist に `layout.` キーが無いことを grep で確認）
- 読みは**モジュール内キャッシュ**（round1 P2: レイアウト計算内で多数回呼ばれるため
  localStorage 同期読みを毎回しない）。書きは `setDevTuningOverride` がキャッシュも更新、
  別タブは `storage` イベントで無効化
- **クランプは保存時と読込時の双方**（round1 P2: 読み出し時だけだと表示・コピー値と実効値が食い違う。round2 P2: 旧形式や手書きの localStorage に残った範囲外値は読込時に範囲へ寄せる）。
  未登録キーは保存・読込とも拒否。「全部リセット」は storage キーごと削除
- レジストリ（`DEV_TUNING_ENTRIES`）へ1件足すだけで項目追加。**登録は「利用者が画面から
  調整できない定数」に限る**（運用者フィードバック 2026-09-03: 段/パート間隔・均等さは
  レイアウトタブのスライダーがブラウザ設定として保存され、一度触った環境では既定値が
  参照されない=効かない項目になる二重実装だったため撤去）。初期対象は
  圧縮率・小節左右余白の2定数。音系は #610（再生の先読みリード `audio.scheduleLead`）で追加。
  余韻（#550）は着手時に追加
- パネル（`DevTuningPanel`）は App が DEV のときだけ lazy mount
  （動的 import + DEV ガード同一箇所・Turbopack の教訓と同方針）

## 配線の注意（round1 P1 → 最終形の学び）

「既定値」の上書きは、効かせる場所が**省略時引数ではなく実際の初期化点**である上に、
その初期化点が localStorage のユーザー設定より弱い（触った環境では参照されない）。
既定値チューニングはこの罠が構造的に付きまとうため、**ユーザー調整可能な値はレジストリに
載せない**方針へ切り替えた（既存スライダーで調整→決めた値をコードの既定へ反映する）。
