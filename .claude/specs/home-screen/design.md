# 設計書: ホーム画面（譜種選択・保存ファイル・設定の玄関）

> 対応 Issue: [#500](https://github.com/satoshi-34/music-editer/issues/500)
> 関連: [#497 保存先の明示](https://github.com/satoshi-34/music-editer/issues/497) /
> [#181・#109 複数作品の保存管理](../multi-score-storage/design.md) /
> [#318 行き止まりは喋る](../dead-end-speaks/design.md)

## 問題

起動すると即・譜面画面という1画面構成だったため、

- 「どの譜種で新しく作るか」を決める入口が、譜面を開いたあとの「楽譜設定」タブの中にしかない
- 保存されている作品は「ファイル」タブの奥の「作品一覧 ▾」を開かないと見えない
- 設定類がタブに散っていて、初めて触る人が全体像をつかめない

「UIの体系化」（弟インタビュー回答②）と「すぐ開けると不安」（#497 の背景）の両方に効く玄関として、
ホーム画面を追加する。ログイン画面は作らない（お試しの障壁を上げない。#498 の方針）。

## 修正設計

### 画面の重ね方（なぜ ScorePage を隠さずに重ねるか）

`App.tsx` が **譜面画面（ScorePage）を常にマウントしたまま**、その上へ全画面の
ホーム（`HomeScreen`）を重ねる。ホームを閉じる＝重ねをやめる、という切り替えだけを行う。

- **「前回の続き」を1クリックにするため**: 起動時の復元（`useWorkLibrary.initializeWorks` →
  自動保存の読み込み）はホームの裏で従来どおり走っている。ホームを閉じるだけで編集を再開でき、
  「起動→即編集」の速さを1クリック以上悪化させない（Issue の最重要の回帰要件）
- **`display: none` で隠さない理由**: 譜面画面は表示幅の実測値から初期の表示倍率を決める
  （`ScorePageInitialZoomFit`）。隠すと幅が 0 になり倍率が狂う
- ホームのレイヤーは `z-index: 3000`（既存のモーダル類 2000〜2100 より上）。
  `@media print` では非表示にして、ホームが出たまま印刷指示が飛んでも紙に出ないようにしている

### 機能の実体は譜面画面のものを呼ぶ（二重実装をしない）

ホームは表示専用のコンポーネントで、処理は持たない。譜面画面が
`ScorePageHomeActions`（`homeActionsRef` 経由）として操作口を公開し、ホームのボタンはそれを呼ぶ。

| ホームの操作 | 実際に動く既存処理 |
| --- | --- |
| 前回の続きを開く | 何もしない（起動時の復元済み。ホームを閉じるだけ） |
| 譜種を選んで新規作成 | `performNewScore()`（ツールバーの新規作成と同じ）→ `handleScoreTypeChange(譜種)` |
| 保存した作品を開く | `handleSelectWork(workId)`（作品一覧パネルと同じ） |
| ファイルを開く（.score.json / MusicXML(.mxl) / PDF(β) / 以前の手動保存） | ファイルタブの各導線と同じ ref・同じハンドラ |
| 設定 | `handleToolbarTabChange('score' / 'layout' / 'playback')` |

譜種の並び・表示名・説明は `SCORE_TYPE_BUTTONS`（`src/utils/editorContextLabels.ts`）を正本にし、
「楽譜設定」タブの種類ボタンとホームの譜種選択が同じ定数から描かれるようにした
（同じラベルを2か所に書くと、片方だけ直したときに食い違う。#223→#280 と同種の事故を避ける）。

### 隠しファイル入力を常設へ移した理由

`.score.json` / MusicXML / PDF の隠し `<input type="file">` は「ファイル」タブの中に置かれており、
タブを開いていないと**要素そのものが存在しなかった**。ホームから開く導線を呼ぶには、
タブを切り替えて再レンダーを待ってから `click()` する必要があり、
Safari は「ユーザー操作と同じ処理の流れ」で呼ばれない `input.click()` を無視する（#464 の実機知見）。
そのため入力要素を `app-root` 直下の常設へ移し、タブ切替の反映を待たずにその場で `click()` できるようにした。
ファイルタブの見た目・操作は変わらない（ボタンとハンドラはそのまま）。

### ホームへ戻る導線と、未保存の扱い（#318）

ツールバー右上（ヘルプ・フィードバックと同じ「どのタブからでも押せるアプリ操作」の並び）に
🏠ホームボタンを置く。押すと戻る前に、

1. 自動保存の待機（1.5秒デバウンス）を止める（`cancelPendingAutosave`）
2. いまの内容を作品へ保存する（`saveCurrentWork`）
3. 作品一覧を読み直してからホームを表示する

という順で処理する。待機中のまま戻ると直前の編集が保存されないまま一覧に並び、
「保存されていない」ように見えてしまうため。ホーム側でも
「編集内容はこの端末のブラウザへ自動保存されています」と明示し、黙って済ませない（#318 の趣旨）。
ホームボタンは `onGoHome` が渡されたときだけ出るので、譜面画面単体をマウントする既存テストには現れない。

### バージョン表示（受入条件7）

ホームのフッターに `v3.6.0` の形で出す。値は `package.json` の `version` を
`vite.config.ts` の `define`（`__APP_VERSION__`）でビルド時に埋め込み、`src/utils/appVersion.ts` から読む
（画面側に版番号を手書きすると更新を忘れ、リリースノートと突き合わせられなくなる）。
着手時点の `package.json` は `0.0.0` のままだったため、保存データのバージョン
（`storage.ts` の `CURRENT_VERSION = '3.6.0'`）とリリースノートに合わせて `3.6.0` へそろえた。

### 将来枠（ログイン）

ヘッダー右に空の枠（`.home-header-slot`）だけ置いてある。ボタン・分岐は実装しない
（過剰設計にしない、という Issue の指示どおり）。後から足しても並びが崩れないようにするための場所取り。

## 影響範囲

- 追加: `src/components/HomeScreen.tsx`・`src/utils/appVersion.ts`・本設計書・
  `src/components/HomeScreen.test.tsx`・`src/App.test.tsx`
- 変更: `src/App.tsx`（ホームと譜面画面の切り替え）、
  `src/components/ScorePage.tsx`（`homeActionsRef` / `onGoHome` の受け口、ホームボタン、
  隠しファイル入力の常設化、譜種ボタンの定数化）、
  `src/utils/editorContextLabels.ts`（`SCORE_TYPE_BUTTONS` 追加）、
  `src/App.css`（ホームの見た目）、`vite.config.ts`・`src/vite-env.d.ts`・`package.json`（版番号の埋め込み）
- **譜面データの形式・保存キーは変更していない**。作品の保存・復元は
  [`multi-score-storage`](../multi-score-storage/design.md) の仕組みをそのまま使う
- サーバー通信は増えていない（ホームはすべてローカルデータで成立する）
- 譜面画面だけをマウントする既存テスト（`render(<ScorePage />)`）は、props を渡さなければ
  従来と同じ挙動になるため影響を受けない
