# 記号と音符の自動衝突回避（Issue #340）

## 問題

強弱記号（pp など）・cresc./dim. の縦位置は「五線最下線から 26px 下」の固定値で、
低い音符の加線・下向きの符幹はそこまで届くため重なっていた。運用者が月光
（ベートーヴェン月光ソナタの写譜）で pp を手動で -93px 動かした実例があり、
弟インタビュー回答1（#89 → #340）の筆頭要望。

## 段階分け（Issue #340 の設計メモ 2026-08-22）

- **段1（本実装）**: 強弱記号・cresc/dim（dynamics 系）の下方向回避
- 段2: カスタム記号・運指など統一高さ帯の記号（未実装）
- 段3: スラー/タイの弧・松葉 — 「避ける」ではなく「形を変える」実装になるため
  別 Issue 化を提案

## 修正設計（段1・2026-08-22）

### 純粋関数エンジン `src/utils/symbolCollisionUtils.ts`（新規）

- `resolveBelowSymbolShifts(symbols, obstacles, options)` — 記号を x 順に処理し、
  障害物か確定済み記号の占有域に重なる間 7px ずつ下へ押し出した「追加 dy」を返す
- **手動調整（⤢/✥ の offsetX/offsetY 非0）の記号は動かさない**（Issue の原則）。
  ただし占有域には加えるので、自動配置の記号の方が手動配置を避ける
- 押し出し上限 112px（実例の 93px を上回る値）。上限まで押しても空かなければ
  元の位置に留める（半端に下がった「避けたのに重なっている」見た目を避ける）
- `estimateTextRect()` — DOM 計測なしの文字箱概算。縦は em 全体ではなく
  **字面の実コア**（ベースライン上 0.55em・下 0.2em）で見積もる。em 全体だと
  通常音域の下向き符幹の先端が 1〜2px かすめるだけで押し出しが発生し、
  譜面全体で強弱記号の高さが不揃いになるため（意味のある重なりだけを避ける）

### PianoSystemCanvas 側の配線

- 音符描画ループ（アクティブ声部＋非アクティブ声部の見た目だけ描画）で
  VexFlow の `note.getBoundingBox()`（符頭＋符幹を含む。モデル側の値なので
  DOM 計測不要＝jsdom でテスト可能）を `collectors.noteObstacles` に段
  （partIndex）付きで収集
- `dynamicTextEntries` に `obstaclePartIndex` を追加し、一括描画の直前に
  段ごとにエンジンを1回呼んで、y へ追加シフトを加算
- **自動回避の結果は保存しない**（描画のたびに計算。保存データは不変なので、
  後からロジックを改良しても既存の譜面が壊れない）

## 影響範囲

- 強弱記号・cresc/dim の描画位置のみ（クリック判定 rect は記号の描画実測
  （getBBox）から作られるため自動で追従する）
- 手動調整済みの記号・重なりのない記号は従来位置のまま
- 保存データ・再生・書き出しは不変

## データ構造

- 保存形式の変更なし。`RenderCollectors` に描画時だけの `noteObstacles`
  （`{partIndex, x, y, w, h}` の配列）を追加

## 経緯・判断

- 障害物は同じ段（パート）の音符に限定。下の段の音符まで見ると「押し出した先で
  下の段に食い込む」を解けず複雑化する。押し出し上限（112px）を安全弁とする
- ベースライン揃え（同じ段の強弱記号を同じ高さに揃える浄書慣習）は段1では
  行わない。重なった記号だけが個別に下がる
