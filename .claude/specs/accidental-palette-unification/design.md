## 1. 何を解こうとしているか

音符・休符タブに、**同じ記号が意味違いで2家族**並んでいる。見た目の差は先頭に ♩ が付くかどうかだけで、
初見では区別できない。テスト会で発案者ユーザー（Finale 熟練者）が実際に戸惑った箇所であり、
「整理したい」ではなく**第一印象を損なった実測データのある箇所**として扱う（#547 コメント）。

運用者発案の**案D**（#547）で統合する: 臨時記号ボタンを1組にし、**クリック先で意味を決める**。

- 既存の音符（符頭）をクリック → その音へ**付与**
- 音の無いところをクリック → その高さに**臨時記号付きの音符を置く**（現・入力家族 #470 の挙動）

### 2-2. クリックの現行文法（`PianoSystemCanvas.tsx` / `editor/hitResolution.ts`）

| 持っているツール | クリック先 | 起きること | 実装 |
| --- | --- | --- | --- |
| 付与（`mode:'accidental'`） | 音符セル内のどこでも | その音符へ付与。クリックYが既存の符頭のラインと一致すればその1音、外れれば**和音全体** | `PianoSystemCanvas.tsx:7198-7259` |
| 付与 | 先頭段の調号領域 | **調号を1段シフト**（♯/♭/♮）。𝄪/𝄫 は調号に無いので案内を出す（#423） | 同 `:7202-7229` / 背景側 `:6646-6672` |
| 付与 | 休符・小節背景（調号領域の外） | **何も起きない**（クリックを消費して終わる） | 同 `:7229-7232` / `:6671` |
| 入力（`accidental` 属性） | 音の無い高さ・空き拍 | その高さに臨時記号付きの音符を挿入 | `applyInputAccidentalToKey` + `doInsert` |
| 入力 | 既存音符の符頭X範囲内の別の高さ | 和音として足す（記号付き） | 同上 |
| 入力 | 休符本体 | 記号付きの音符へ置換（#233 の1クリック置換） | 同上 |

**「音符クリック＝置換」は音符には無い**（#547 コメントの表現は不正確）。音価の置換で動くのは
休符の1クリック置換（#233）だけで、音符セルのクリックは選択・和音追加・挿入のいずれかになる。
このため案Dで「符頭クリック＝付与」に倒しても、**失われる既存操作は無い**。

### 2-3. 「3系統ある」という指摘の確認結果（#548 コメント・運用者指摘）

コードを確認した結果、**臨時記号のボタンは2系統**で、演奏記号タブには無い。

- `mode:'accidental'` / `mode:'microtone'` のボタンは `Palette.tsx` の `section === 'notes'`
  ブロック（262〜530行）の中にしか無い。`section === 'symbols'`（531行以降）に `accidental` の
  文字列は1つも出てこない（`grep "mode: 'accidental'" src` の結果は Palette.tsx の型定義と
  notes 側の生成箇所だけ）
- 演奏記号タブにある「♯♭」の見た目のボタンは **途中調号変更（`mode:'measureKeySig'`）**
  （`Palette.tsx:569` 付近。アイコンが ♯ と ♭ を並べた SVG のため、臨時記号に見える）

ただし**重複自体は実在する**。形が違う:

> **調号を変える経路が2つある**: ①演奏記号タブの「途中調号変更」ボタン、
> ②**臨時記号ツールで先頭段の調号領域をクリック**（2-2 の2行目）。
> ②は臨時記号ツールに調号編集が相乗りしている状態で、案Dで「空きクリック＝音符を置く」に
> するときに**最初にぶつかる**（3-3 で扱う）。

したがって #548 の「3系統」は、**2系統（付与・入力）＋臨時記号ツールへの調号編集の相乗り**と
読み替えて設計する。タブ間の重複は無いので「どちらのタブに残すか」の裁定（#317 との整合）は
**不要**になった。

## 3. 統合設計

### 3-1. ボタンは1組（7個）。ツールは音符入力ツールへ一本化する

`mode:'accidental'` / `mode:'microtone'` を**廃止**し、入力ツール側の属性へ寄せる。

```ts
// 統合後（Palette.tsx の Tool）
| { duration: DurKey; isRest?: boolean; dots?: 1; tuplet?: TupletKind;
    accidental?: AccidentalToolKind;   // 既存（#470）
    microtone?: MicrotoneType }        // 新設。accidental とは排他
```

- 付点・連符と同じ「入力の属性」になり、**音価と独立したトグル**として並ぶ（詰める点1の答え）
- `accidental` と `microtone` は**排他**（`applyAccidentalToEvent` / `applyMicrotoneToEvent` が
  既に排他で書かれているため、UI 側も同じ規則に揃える）
- 表記は ♩ を外して **♯ ♭ ♮ 𝄪 ♭♭ ¼♯ ¼♭ の7個**（`accidentalSymbol` / `microtoneSymbol` をそのまま使う）

**属性側へ寄せる理由**: 逆向き（`mode:'accidental'` に一本化）だと、音価・付点・連符と同時に
選べなくなり #470 の速度メリットが消える。属性側なら「♯を持ったまま8分に変える」が自然に通る。

### 3-2. クリック先の裁定表（優先順位つき）

上から順に判定する。**この順序が本設計の中心**。

| # | クリック先 | 起きること | 備考 |
| --- | --- | --- | --- |
| 1 | 先頭段の調号領域（`firstStaveKeySignatureHitBounds` の内側） | **調号を1段シフト**（現行維持。𝄪/𝄫 の案内も維持） | 3-3 |
| 2 | 既存の**符頭に当たる**クリック（`resolveSelectableKeyIndexAt(lx,ly) >= 0`） | その1音へ**付与**（音価は変えない・音符は増えない） | 3-4 |
| 3 | 符頭に当たらない・音符セル内 / 小節背景 | その高さへ**記号付きの音符を挿入**（和音追加を含む・現行 #470 の経路） | |
| 4 | 休符本体 | **記号付きの音符へ置換**（#233 の1クリック置換に記号が乗る・現行 #470 の経路） | 3-5 |

### 3-3. 調号領域の相乗りは現行のまま残す（統合の最初の落とし穴）

現在「臨時記号ツール＋背景クリック」は**何も起きない**のが既定なので、調号領域だけを特別扱い
できていた。案Dでは背景クリックが「音符を置く」に変わるため、**先に調号領域を判定しないと
調号変更が音符入力に食われる**（先頭段の調号の上に音符が生える）。

- 実装では `PianoSystemCanvas.tsx:6645` の背景クリック分岐と `:7202` の休符分岐にある
  調号領域の判定を、**統合ツールの分岐の先頭へ移す**（判定式・通知は現行のまま流用）
- 調号領域は先頭段（`i===0`）だけなので、2段目以降は素直に挿入になる

> 将来: 調号編集を「途中調号変更」ボタン（`measureKeySig`）へ一本化して相乗りをやめる案は
> 別Issue（#547 の棚卸し側）で扱う。本Issueでは**挙動を変えない**。

### 3-4. 付与かどうかの判定は既存の共用関数を使う（新しい当たり判定を作らない）

符頭に当たるかどうかは、`editor/hitResolution.ts` の **`resolveSelectableKeyIndexAt`** が既に
正本になっている（`hitResolution.ts:404-425`）。click・mousemove（ホバーのカーソル形状）・
再クリック巡回（#264）・非アクティブ声部（#258）が同じ関数を呼ぶ設計で、
「ホバーでは選択に見えるのに押すと和音追加になる」食い違いを構造的に防いでいる。

**統合ツールの分岐もこの関数の戻り値1本で決める**（AGENTS.md「同じロジックの2枚目を作らない」）。

- 戻り値 `>= 0` → その `keyIndex` へ付与（表2の#2）
- `-1` → 挿入・和音追加・休符置換（表2の#3/#4）
- 副産物として、**押す前にカーソル形状で結果が分かる**（記号が付くのか音符が生えるのかを
  ホバーで区別できる。#318「無言の行き止まりを作らない」と同じ方向）

判定の寛容さも既存のまま引き継げる: 符頭のX範囲 ±`keySelectXPad`、五線の外は ±1ライン、
五線の中でも符頭X範囲内なら個別選択を優先（#271 案A）。単音の音符では実質「符頭の高さの
あたりをクリックすれば付く」ので、`accidental-implementation` が重視した
「初心者でも押しやすい当たり判定」は概ね維持される。

### 3-6. トグル規則・休符・ショートカット・文言

- **トグルOFF**: 同じ記号を再クリックでOFF、別の記号を押すと切替（現行踏襲・詰める点2）
- **休符ツール中に臨時記号をON**: 同じ音価の**音符**へ切り替える（現行 `Palette.tsx:449-458`）
- **`R` キー**: 休符へ切り替えるとき `accidental` を落とす現行処理（#470 round1 P2・#318）を
  維持し、**`microtone` も同じように落とす**（`ScorePage.tsx:3375-3386`）。
  「♯がONなのにクリックしても効かない」状態を作らないための規則なので、統合後も同じ
- **`aria-label` 案**: `臨時記号: シャープ（音符をクリックで付与・空きをクリックで♯付きの音符を入力）`
  - 先頭を `臨時記号: <名前>` に揃えると、テストの前方一致（`buttonByLabelPrefix`）が使いやすい
  - 微分音も `臨時記号: 四分音上げ（…）` に揃える
- **コンテキストバー**（`uiContextBar.ts:87-99`）: `mode:'accidental'` / `'microtone'` の分岐が
  消え、既存の「♯付き4分音符」の表示に自然に吸収される（分岐が1つ減る）

## 4. ボタン数と受入条件3

| 数え方 | 現状 | 統合後 | 削減 |
| --- | --- | --- | --- |
| 臨時記号（♯♭♮𝄪♭♭）だけ | 10（付与5＋入力5） | **5** | ちょうど半分 |
| 微分音（¼♯¼♭）を含む列全体 | 12 | **7** | 42%減 |

受入条件3「ボタン数がこの列で半分以下」は、**臨時記号だけを数えれば達成（10→5）**、
微分音を含めると 12→7 で半分（6）にわずかに届かない。

> **裁定事項1**: 12→7 を達成とみなすか、微分音2個を「その他 ▾」へ畳んで 12→6 にするか。
> **推奨は 12→7 のまま**（畳まない）。#89 で発案者ユーザーが微分音を多用する可能性があり、
> 「畳む場合も1クリックで出せること」が条件になっているため、畳むと条件を満たすのが難しい。

## 7. 実装段の進め方（承認後）

1. **段1a**: パレットだけ統合（`Tool` 型・ボタン・ラベル・`R` キー・コンテキストバー）。
   キャンバス側は `accidental` 属性の既存経路をそのまま使う → ケース3〜6・14 が緑になる
2. **段1b**: キャンバスの分岐（表2の順序・調号領域の移設） → ケース1・2・7・8・11〜13 が緑になる
3. ブラウザで golden path を確認（♯を選ぶ→符頭クリックで付与→空きクリックで♯付きの音符→
   Undo 1回で戻る→先頭段の調号領域クリックで調号が変わる）。スクリーンショットを PR に添付
