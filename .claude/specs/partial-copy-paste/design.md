# 小節未満の部分コピペ 設計メモ（段1: 連符グループ単位のコピー＆ペースト）

対象 Issue: #234（段1）。実装仕様の正本はトリアージコメント（レビュアー, 2026-08-11）。

## 問題

コピー＆ペーストの単位が「小節」しかなかった。運用者の実作業（月光の入力）で
出てくるのは「同じ三連符を何度も置き直す」という**小節未満**の反復で、
既存機能では次のどれも当てはまらなかった。

- 小節コピペ … 単位が大きすぎる（他の拍まで巻き込む）
- 連符ツールで休符をクリック（#224） … 毎回「音価ツール＋連符トグル＋音高」を
  クリックし直すことになり、同じ音型の反復には向かない

段2（任意のイベント範囲選択）は別Issueとし、本段では**グループ境界がデータ上はっきりしている
連符グループ**（同じ `tuplet.id` が連続する区間）だけを対象にした。

## 採用した設計

### クリップボード（`src/utils/tupletClipboard.ts` 新設）

連符グループのコピー内容は**モジュール変数**に置き、`set/get/subscribe` の3関数で扱う。

- コピー元も貼り付け先も `PianoSystemCanvas` だが、1ページの中に段の数だけ
  インスタンスが並ぶ（段2でコピーして段5へ貼るのが普通の操作）。ScorePage の state に
  持たせると Piano/Single/Quartet/Ensemble の4ラッパーへ props を配り直すことになる
- 保持するのは `NoteEvent[]` だけで、描画状態は持たない
- `subscribe` は「後勝ち」の連絡用（下記）

### 「最後にコピーしたもの」の後勝ち

トリアージの指示どおり、クリップボードは**小節 or グループのどちらか一方だけ**を持つ。

| 操作 | 起きること |
| --- | --- |
| 小節を選んで Cmd+C（ScorePage） | 小節クリップボードを更新し、`setTupletClipboardGroup(null)` |
| 連符の音符を選んで Cmd+C（キャンバス） | グループを入れる → 購読中の ScorePage が小節クリップボードを `null` に |
| 新規譜面（`resetScoreStateToEmpty`） | 両方とも空にする |

キャンバス側の Cmd+C は「小節が選択されているあいだは何もしない」。
両方のハンドラが `window` の keydown に付いているため、
**どちらが先に走るかに依存しない線引き**（＝選択状態で決める）にしてある。

### コピー（`copyTupletGroupForClipboard`）

`findTupletGroupRange` で同じ `tuplet.id` が連続する区間を求め、その範囲を複製する。

- **弧（`arcs`）・松葉（`hairpins`）・レガシーの `tiedToNext` は落とす**。
  これらは「同じ声部の別イベントをインデックスで指す」情報なので、
  そのままコピーすると貼り付け先で無関係の音符を指す（#245 と同じ壊れ方）
- 音符自身に付く記号（アーティキュレーション・運指・歌詞など）は残す
- 複製は JSON 経由のディープコピー。コピー後に元の音符を編集しても中身は変わらない

### ペースト

貼り付け実体は `instantiateTupletGroup` が作り、**グループ id は毎回新規発番**する
（元グループと id を共有すると、離れた場所の連符同士が1グループとみなされて
削除・描画が壊れる。#217 系のグループ整合を守るため）。

貼り付け先の声部は**いま編集中の声部**（`activeVoiceIndex`）。コピー元の声部は問わない。

#### 経路1: 休符を1クリック（主経路）

`planTupletGroupPasteIntoRest(restEvent, group)` が計画を立てる。

- 対象は「連符ではない普通の休符」だけ。連符内の休符へ貼ると連符が入れ子になって壊れるため
  （#224 の `buildTupletRestReplacement` と同じ保守的な考え方）
- 休符の拍数 ≧ グループの拍数なら置換。**余りは #224 と同じ規則**で
  `buildRestEventsForBeats` により通常の休符として後ろに残す
- 足りなければ `null` → 何もしない

#### 経路2: Cmd+V（小節の空きへ末尾追加）

選択中の音符がある小節の、アクティブ声部の末尾へ追加する。
容量チェックは音符追加（`doInsert`）と同じ「使用拍＋追加拍 ≦ 拍子の拍数」。
足りなければ何もしない。

### フィードバック（容量不足を無言にしない）

このキャンバスの既存の作法は**カーソル形状**（#224 → #233 で導入）なので、それに合わせた。

- グループをコピー中に休符へホバー … 貼れるなら `copy`、貼れないなら `not-allowed`
- 判定はクリック時とまったく同じ `planTupletGroupPasteIntoRest` を通す
  （別の式で近似するとホバー表示だけ嘘になる）
- Cmd+V（キーボード）側にはカーソルが無いため、容量不足時は無反応になる。**既知の弱点**

### Escape でコピー状態を解除（トリアージの明文にはない追加）

グループをコピーしているあいだ、休符クリックの意味は「音符の置換」から「貼り付け」に変わる。
この状態から**通常の音符入力へ戻る手段が仕様に無かった**ため、Escape で
クリップボードを空にする出口を足した（音符選択の有無にかかわらず効く）。
小節を Cmd+C し直しても後勝ちで解除される。

## 既知の制限・未決定

1. **コピー中は休符クリックが貼り付けに変わる**（トリアージの「音価ツール不問」に従った結果）。
   通常の音符入力へ戻るには Escape か、小節の Cmd+C、または新規譜面。
   運用上つらければ「連符ツール選択中だけ貼り付けにする」等へ寄せる余地がある
2. Cmd+V の容量不足は無反応（カーソルのような事前表示が無いため）
3. 貼り付け先の音高はコピー元のまま。移調して貼る指定は段2以降の検討事項
4. 声部をまたぐコピー（声部2でコピー→声部1へ貼る）は許している。
   グループは声部ローカルなイベント列なので破綻しないが、浄書上の妥当性は運用者判断

## 追記（Issue #325）: コピー中の当たり判定を休符の「列」全体へ広げる

### 問題

上記の経路1（休符を1クリック）が成立するのは `isOnRest`、すなわち
**休符の記号の描画中心 ±18（`REST_BODY_HIT_HALF_WIDTH`）の帯**だけだった。
4分休符の時間枠（列）は幅240前後あるため、列の中央付近を押しても
`|439-479|=40 > 18` で外れ、フォールバックの `doInsert`（隣接挿入）へ流れていた。
満杯の小節では `doInsert` が容量チェックで無言 return するため、
ユーザーには「コピーしたのにクリックしても何も起きない」体験になっていた（運用者報告・実測）。

ホバーカーソル（copy / not-allowed）も同じ ±18 でしか出ないため、
「そこは押せない」という誘導も効いていなかった。

### 修正設計

**コピー中（クリップボードにグループがあり、かつ音価ツールを選んでいるあいだ）だけ**、
貼り付けの当たり判定を休符の時間枠（列）全体にする。

- 判定順を入れ替え、`if(!isOnRest){doInsert}` より**前**に貼り付け分岐を置く。
  条件は `clipboardGroup && getDurationTool(tool) && isInRestRowY`（X方向の帯は見ない）
- Y方向は従来どおり五線±3加線（`chordTopY`〜`chordBotY`）に限る。
  ここを外すと、五線から離れた符頭のために足した拡張ヒット領域（#246）まで
  貼り付け扱いになり、隣のパートのクリックを奪ってしまう
- ホバーカーソルも同じ範囲へ広げる（判定はクリックと同じ `planTupletGroupPasteIntoRest`）
- **コピー中でないときの線引き（±18 の中＝置換／外＝隣接挿入）は1ピクセルも変えない**

根拠は既存実装自身の設計判断で、「貼り付けるつもりのクリックで別の音符が増えるほうが
分かりにくい」として記号帯の中では挿入へ流さないようにしてあった。
列の残り9割がその例外になっていた状態を、元の意図へそろえたことになる。

### 貼れないときは黙らない（#318 の「行き止まりは喋る」）

当たり判定を広げると、無言で終わる場面は「そもそも貼れない休符を押したとき」だけになる。
その1本の行き止まりに通知を足した（PR #326 が本Issueの結論待ちとして見送っていた箇所）。

可否の判断元は `findTupletGroupPasteBlockReason`（`tupletUtils.ts`）1か所に寄せ、
`planTupletGroupPasteIntoRest` はその結果だけで null を返す。
通知の文言（`describeTupletGroupPasteUnavailable`）も同じ理由を受け取るので、
**「文言と実際の結果が食い違う」事故（#280 の形）が構造的に起きない**。

| 理由 | 文言の要点 |
| --- | --- |
| `tooShort` | 拍が足りない／もっと長い休符か Escape |
| `insideTuplet` | 連符の中の休符には貼れない |
| `emptyClipboard` | コピーしてから貼る（キーボード経路の保険） |
| `notRest` | 音符の上には貼れない |

## 段2: 拍範囲の縦スライス選択とコピペ（Issue #333・2026-08-22 設計確定）

発案は運用者（2026-08-20「小節選択ボタンで選択できるグループ、範囲選択みたいにピーってできないかな？」）。
Issue #333 の方向づけをここで実装可能な仕様に落とす。実装承認は 2026-08-22 の
「一旦全部実装終わらせてくれる」の包括指示による。

### 選択モデル

- 小節選択ツールのドラッグを小節未満へ拡張する。選ぶのは**拍範囲 × 全パート・全声部**の
  縦スライス。選択状態は既存の `selectedMeasures` を後方互換のまま拡張する:
  `{ start, end, startBeat?, endBeat? }`（beat 無し = 従来の小節丸ごと選択。
  キーボードでの範囲移動・移調など既存操作は beat 無し選択のときだけ従来どおり働く）
- `startBeat` は start 小節内の開始拍、`endBeat` は end 小節内の終了拍。
  小節をまたぐドラッグは「端の小節は部分・中の小節は全体」（Finale と同じ）

### 境界スナップ（この設計の肝）

- スライス境界は**全パート・全声部で音符を割らない位置**にだけ置ける。
  候補 = 各声部のイベント開始拍の共通部分（全声部がそこで切れる拍）∪ {0, 小節の拍数}。
  さらに連符グループの内部（開始と終了の間）は候補から除外する（#282 の整合規則）
- ドラッグ座標→拍は #327 の拍台帳（beatColumnsByMeasureP）で解決し、最近傍の候補へスナップ
- 共通境界が 0 と小節末しか無い小節では、実質「小節丸ごと」へスナップされる（安全側）

### 操作

- 表示: 小節選択と同じ青枠+薄青を、スライスの x 範囲だけに描く（全段を縦に貫く）
- Escape で解除（既存と同じ）・Delete でスライス内を等価の休符へ置換
  （小節丸ごと選択の Delete が events を空にするのと違い、他の拍を保つため休符埋め）
- Cmd+C: スライスをクリップボードへ（既存の後勝ち3すくみ: 小節 / 連符グループ / スライス）。
  弧・松葉は**v1 では全部落とす**（既知の制限）。「スライス内で完結するものだけ保持」は、
  弧が持つ絶対インデックス（toMeasureIndex/toEventIndex）の貼り付け先での付け替えが必要で、
  誤った付け替えは #319 型の壊れ方をするため、まず安全側に倒す。連符グループの
  クリップボード（段1）も同じ制限で運用実績がある
- Cmd+V: 現在の選択位置（小節+拍）へ上書き貼り付け。貼り先の該当拍範囲を
  スライス内容で置換する。空き不足・境界不一致は #318 準拠で通知して中止
- 段3（複数回貼り付け）は本段ではやらない（別Issue化の候補のまま）

### 実装の割り付け

- PSC: ドラッグの拍解決とスナップ・onBeatRangeSelect コールバック・スライスの強調表示
  （描画の最終段で beatColumnsByMeasureP から x を引く）
- ScorePage: selectedMeasures の拡張・Cmd+C/V・Delete のスライス分岐・スライス用クリップボード
- 純関数 utils（beatSliceUtils.ts 新設）: 境界候補の算出・イベント列のスライス切り出し・
  休符置換・貼り付け合成（テストはここに集中させる）

### 追記（Codex round1 対応・2026-08-22）: 上書きの意味論と参照補正の確定

PR #359 の Codex レビュー（P1×6・P2×5）を受けて、次を実装で確定した。

**貼り付けは「選択幅の上書き」**（P1: 無音も選択幅ぶん上書き）
- `pasteVoiceSlice` はスライスの**イベント合計拍**ではなく**選択幅（segment.beats）**を
  上書き範囲とする。コピー元の後半が無音なら残りを休符で埋める（後続音符があるときのみ。
  末尾の空きは詰め物領域なので埋めない＝削除と同じ規則）。イベントが空のスライスも
  「幅ぶんの無音」として貼れる（＝範囲の削除と同義）。空→空だけは完全 no-op
- 連符グループ id は**貼り付けごとに再発番**する（instantiateTupletGroup と同じ規則）。
  元 id のままだと隣接貼りで1つの巨大グループに融合し、createVexFlowTuplets が連符化を諦める

**イベント数が変わったら弧・松葉の終点参照を全小節ぶん補正**（P1）
- `replaceVoiceSliceWithRests` / `pasteVoiceSlice` は `VoiceSliceEdit`
  （events + 置換したインデックス範囲 + 挿入数）を返し、ScorePage が
  `remapVoiceRefsAfterSliceEdit` で同じ声部の全小節を走査して
  「消えた範囲を指す弧・松葉は除去、後ろを指す参照はずらす」を適用する
  （noteDeletionUtils の remapAllMeasuresAfterRemoval と同じ理由・同じ規則）

**拍選択中の小節単位操作はすべて理由つきで断る**（P1/P2・#318）
- Cmd+V の小節クリップボードへのフォールスルーは中止+通知（拍範囲を無視した全上書きを防ぐ）
- 移調（ボタン・ショートカット）・小節の挿入/削除・矢印キー移動は
  disabled（理由ツールチップ）+ ハンドラ側ガード + describeSliceMeasureOpUnavailable で通知

**削除も貼り付けと同じ「全計画→全適用」**（P2）
- 選択後の Undo 等で境界が合わなくなった声部が1つでもあれば、部分適用せず全体を中止して通知

**その他**
- スライスのクリップボードは連符コピーの後勝ち購読・新規譜面リセットの両方でクリアに参加
- extractVoiceSlice は旧形式タイ（tiedToNext）も落とす（v1 の「弧は全部落とす」に合わせる）
- 完全な空小節の x→拍は、全休符プレースホルダー列を捨てて線形補間で読む
  （プレースホルダー1列が最近傍に吸うと途中の拍を選べない）
- 削除通知の終了境界（排他）は「小節末」「N拍目の手前」表記にし、存在しない次拍を出さない

### 追記（Codex round2 対応・2026-08-22）

- **パート照合を ID 化**: スライスのクリップボードは位置（配列インデックス）ではなく
  partId（小節クリップボードと同じ命名: right/left/quartet-i/ensemble-i/ensemble-i::2/single）で
  照合する。コピー後に楽譜種別・編成が変わっても別の楽器へ上書きしない。
  コピー元に無いパートは「無音上書き」ではなく丸ごと触らない（find(partId) 不成立はスキップ）
- **完全 no-op は履歴も適用も走らせない**: 削除・貼り付けとも「実変更が1件も無い」計画は
  pushHistory・小節の実体化・apply をすべて省略し、#318 準拠で理由を通知する
  （describeSliceClearNoop / describeSlicePasteUnavailable('noEffect')）
- **空になった末尾声部を畳む**: 削除・無音貼り付けで声部2以降が空になったら
