# ツールバーのタブ化

## 背景

強弱記号、拍子、終止括弧、再生設定などの追加で
固定ツールバーの横幅が足りなくなり、

- サンプルボタンが切れる
- ヘッダーが高くなったとき本文と重なる
- 関係ない操作群が常に並んで視認性が落ちる

という問題が出た。

## 方針

### 1. 操作群を4つのタブへ分ける

- `音符・記号`
- `楽譜設定`
- `再生・音色`
- `その他`

各タブでは、その場で必要な操作だけを見せる。

### 2. 既存コンポーネントはなるべく再利用する

レイアウトだけを `ScorePage` 側で組み替え、

- `Palette`
- `PlaybackControls`
- `SaveLoadButtons`

の責務は大きく変えない。

これで既存の音声ロジックやツール状態の退行を減らす。

### 3. 固定ヘッダー高さは実測する

タブごとに中身の高さが違うため、
CSS の固定値だけでは本文が潜り込みやすい。

そこで `ResizeObserver` でツールバー高さを測り、
`--toolbar-h` を React 側から更新する。

### 4. パネルは横スクロールを許す

パレットや再生詳細は最小でも一定幅が必要なので、
無理に縮めず `toolbar-panel` へ `overflow-x: auto` を付ける。

これで極端に狭い画面でも UI が壊れにくい。

## 変更対象

- `src/components/ScorePage.tsx`
- `src/App.css`
- `README.md`

## 注意点

- タブで隠れているだけで、各 state は保持したままにする
- `Y補正` のポップアップは `その他` タブ内へ残す
- 印刷時は従来どおりツールバー非表示を維持する

## 追補: タブ切替時に選択中ツールをリセットする（2026-07-20）

### 問題

上の「注意点」で「タブで隠れているだけで、各 state は保持したままにする」と
した方針により、`tool` state（Palette で選択中のツール）もタブを切り替えても
そのまま保持されていた。これが原因で、「演奏記号」タブで「途中テンポ変更」
（`{ mode: 'measureTempo' }`）などの編集オーバーレイ系ツールを選んだまま
「音符・休符」タブへ切り替えても選択状態が残り、次に譜面をクリックすると
意図せず BPM 入力欄が開いてしまう不具合があった。

### 修正方針

`tool` state だけは方針の例外とし、タブ切替時にリセットする。

- `ScorePage.tsx` にタブ切替の専用ハンドラ `handleToolbarTabChange` を追加し、
  タブボタンの `onClick` を素の `setActiveToolbarTab` からこちらへ差し替えた。
- 「音符・休符」タブへ戻るときだけは、`lastNotesToolRef`（「音符・休符」タブに
  いる間の `tool` の値を追従して保持する ref）の値を復元する。毎回既定の
  4分音符へ戻ると、音価を選び直す手間が増えて不自然なため。
- それ以外のタブ（演奏記号・楽譜設定・再生・音色・その他）へ切り替えたときは、
  常に無害な既定ツール `{ duration: '4', isRest: false }`（4分音符）へリセットする。
  これらのタブでは Palette の音符ボタン自体は表示されないが、`tool` state は
  譜面クリック時の挙動（どのオーバーレイを開くか）に影響するため、編集
  オーバーレイを開くようなモードを残さないようにした。
- タブ以外（Undo/Redo・声部トグルなど）は本修正の対象外で、それらの state が
  タブ切替で保持される方針自体は変更していない。

### 影響範囲

- `src/components/ScorePage.tsx`: `lastNotesToolRef` の追加、`tool` を追従する
  `useEffect`、`handleToolbarTabChange` の追加とタブボタンの `onClick` 差し替え。
- `README.md`: タブ式ツールバーの説明にツールリセットの挙動を追記。

### 検証

- `docker compose run --rm app npm run build` / `npm test`: エラー・失敗なし
  （4661 Tests すべて成功）。
- ブラウザ確認: 「演奏記号」タブで「途中テンポ変更」ツールを選択 →「音符・休符」
  タブへ切替 → 譜面クリックで BPM 入力欄が開かないことを確認。「音符・休符」
  タブで8分音符ツールを選択 →「演奏記号」タブへ切替 →「音符・休符」タブへ戻ると
  8分音符ツールが再び選択されていることを確認。コンソールエラーなし。

## 追補: レイアウト系コントロールを「その他」から「楽譜設定」へ移動（2026-07-21）

### 問題

「その他」タブに、ファイル入出力（新規作成・保存・読込・書出/読込系）と、
譜面の見た目に関するレイアウト調整（段あたり小節数・段数/ページ・小節幅の
均等さ・段割りをリセット・画面表示のズーム・音符の大きさ・ページ余白・
段の間隔・レイアウトをリセット・Y補正）という、性質の異なる操作群が
一緒くたに並んでおり、目的の操作を探しにくかった。

### 修正方針

上記のレイアウト系コントロールを「楽譜設定」タブ（表示ウェイト・楽譜の種類・
編成・拍子・調号のあとに続ける形）へ JSX ごと移動した。state・イベント
ハンドラ・localStorage キーはすべて既存のものをそのまま使い、ロジックは
一切変更していない（純粋な配置換え）。

- **移動したもの**: 段あたり小節数 / 段数・ページ / 小節幅の均等さ・段割りを
  リセット / 画面表示のズーム / 音符の大きさ / レイアウト（余白(左右)・
  余白(上)・余白(下)・段の間隔）・レイアウトをリセット / Y補正
- **残したもの**: 新規作成・保存・読込・ファイル保存・ファイルを開く・
  サンプル系・PDF書出/印刷・**印刷プレビュー**・MusicXML書出/読込・MIDI書出・
  パート譜表示・移調（いずれもファイル入出力、または印刷プレビューと対になる
  操作のため「その他」に残置）
- **Y補正の扱い**: `yOffset` は音符データそのものではなく、画面表示位置の
  補正値（localStorage の `Y_OFFSET_KEY` に保存、楽譜データには含まれない）
  であり、他のレイアウト系スライダーと同じ「表示補正」の性質を持つと判断し、
  移動対象に含めた。

### タブ切替時のツールリセットとの相互作用

このセクション冒頭の「追補」で導入した `handleToolbarTabChange` は `tool`
state（Palette のツール選択）だけをリセットする。今回移動したコントロール
（段数・余白・ズームなど）はいずれも通常の `useState` + `onChange` で
直接値を更新する設定系コントロールであり、`tool` state を経由しないため、
タブを切り替えても値がリセットされることはない。実際に「楽譜設定」タブへ
移動したあとも、スライダーの値は他のタブへ移動して戻ってきても保持される
ことをブラウザで確認済み。

### 印刷プレビューとの相互作用

`isPrintPreview` は `activeToolbarTab` とは独立した state のため、印刷
プレビュー ON の状態で「その他」タブから「楽譜設定」タブへ切り替えても
プレビューは解除されない（`app-root` の `print-preview` クラスは維持
される）。そのため、プレビューを見ながらレイアウト系コントロールを
「楽譜設定」タブで調整する、という導線は従来どおり成立する。

### 影響範囲

- `src/components/ScorePage.tsx`: 「その他」タブの JSX からレイアウト系
  コントロール（段あたり小節数〜Y補正パネル）を切り出し、「楽譜設定」タブの
  末尾（パート編集ボタンのあと）へ移動。MusicXML書出/読込・MIDI書出は
  「その他」タブに残置。
- `src/components/PrintPreview.test.tsx`: レイアウト系スライダーの参照先
  タブが変わったことに合わせ、「印刷プレビューON中に楽譜設定タブへ切り替えても
  プレビューが維持され、スライダーが操作できる」ことを確認するテストへ更新。
- `README.md`: 「その他タブの『X』」という記述のうち、移動したコントロール
  を指すものを「楽譜設定タブの『X』」へ一括更新。

- `docker compose run --rm app npm test`: 452 Test Files / 5716 Tests すべて
  成功。
- `docker compose run --rm app npm run build`: `tsc -b && vite build` が
  エラーなく完走。
- ブラウザ確認（`http://localhost:5178`）: 「楽譜設定」タブに段あたり
  小節数・段数/ページ・小節幅の均等さ・段割りをリセット・画面表示の
  ズーム・音符の大きさ・レイアウト（余白(左右)/余白(上)/余白(下)/段の間隔）・
  レイアウトをリセット・Y補正が表示され、スライダー操作で値が変わることを
  確認。「その他」タブはファイル入出力・PDF書出/印刷・印刷プレビュー・
  MusicXML/MIDI書出入・パート譜表示・移調のみになったことを確認。印刷

  なし。

## 追補: ツールバー内コントロールの高さを共通化（Issue #104・2026-07-28）

### 問題

各タブ内のボタン・セレクト・数値入力は、要素ごとに個別の `padding`/`font-size`
（`.toolbar-chip-button` は高さ28px固定、`.toolbar-select-label select` も28px、
一方で素の `button.ghost` は `line-height: 1.5` 由来で約26px、`.compact-button`
は `line-height: 1.2` で約24px、インラインstyleだけの数値入力・素の `<button>`
（「段割りをリセット」「レイアウトをリセット」等）はさらにバラバラ）で高さが
決まっており、同じ行に並ぶと縦位置・高さがわずかに揃わず見た目が雑然としていた。

### 修正方針

トリアージコメントの仕様どおり、個々の要素に高さを書き足すのではなく、
CSSカスタムプロパティ1つ（`--toolbar-control-height`、既定値28px。既存の
`.toolbar-chip-button` / セレクトの高さに合わせた）を `:root` に定義し、
`.toolbar-panel` 配下の `button` / `select` / `input[type="number"]` /
`input[type="text"]` へ一括で `height: var(--toolbar-control-height);
box-sizing: border-box;` を適用する1つのCSSルールを追加した。

- **対象**: 「楽譜設定」「レイアウト」「再生・音色」「その他」タブの
  ボタン（`.ghost` / `.compact-button` / 無クラスの `<button>` 含む）・
  チップボタン・セレクト・数値入力。既存の `.toolbar-chip-button` /
  `.toolbar-select-label select` のハードコードされた `height: 28px` も
  同じ変数を参照するよう書き換え、値の出どころを1箇所に統一した。
- **対象外（Palette）**: 「音符・休符」「演奏記号」タブの記号パレット
  （`Palette.tsx`）は幅36×高さ30pxのアイコンボタンを隙間なく並べる設計
  （`btnStyle()` がinline `style` で `width`/`height` を直接指定）で、
  グリフの視認性を優先しアイコンサイズを変えたくないため対象外とした。
  inline `style` の `height` は外側のCSSルールの `height` に対して常に
  優先されるため実害はないが、`box-sizing: border-box` だけは inline側で
  指定していないため外側のルールがそのまま効いてしまい、`padding: 0` の
  Paletteボタンで border 分（1〜2px）だけ見た目のサイズが縮む副作用が
  あった。これを防ぐため、Palette側のルート `<div>` 2箇所（`section ===
  'notes'` / `'symbols'`）に `className="palette-panel"` を追加し、
  `.palette-panel button { box-sizing: content-box; }` で打ち消した。
- **対象外（レンジスライダー・チェックボックス）**: `input[type="range"]`
  と `input[type="checkbox"]` は今回の高さ統一の対象外とした。チェック
  ボックスは `height` を指定するとチェックマーク自体のサイズが変わって
  しまうため。レンジスライダーはトリアージ仕様（「ボタン・トグル・数値
  入力・セレクト」）に明記されておらず、`.tempo-slider` など一部は
  `-webkit-appearance: none` で独自の細いトラック（4px）を持つカスタム
  見た目のため、一括で高さを揃えると trackの太さ自体が変わる可能性があり
  見送った。
- 機能・ロジックの変更は一切なし（CSSのみ、Paletteへの `className` 追加は
  スタイルフック目的でロジックに影響しない）。

### 影響範囲

- `src/App.css`: `--toolbar-control-height` の追加、`.toolbar-chip-button`
  / `.toolbar-select-label select` の `height: 28px` を変数参照へ書き換え、
  `.toolbar-panel button/select/input[number]/input[text]` への一括ルール
  追加、`.palette-panel button` の `box-sizing` 打ち消しルール追加。
- `src/components/Palette.tsx`: ルート `<div>` 2箇所へ `className=
  "palette-panel"` を追加（スタイルフックのみ、他の挙動に影響なし）。
- `README.md`: タブ式ツールバーの説明に高さ統一とPalette除外の注記を追記。

## 追補: フィードバックをタブ行右端へ常設（Issue #142・2026-08-01）

ヘッダーのタブ行の構造が変わったため、この設計書にも記録しておく。詳細（背景・
受入条件の解釈・影響範囲）は `.claude/specs/feedback-button/design.md` の
「3.5 追補」を参照。

- `.toolbar-tabs`（`role="tablist"`）を `.toolbar-tab-row` でくるみ、その右端に
  フィードバックボタン（`.toolbar-feedback-button`）と結果通知を置いた
- フィードバックは**タブではない**（パネルを持たず、押すと送信フローが始まる）ため、
  `role="tab"` を付けず `tablist` の外に置き、見た目もピル型＋アイコンでタブと分けている。
  タブ数は従来どおり6のまま

## 追補: ツールバーを折り畳んで隠せるようにする（Issue #125・2026-07-31）

### 問題

タブ化・レイアウト分割を重ねた結果、ツールバーは 1280×720 のピアノ譜で高さ約212px
（Issue本文の実測は143px、その後のタブ追加で更に増えている）を占め、ビューポートの
2〜3割を常時使ってしまっていた。譜面だけを確認したい場面でも編集用のコントロールが
出続けるため、1ページ全体を見渡しにくい。

### 修正方針

ツールバー右下に折り畳みトグルを1つ置き、押すとタブ列・Undo/Redo・パネルを隠して
「トグルだけが乗った細い帯」にする。

- **戻せなくならないことを最優先**にした。ヘッダーごと消して別の復帰ハンドルを
  用意するのではなく、`.toolbar` 自体は残したまま中身だけを隠す構造にしてある。
  折り畳み中もトグル（「▼ ツールバーを表示」）は必ず同じ位置に残る。
- **隠し方は `display: none`（アンマウントしない）**。React 側で条件レンダリングを
  やめて `.toolbar.collapsed` の子孫を CSS で隠すだけにした。パネルを
  アンマウントすると `PlaybackControls` などの内部状態まで作り直され、折り畳んだ
  だけで設定が初期化されたように見えるおそれがあるため。
- **本文の余白は既存の実測機構に任せる**。`--toolbar-h` は既に ResizeObserver で
  ヘッダー高さを実測して更新しているので、折り畳みで高さが変われば
  `.app-root { padding-top: var(--toolbar-h) }` も自動で詰まる。CSS 側に
  折り畳み時の固定高さを書く必要はない。ただし実測値の下限クランプが 60px
  だったため、折り畳み帯（実測33px）では余白が返ってこない。折り畳み中だけ
  下限を24pxへ下げた（上限280pxは据え置き）。
- **状態は localStorage（`score-toolbar-collapsed`）へ `'1'`/`'0'` で保存**する。
  他のUI設定と同じ扱い。JSON.parse を挟まないため、保存値が壊れていても
  「`'1'` 以外はすべて展開」と解釈されて安全側（＝操作できる側）に倒れる。
- トグルの CSS セレクタは `.toolbar .toolbar-collapse-button` と親を前置きしている。
  素の `.toolbar-collapse-button` では `button.ghost`（要素名を含むぶん詳細度が高い）の
  `padding: 8px 12px` に負け、ブラウザ確認でこのボタンだけ高さ36pxになっていた。
  高さは Issue #104 の `--toolbar-control-height`（28px）に合わせている。

### 受入条件のうち未達の項目（#124 の扱い）

Issue #125 の受入条件には「折り畳み時にページ全体が画面に収まる（**#124 のフィット
再計算が効く**）」があるが、**この1点は実装していない**。#124（初期ズームのページ全体
フィット）は 2026-07-28 に「紙面は正確にA4であり自動フィットは不要」という運用者判断で
クローズされ、対応PR #127 も未マージのままクローズされている。現在 `computeFitZoom()`
（`src/utils/viewZoomUtils.ts`）は Issue #40 由来の**幅フィット専用**で、高さは引数に
取らない。ツールバーの折り畳みで変わるのは表示領域の高さだけなので、幅フィットを
再実行しても結果は変わらない。

高さフィットをこのIssueで新規に作ることは、クローズ済みの #124 の設計判断を
夜間エージェントが独断で覆すことになるため行わなかった。折り畳みで広がった領域は
従来どおり「レイアウト」タブの「画面表示のズーム」スライダーで調整できる。

4. 「工場出荷時に戻す」が内輪用語

（Issue #143 の本文は正本コメントの日付を「2026-07-30」と書いているが、実際のコメントは 2026-07-29 付。

### 修正設計

#### 1. スライダーを見出し付きの3グループへ

`.toolbar-layout-group`（薄い枠＋見出しラベル、`role="group"` + `aria-label`）を新設し、
正本コメントの分類どおり次の3つに分けた。**値・localStorage キー・既定値・ツールチップは
一切変更しておらず、変えたのは並べ方だけ**（純粋な配置換え）。

- **用紙と余白**: 余白(左右) / 余白(上) / 余白(下)
- **譜面の密度**: 音符の大きさ / 小節幅の均等さ / 段の間隔 / パート間隔
- **タイトル**: タイトル余白(上) / タイトル余白(下)

「タイトル」を独立させたのは、この2つだけが1ページ目にしか効かないため（ページ全体の余白と混ぜない）。

#### 2. 「画面表示のズーム」を常設エリアへ

ズームは紙面レイアウトではなく画面の見え方を変える操作なので、レイアウトタブから
**折り畳み行（`.toolbar-collapse-row`）の左端**へ移した。正本コメントは「折り畳み行 or タブ行付近」
のどちらでもよいとしており、折り畳み行を選んだ理由は2つ。

- タブ行は Issue #142（フィードバックボタンをタブ行右端へ）が同時に触っている領域で、衝突を避けたい
- 折り畳み行は `.toolbar.collapsed` でも隠れない唯一の行なので、**ツールバーを畳んで譜面だけを
  見ている状態でも拡大縮小できる**。「常設」の要件をいちばん強く満たせる

`.toolbar-collapse-row` は `justify-content: flex-end` から `space-between` に変え、左にズーム・
右に折り畳みトグルを置いた。折り畳み中の帯の高さは実測で 33px のままで、#125 の値から増えていない
（ズームのコントロール高さがトグルと同じ 28px に収まるため）。

#### 3. リセット系4種を1つの「リセット」メニューへ

`リセット ▾` ボタン1つに集約し、押すとポップアップの中に4項目が縦に並ぶ。各項目には
**「影響範囲: …」の説明文**を添え、押す前に「どこまで戻るのか」を読めるようにした。

| 項目 | 説明文に書いた影響範囲 |
| --- | --- |
| 段割りをリセット | 各段の◀▶で上書きした小節数だけ。譜面（音符・記号）や余白・間隔、保存済みの初期値は変わりません |
| レイアウトをリセット | このタブの余白・タイトル余白・段の間隔・パート間隔をまとめて既定値へ。譜面（音符・記号）は変わりません |
| 既定として保存 | 今の設定を「次の新規作成・次回起動の初期値」として保存します。今開いている譜面（音符・記号）は変わりません |
| 初期設定に戻す | 上で保存した初期値を削除します。今の画面の譜面（音符・記号）はそのままで、次の新規作成・次回起動からアプリ既定の設定になります |

（この表の文言は Issue #155 で「譜面（音符・記号）には影響しない」ことを明記する形へ更新済み。
下記「追補: 譜面非影響の明記」を参照）

- **説明文はボタンの中ではなく兄弟の `<span>` に置いた**。ボタンのテキストに含めると
  アクセシブル名が「段割りをリセット 影響範囲: …」と長くなり、既存テストの
  `getByRole('button', { name: '段割りをリセット' })` も壊れるため。

  （`settingsProfileNotice`）は**メニューの外**に置いてあるので、閉じたあとも読める。
- ハンドラ（`handleResetSystemMeasureOverrides` / `handleResetPageLayout` /
  `handleSaveSettingsProfile` / `handleResetSettingsProfile`）は一切変更していない。
  「段割りをリセット」の `disabled`（上書きが無いときは押せない）も従来どおり。

##### メニューを `position: fixed` で描いている理由（ブラウザ確認で判明したバグ）

最初は Y補正パネルと同じ `position: absolute` + 親 `position: relative` で実装したが、
ブラウザ確認でメニューの下半分が見えないことが分かった。親の `.toolbar-panel` に
`overflow-x: auto` が付いており、CSS の規則で **`overflow-x` が `visible` 以外だと
`overflow-y: visible` は `auto` に計算される**ため、縦方向のはみ出しも切られてしまう
（実測: メニューは bottom 508px まであるのに、パネルは 191px で切れて
`document.elementFromPoint()` がメニューを返さない＝クリックもできない状態だった）。

そのため、メニューは `position: fixed` で描き、開くときにトリガーボタンの
`getBoundingClientRect()` を実測して座標を state（`resetMenuPos`）へ入れている。
画面右端からはみ出さないよう `left` は「画面幅 − メニュー幅 − 8px」でクランプし、
開いている間のウィンドウリサイズでは測り直す。390px幅でもメニュー全体が画面内に収まることを
ブラウザで確認済み（`fitsRight: true` / `fitsBottom: true`）。

ラベルとコメント・ドキュメントの文言のみの改名。処理・localStorage キーは変更なし
（`.claude/specs/settings-profile/design.md` の追補も参照）。

#### Y補正について

Issue #143 の指示どおり Y補正には触れていない（削除は #134 / PR #146 の担当）。
3グループの外・リセットメニューの隣に従来どおり残してある。#134 がマージされたら
このボタンごと消える想定。

#### 1. 「段あたり小節数」「段数/ページ」を「譜面の密度」グループ内の「段組」へ

## 追補: 譜面非影響の明記（Issue #155、2026-08-02）

### 問題

「初期設定に戻す」を押した運用者が「音符が残っているけどいいの？」と不安になった。
リセット4種はいずれもレイアウト設定・初期値プリセットだけを対象にしており譜面データには
触れないが、#143 で入れた説明文はそれを**譜面・音符という語で**言い切っていなかった
（「今の画面はそのまま」「音符データは変わりません」等、項目ごとに表現がばらついていた）。
リセット系は押す前の不安がいちばん大きい操作なので、「影響**しない**もの」の明記が要る。

### 修正設計

4項目の `.toolbar-reset-menu-desc` の文言に、統一表記 **「譜面（音符・記号）」** を入れた
（上の表が更新後の正本）。既存の説明と自然につながるよう、項目ごとに差し込み位置を変えている。

- 段割りをリセット: 「変わらないもの」の列挙の先頭に足す
- レイアウトをリセット: 「音符データは変わりません」→「譜面（音符・記号）は変わりません」に統一
- 既定として保存: 「今開いている譜面」→「今開いている譜面（音符・記号）」
- 初期設定に戻す: 「今の画面はそのまま」→「今の画面の譜面（音符・記号）はそのまま」

表記を4項目でそろえたのは、読み比べたときに「同じことを言っている」と分かるようにするため。
`（音符・記号）` の括弧書きがあるので、譜面という語を知らない利用者にも何を指すか伝わる。

### 影響範囲

- `src/components/ScorePage.tsx`: リセットメニュー4項目の説明文のみ。ハンドラ・`disabled`
  条件・メニューの開閉・CSS は**一切変更していない**（ボタンのアクセシブル名は説明文が
  兄弟 `<span>` にあるため今回も変わらない）。
