# 設計書: データ保存先の明示（ローカル保存であることの見える化）

対象 Issue: #497「データ保存先の明示（ローカル保存であることの見える化・信頼UX）」

## 1. 問題

実装上、楽譜データは localStorage（自動保存・作品一覧・復元履歴）と、ユーザーが書き出しで選んだフォルダにしか保存されない。ネットワークへ送信する経路は、環境変数 `VITE_OMR_API_URL` が設定されているときだけ現れる「PDF (β)」（Issue #487 の変換API）に限られ、本番ビルドではそのボタン自体が出ない。

にもかかわらず、実機テストで「すぐ開けると、楽譜のデータとか公開されてるんじゃないかと不安になる」という声が出た（2026-08-30・又聞き）。**アプリがその事実を一度も説明していない**ことが原因で、体感の安全性が実装の安全性に追いついていない。運用者が口頭で説明したら解消した＝説明そのものには効果があることが分かっている。

## 2. 修正設計

口頭の説明をアプリ自身に言わせる。「公開されていないことの証明」ではなく**事実の記述**に徹し、次の2層で行う。

### 2.1 初回だけ出す通知（`src/utils/storageLocationNotice.ts`）

- 既読フラグを localStorage キー `music-score-app-storage-location-notice-seen` に持つ（他の設定キー `music-score-app-ui-variant` 等と接頭辞をそろえた）
- `hasSeenStorageLocationNotice()` / `markStorageLocationNoticeSeen()` は、`uiVariant.ts` と同じく try/catch で握りつぶす。**localStorage が使えない環境（プライベートブラウジング等）では「未読」を返す**ため通知は毎回出るが、記述内容は常に正しく、そもそもその環境では自動保存自体が働かない。「読めないから出さない」より無害と判断した
- 本文は通知が数秒で消えることを前提に「保存先」と「自動では送信しない」の2点へ絞り、詳細はヘルプへ誘導する。送信の否定は「自動で」に限定する（PDF取り込み（β）はユーザーが選んだ PDF を変換サーバーへ送る例外があるため、例外なしの断定は嘘になる。round1 P1）。βの例外の明示はヘルプ側が担う

### 2.2 表示は #318 の通知系を流用する（同じ仕組みの2枚目を作らない）

`ScorePage` の `editNotice`（画面下端中央に出る `data-testid="edit-notice"`。Issue #238 → #306 → #318 で育った通知）へ、`notifyScoreEdit()` 経由でそのまま流す。新しい通知UIは作らない。

ただし1点だけ既存の仕組みを拡張した。

- `ScoreEditNoticeDetail` に任意の `durationMs` を追加し、`notifyScoreEdit(message, durationMs?)` で渡せるようにした。`ScorePage` 側は `detail.durationMs ?? EDIT_NOTICE_DURATION_MS`（既定4秒）で処理する
- **理由**: 保存先の説明は編集の通知より文が長く、4秒では読み切れない。ここで独自の通知コンポーネントを作ると「見た目・位置・タイマーの2枚目」ができ、片方の修正がもう片方に届かない事故（#223→#280 と同型）の温床になる。表示時間だけを引数にするのが最小の差分と判断した（既定値そのままの既存呼び出しは全て無改修）

`ScorePage` 内では、この初回通知の `useEffect` を**通知リスナーの `useEffect` より後ろ**に置いている。React は宣言順に効果を実行するため、前に置くと dispatch 時点でリスナーが未登録で、通知が誰にも届かず消える。

### 2.3 ヘルプ（後から読み直せる場所）

- README「4. 音符入力から保存・印刷までの基本操作」に `### データの保存場所と安全性` を追加した。ヘルプのリファレンスは README の操作章を実行時にパースする方式（Issue #341、`utils/helpContent.ts`）なので、**README に書けばヘルプにも出る**（二重管理しない）
- 併せて目的別ガイド `storage-location`「楽譜データがどこに保存されるか知りたい（公開されない？）」を `TASK_GUIDES` に追加し、`seeAlso` で上記リファレンス項目へつないだ。キーワードに「公開」「プライバシー」「サーバー」等を入れ、不安になった言葉のまま引けるようにした
- PDF (β) の例外（変換のため PDF を変換サーバーへ送り、完了後に削除される）は、README の同節に引用ブロックで明記した。ボタンが出ていない環境ではその通信自体が起きないことも併記し、ボタンの `title` 属性の説明と矛盾しないようにしている

## 追記（round 1 対応・2026-08-31）

- **文言の限定（P1）**: 通知・ヘルプとも送信の否定は「自動で〜送信されることはありません」に限定。
  PDF取り込み（β）はユーザーが選んだ PDF を変換のためサーバーへ送る（完了後削除）例外があるため、
  例外なしの断定は β 使用の瞬間に嘘になる。ヘルプの手順に β の例外1行を追加済み
- **StrictMode 対策（P3）**: 既読判定を `claimStorageLocationNotice()`（claim 型）へ変更。
  モジュール変数 `shownThisLoad` により、同一ページ読み込み内の effect 再実行
  （StrictMode の実行→片付け→再実行）では true を返し続けて通知と消去タイマーを張り直す。
  `resetStorageLocationNoticeForTest()` をテスト専用に用意。
  配線テストに StrictMode ラップ+時間経過での消滅（10秒）の検証を追加

## 追記: 既読管理を共通部品へ切り出した（Issue #524, 2026-09-01）

Issue #524（音符の初回選択で矢印キーの操作を知らせる）が同じ「一度だけ出す通知」を
必要としたため、既読の判定・記録を `src/utils/onceNotice.ts` の `createOnceNotice(key)` へ
切り出し、このファイルはそれを使う形へ付け替えた。**公開している関数名・localStorage キー・
文言・挙動（StrictMode で出し直す `claim`）はいずれも変えていない**。

#524 側は同じ部品の `claimStrict`（この読み込み中も二度と出さない）を使う。
きっかけがマウントではなくユーザー操作で、選び直すたびに effect が走るため。
詳細は `.claude/specs/arrow-key-hint-notice/design.md` を参照。

## 追補（2026-09-03・Issue #570: ホームの常設表示へ格上げ）

### 問題

#497 で入れたのは**初回に一度だけ・10秒で消える通知**だった。ところが不安は後から来る。
発案者ユーザー（テスト会 2026-08-31）は「ログインがないと、全世界に作品が公開されて
いるんじゃないかと不安になる」と述べており、マイクラの公開サーバーのようなメンタルモデルを
持っていた（運用者聴取 2026-09-02）。消えてしまう通知では、この時点の不安には答えられない。

ホームには保存先に触れる文言が2つ（作品一覧の下・フッター）あったが、

- どちらも「送信していない」と「端末を変えると持ち出せない」の**両方**は言えていない
- 文言がJSXへ直書きで2か所に散っており、将来ログイン（#498）が入ったときの差し替え点が不明

という状態だった。

### 修正設計

ホームの保存先表示を**常設の説明**として整理し、文言を `storageLocationNotice.ts` の定数へ集約する
（#570 仕様4。ログインが入ったら「ローカル/クラウド」表示へ発展させる差し替え点をここ1か所にする）。

| 定数 | 出す場所 | 役割 |
| --- | --- | --- |
| `HOME_STORAGE_LOCATION_NOTE` | 作品一覧（最近使ったファイル）の下 | 保存先＋**自動送信していない**こと |
| `HOME_STORAGE_PORTABILITY_NOTE` | 同上（対で並べる） | 裏返しの注意＝別端末で使うには「書き出し」 |
| `HOME_STORAGE_LOCATION_NOTE_SHORT` | フッター | 探さずに見つかる位置の控えめな一行 |

- **フッターに同じ文をもう一度置かない**。同じ画面に同一の文が2つ並ぶと、かえってどちらも
  読み飛ばされる（実際に一度そう実装して画面で確認し、短い言い方へ分けた）
- 「**自動で**サーバーへ送信されることはありません」と対象を限定するのは初回通知
  （`STORAGE_LOCATION_NOTICE_MESSAGE`）と同じ理由。PDF取り込み（β）だけはユーザーが
  選んだファイルを変換サーバーへ送るため、例外なしの断定にすると嘘になる（#497 round1 P1）
- 詳しい説明はヘルプ（README「データの保存場所と安全性」）が既に担っているので新設しない
  （#570 仕様3 は #497 で充足済み。二重に書かない）
- 表示はホーム（`HomeScreen`）だけなので、印刷・書き出し物には出ない（受入2）

### 影響範囲

- `src/utils/storageLocationNotice.ts`（定数3つを追加。既存の通知の関数・キー・文言は無変更）
- `src/components/HomeScreen.tsx`（直書きの2文を定数から描画。持ち出し方の一行を追加）
- `src/components/HomeScreen.test.tsx`（実マウントの配線テスト2件。**定数との一致**まで見て、
  将来の差し替えで2か所へ書き分ける事故を防ぐ）
- `README.md`（ホームに常設表示がある旨を1行）

| --- | --- |
| ホームで保存先の説明が見える（HomeScreen 単体テスト+App 実マウント統合テスト（round1 P2 で App.test.tsx に追加）で固定） | `HomeScreen.test.tsx` に2件追加（作品0件でも消えないことも固定）。実ブラウザでも表示を確認 |
