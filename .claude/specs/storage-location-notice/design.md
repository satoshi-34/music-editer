# 設計書: データ保存先の明示（ローカル保存であることの見える化）

対象 Issue: #497「データ保存先の明示（ローカル保存であることの見える化・信頼UX）」

## 1. 問題

実装上、楽譜データは localStorage（自動保存・作品一覧・復元履歴）と、ユーザーが書き出しで選んだフォルダにしか保存されない。ネットワークへ送信する経路は、環境変数 `VITE_OMR_API_URL` が設定されているときだけ現れる「PDF (β)」（Issue #487 の変換API）に限られ、本番ビルドではそのボタン自体が出ない。

にもかかわらず、実機テストで「すぐ開けると、楽譜のデータとか公開されてるんじゃないかと不安になる」という声が出た（2026-08-30・又聞き）。**アプリがその事実を一度も説明していない**ことが原因で、体感の安全性が実装の安全性に追いついていない。運用者が口頭で説明したら解消した＝説明そのものには効果があることが分かっている。

## 2. 修正設計

口頭の説明をアプリ自身に言わせる。「公開されていないことの証明」ではなく**事実の記述**に徹し、次の2層で行う。

### 2.1 初回だけ出す通知（`src/utils/storageLocationNotice.ts`）

- 既読フラグを localStorage キー `music-score-app-storage-location-notice-seen` に持つ（他の設定キー `music-score-app-ui-variant` 等と接頭辞をそろえた）
- `hasSeenStorageLocationNotice()` / `markStorageLocationNoticeSeen()` は、`uiVariant.ts` と同じく try/catch で握りつぶす。**localStorage が使えない環境（プライベートブラウジング等）では「未読」を返す**ため通知は毎回出るが、記述内容は常に正しく、そもそもその環境では自動保存自体が働かない。「読めないから出さない」より無害と判断した
- 本文は通知が数秒で消えることを前提に「保存先」と「送信していない」の2点へ絞り、詳細はヘルプへ誘導する

### 2.2 表示は #318 の通知系を流用する（同じ仕組みの2枚目を作らない）

`ScorePage` の `editNotice`（画面下端中央に出る `data-testid="edit-notice"`。Issue #238 → #306 → #318 で育った通知）へ、`notifyScoreEdit()` 経由でそのまま流す。新しい通知UIは作らない。

ただし1点だけ既存の仕組みを拡張した。

- `ScoreEditNoticeDetail` に任意の `durationMs` を追加し、`notifyScoreEdit(message, durationMs?)` で渡せるようにした。`ScorePage` 側は `detail.durationMs ?? EDIT_NOTICE_DURATION_MS`（既定4秒）で処理する
- **理由**: 保存先の説明は編集の通知より文が長く、4秒では読み切れない。ここで独自の通知コンポーネントを作ると「見た目・位置・タイマーの2枚目」ができ、片方の修正がもう片方に届かない事故（#223→#280 と同型）の温床になる。表示時間だけを引数にするのが最小の差分と判断した（既定値そのままの既存呼び出しは全て無改修）

`ScorePage` 内では、この初回通知の `useEffect` を**通知リスナーの `useEffect` より後ろ**に置いている。React は宣言順に効果を実行するため、前に置くと dispatch 時点でリスナーが未登録で、通知が誰にも届かず消える。

### 2.3 ヘルプ（後から読み直せる場所）

- README「4. 音符入力から保存・印刷までの基本操作」に `### データの保存場所と安全性` を追加した。ヘルプのリファレンスは README の操作章を実行時にパースする方式（Issue #341、`utils/helpContent.ts`）なので、**README に書けばヘルプにも出る**（二重管理しない）
- 併せて目的別ガイド `storage-location`「楽譜データがどこに保存されるか知りたい（公開されない？）」を `TASK_GUIDES` に追加し、`seeAlso` で上記リファレンス項目へつないだ。キーワードに「公開」「プライバシー」「サーバー」等を入れ、不安になった言葉のまま引けるようにした
- PDF (β) の例外（変換のため PDF を変換サーバーへ送り、完了後に削除される）は、README の同節に引用ブロックで明記した。ボタンが出ていない環境ではその通信自体が起きないことも併記し、ボタンの `title` 属性の説明と矛盾しないようにしている

## 3. 影響範囲

| ファイル | 変更 |
| --- | --- |
| `src/utils/storageLocationNotice.ts` | 新規。既読フラグ・本文・表示時間 |
| `src/utils/scoreEditorNotices.ts` | `ScoreEditNoticeDetail.durationMs`（任意）と `notifyScoreEdit` の第2引数を追加。既存呼び出しは無改修 |
| `src/components/ScorePage.tsx` | 通知リスナーが `durationMs` を尊重するよう変更。初回通知の `useEffect` を追加 |
| `src/utils/helpContent.ts` | 目的別ガイド `storage-location` を追加 |
| `README.md` | 「データの保存場所と安全性」節を追加（＝ヘルプのリファレンスにも反映される） |

譜面データの読み書き・自動保存の経路には一切触れていない（保存の挙動は不変）。
