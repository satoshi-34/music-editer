# 設計書: 音符の初回選択で矢印キーの操作を一度だけ知らせる（Issue #524）

## 問題

`↑↓`（音高）・`←→`（隣の音符へ）・`Delete`（削除）は実装済みで、README とアプリ内ヘルプにも
書いてある。にもかかわらず、運用者もテスター（発案者ユーザー）も**存在に気づいていなかった**。
「機能があるのに知られない」典型で、ヘルプは「困ったときに開くもの」なので、
そもそも困っていると自覚していない段階では読まれない。

一方で、画面に常時ヒントを出すのは譜面を騒がしくするだけで採らない（運用者方針）。

## 修正設計

**音符を初めて選択したときに、既存の通知系（#318）で一度だけ**知らせる。
形は Issue #497（起動時に保存先を一度だけ説明する）とまったく同じ型にそろえた。

### 出す文

```
↑↓ で音の高さ、←→ で隣の音符へ、Delete で削除できます。
ほかのキー操作はヘルプの「キーボードショートカット」をご覧ください
```

通知は数秒で消えるので、**その場ですぐ試せる3つ**だけを書き、残りはヘルプへ誘導する
（全ショートカットを並べても読み切れない）。表示時間は #497 と同じ 10 秒
（編集の通知の既定 4 秒では読み切れない長さのため）。

### 既読の覚え方（共通部品への切り出し）

`localStorage` のキー `music-score-app-arrow-key-hint-notice-seen` に記録する。

判定ロジックは #497 と同じ形になるため、**同じ判定を2枚書かない**よう
`src/utils/onceNotice.ts` の `createOnceNotice(key)` として切り出し、
`storageLocationNotice.ts`（#497）もこれを使うように付け替えた
（このリポジトリでは「同じロジックの2枚目」が #223→#280 の事故を生んでいる）。

共通部品は2つの claim を持つ。**この違いが今回いちばん重要な設計判断**である。

| 関数 | 使う場面 | 同じ読み込み中の2回目 |
| --- | --- | --- |
| `claim()` | **マウント時**に出す通知（#497） | `true`（出し直す） |
| `claimStrict()` | **ユーザー操作**をきっかけに出す通知（#524） | `false`（出さない） |

`claim()` が2回目も `true` を返すのは StrictMode 対策である。React の StrictMode は
effect を「実行→片付け→再実行」するため、「既読なら出さない」だけだと1回目で既読が付き
2回目が黙り、**片付けで消去タイマーを失った通知だけが画面に残る**（#497 round1 P3）。

ところが今回のきっかけは「音符を選ぶ」というユーザー操作で、選び直すたびに effect が走る。
`claim()` をそのまま使うと**選択のたびにヒントが出た**（実装中に実際に踏み、テストが捕まえた）。
この通知は消去タイマーを自前で持たない（表示は通知系に任せきり）ので StrictMode で
出し直す必要が無く、既読だけで判定する `claimStrict()` を使う。

### 出す場所

`PianoSystemCanvas` の `selected`（音符の選択）を見る `useEffect` 1か所。

譜面は段ごとに別インスタンスなので、どの段で選んでも1回で済むよう、出すかどうかの判断は
`localStorage` を見る claim 側に任せている（インスタンス間で状態を共有しない）。

## 影響範囲

- 新規: `src/utils/onceNotice.ts`（共通部品）、`src/utils/arrowKeyHintNotice.ts`
- 変更: `src/utils/storageLocationNotice.ts`（内部を共通部品へ付け替え。**公開している関数名・
  キー・文言・挙動は変えていない**ので #497 側の回帰は無い）、
  `src/components/PianoSystemCanvas.tsx`（effect を1つ追加）
- UI 要素は増やしていない（受入条件2: パレット・ツールバーの DOM は無変更。
  これらのファイルには一切触れていない）

### テストの既定値（注意点）

このヒントは音符を選ぶと通知系へ1件流れるため、**「操作の結果出た通知」を件数で確かめている
既存テスト**（`SCORE_EDIT_NOTICE_EVENT` を数えるもの・17ファイル）が軒並み1件ずれる。
17ファイルを個別に直すのではなく、`src/setupTests.ts` の `beforeEach` で既定を
**既読**にした（テストの初期状態を「アプリを使い慣れたユーザー」にそろえる、という意味づけ）。
ヒント自体の動きは専用テストがこのキーを消してから確かめる。

## テスト

- `src/utils/arrowKeyHintNotice.test.ts`: claim が初回だけ `true`（2回目も、次の読み込みも `false`）、
  文面に3つの操作とヘルプ誘導が入っていること、#497 とキーを共有していないこと、
  `localStorage` が使えなくても例外を投げないこと。
- `src/components/PianoSystemCanvasArrowKeyHint.test.tsx`（実マウント）: 初回選択で1回出る／
  2つ目の音符を選び直しても増えない／既読の状態で開き直したら出ない／譜面の DOM に
  要素を足さない。

## ブラウザ確認（2026-09-01）

既読キーを消してから譜面を開き、音符をクリック → 画面下中央にヒントが出ることを確認。
10秒待って消えたあと、別の音符を選び直しても**出ない**こと（`localStorage` は `1`）も確認。
コンソールエラーなし。
