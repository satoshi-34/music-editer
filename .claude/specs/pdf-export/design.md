# 楽譜のPDFエクスポート 設計書

## 背景・課題

README ロードマップに初期から残っていた項目「楽譜のエクスポート（PDF）」を実装する。
既存実装では `@media print` により A4 用の印刷整形は済んでいるが、ワンクリックで
PDF を書き出す導線が「その他」タブの MusicXML書出・MIDI書出の隣に無かった。

## 案の比較検討

### 案A: `window.print()` 呼び出しボタン
- 実装コストがほぼゼロで、既存の `@media print` 整形（A4サイズ・改ページ・当たり判定除外など）をそのまま流用できる。
- ブラウザの印刷ダイアログで「PDFとして保存」を選べば実質PDFエクスポートになる（Chrome/Edge/Safari はいずれも印刷ダイアログの送信先に「PDFに保存」を持つ）。
- デメリット: 「ボタン1つでファイルが降ってくる」体験ではなく、印刷ダイアログでの追加操作（送信先の選択）が要る。

### 案B: クライアントサイド PDF 生成（jsPDF + svg2pdf.js 等）
- ワンクリックでPDFファイルが直接ダウンロードされる体験は良い。
- ただし新規依存の追加が必要（CLAUDE.md の依存追加ルールに従い `--ignore-scripts` での安全な追加が要る）。
- 最大のリスクは、VexFlowが描く音楽記号（Bravuraフォントを使ったSVG `<path>` ベースのグリフ）を `svg2pdf.js` が正しく変換できるかどうか。多声部・強弱記号・カスタム記号・微分音記号など、この譜面エディタは通常の五線譜より複雑なSVG構造（`<text>`・`<circle>`・当たり判定用の透明 `<rect>`/`<path>` を多数含む）を持つため、変換品質の検証コストが高い。

### 採用結果
**案Aを採用**。理由:
1. 既存の `@media print` は本タスク以前から十分に作り込まれており（A4整形・非表示要素の除外など）、それを流用するだけで実用十分な PDF が得られる。
2. 案Bは新規依存追加＋SVG→PDF変換品質の検証という大きな作業になり、「無理に完成させようとして時間を溶かさない」という方針に反する。
3. 案Bの小さな検証（別譜面パターンでの svg2pdf.js 変換テスト）は行わず、案Aで確実に動作させることを優先した。将来的に「ワンクリックでファイル直接保存」が本当に必要になった時点で、改めて案Bのプロトタイプを検証する方が費用対効果が良いと判断。

## 実装内容

### 1. ボタンの追加（実質は既存ボタンの整備）
「その他」タブには元々 `window.print()` を呼ぶ「印刷」ボタンが既に存在していた
（`src/components/ScorePage.tsx` の `activeToolbarTab === 'other'` ブロック内）。
今回は重複ボタンを増やさず、この既存ボタンをそのまま「PDF書出」導線として整備する方針にした:

- ラベルを「印刷」→「PDF書出 / 印刷」に変更し、印刷ダイアログで「PDFとして保存」を選べば
  PDF書出になることが伝わるようにした。
- `title` 属性に操作手順（「ブラウザの印刷ダイアログを開き、『PDFとして保存』を選ぶと楽譜をPDF書出できます」）を追加。
- ハンドラを `handleExportPdf`（中身は `window.print()` のまま）という名前の `useCallback` に切り出し、
  `handleExportMusicXml` / `handleExportMidi` と同じ命名パターンに揃えた。

### 2. 印刷CSSの品質確認と修正（`src/App.css` の `@media print`）

既存の @media print ルールを精読した結果、以下の問題が見つかったため修正した。

#### 問題1: クリック判定用の透明パスが印刷で黒い太線として出てしまう
既存ルール `.print-page svg path, svg line { stroke:#000; fill:#000 }` は、
線を薄くしないための「黒で強制」ルールだが、これは **見た目の線を持つ `<path>` だけでなく、
クリック判定専用の透明な `<path>`（`stroke="transparent"`, 太さ10pxの当たり判定領域）にも
無差別にかかってしまう**。具体的には:

- タイ／スラーの当たり判定パス（`src/components/StaffCanvas.tsx` および
  `src/components/PianoSystemCanvas.tsx` の `drawArcPathP` 内、`hitPath`）
- 松葉（ヘアピン）の当たり判定パス（`src/utils/hairpinRenderUtils.ts` の `drawHairpinSegment` 内、`hit`）

これらは元々 `rect` の当たり判定（`.vf-hit` 等）と同様に印刷から除外されるべきだったが、
`<rect>` 用の除外クラスしか用意されておらず、`<path>` 側は対象外だった。
印刷結果では、タイ・スラー・松葉のたびに幅10pxの黒い帯が出てしまうバグになっていた。

**修正**:
- 上記3箇所の当たり判定パスに `class="vf-arc-hit"` / `class="vf-hairpin-hit"` を付与。
- `@media print` 側で `path.vf-arc-hit`, `path.vf-hairpin-hit` を `stroke:none; fill:none` に上書きし、
  通常の `path` 強制黒ルールから除外。

#### 問題2: カスタム記号のテキスト・輪郭円が印刷で薄いグレーのまま
運指番号・強弱記号・リハーサルマーク・ペダル記号・オッターバなどは `<text>` 要素で描かれており、
色は `#111827` / `#1f2937` / `#1e293b` / `#374151` など、視認性のためにやや薄めのダークグレーが
使われている（画面表示用の配色）。印刷では純粋な黒で出したいため、
`.print-page svg text { fill: #000 !important; }` を追加した。

カスタム記号（ユーザー定義の奏法記号）は `<circle>` 要素も使う
（`src/utils/customSymbolUtils.ts`）。ここは `fill="none"`（輪郭だけの記号）のケースがあるため、
`path`/`line` と同じ「一律 fill:#000」にすると輪郭記号が塗りつぶし記号に化けてしまう。
そのため `circle` は `stroke:#000` のみ一律で強制し、`fill` は
`:not([fill="none"])` の場合だけ `#000` を強制するようにした。

#### 問題3（確認のみ、修正不要）: 2声部の淡色表示
非アクティブ声部の淡色（`INACTIVE_VOICE_COLOR = '#9ca3af'`）は VexFlow の `setStyle` 経由で
ノートヘッド等の `<path>`/`<rect>` に適用されるため、既存の
`.print-page svg path { fill:#000 !important }` によって印刷時は黒に強制される
（`src/components/PianoSystemCanvas.tsx` 冒頭のコメントの通り）。ブラウザ確認でも
淡色ノートが印刷プレビューでは黒く出ることを確認した。修正不要。

## 追補: 実機印刷で見つかった不具合の修正（2026-07-18）

実プリンタでの印刷テストで、以下の3つの症状が見つかった。

1. **リハーサルマークが黒四角になる**: 囲み枠の `<rect>`（`fill="none"` +
   `stroke="#111827"`）に、印刷CSSの「rect へ一律 fill:#000」が効いて
   枠が黒く塗りつぶされ、中の文字が隠れていた。
2. **スラー／タイが黒い塊になる**: 弧の可視パスは `fill="none"` の細い
   ストローク描画だが、「path へ一律 fill:#000」で弧の内側が塗りつぶされ、
   太いバナナ状に印刷されていた。
3. **譜面全体が太る**: 符頭・音部記号などの「塗りのみ」グリフパスと
   五線・小節線の rect に「一律 stroke:#000」で輪郭線が追加され、
   全要素が一回り太く印刷されていた（インク消費も増える）。

### 修正設計

「fill / stroke の有無は元の描画を尊重し、色だけを黒へ統一する」方針へ変更。
属性セレクタで「元からその属性を持つ要素」だけを対象にする。

```css
path[stroke]:not([stroke="none"]) { stroke:#000 }   /* 色付き線だけ黒に */
path[fill]:not([fill="none"])     { fill:#000 }     /* 色付き塗りだけ黒に */
rect / circle も同様（クリック判定・デバッグ用クラスは従来どおり除外）
```

- 属性なし（SVGデフォルトの黒塗り）グリフはそのまま黒で印刷されるため、
  強制は不要。
- 2声部の淡色（#9ca3af）は VexFlow の setStyle が fill/stroke 属性として
  付与するため、属性セレクタでも従来どおり黒に強制される。

### 追補2: 編集ページを A4 実寸に固定（2026-07-18）

上記の既知問題のうち「ページ割りと A4 実寸の不一致」を解消した。

- `App.css` の `.print-page` を `min-height: var(--page-height, 297mm)` から
  `height: 297mm; overflow: hidden` の固定サイズへ変更。
  編集画面の1ページがそのまま印刷の1枚になる（WYSIWYG）。
- 1ページに収まる段数を `ScorePage.tsx` の `systemsPerPage` で
  楽譜種別ごとに実測から再設定した:
  - 単旋律: 9 → 8 段/ページ（1段 ≒114px）
  - ピアノ大譜表: 9 → 5 段/ページ（1段 ≒180px）
  - 弦楽四重奏: 9 → 2 段/ページ（1段 ≒340px）
  - 編成譜: 従来どおり 2（11パート以上は 1）
  - 本文予算はタイトルページで約 938px（A4 高 1123px − 上下余白 98px −
    タイトル欄 68px − ページ番号 19px）。
- これにより「継ぎのシートにタイトルが無い」「段が紙面の境目で切断される」
  「ページ番号が継ぎのシートへ流れる」問題がまとめて解消される。
- 検証: ピアノ／単旋律／四重奏で全ページ offsetHeight = 1123px（A4）、
  本文の下端がページ内（24px の余裕）に収まることを DOM 計測で確認。

### 追補3: 印刷時の画面用オフセット打ち消し漏れを修正（2026-07-18）

追補2（A4 実寸固定）後の実機印刷で、1枚目の最終段が2枚目へ押し出され、
2枚目が「1ページ目の続き」になる症状が残っていた。原因は、印刷時に
画面表示用のオフセットが打ち消し切れておらず、紙のページ境界と
`.print-page`（297mm）の位置が最初からずれていたこと。

打ち消し漏れは4箇所:
- `body` のデフォルト margin 8px
- `.app-root` の `padding-top: 60px`（固定ツールバー分の逃し）
- `.paper-rail` の `padding: 16px 0` と `.spread` の `padding: 16px 24px` / `gap`
- `.page-wrapper` のインライン style（`height: measuredHeight × scale`）。
  インライン style は `!important` なしの印刷CSSでは上書きできず、
  紙面上のページ高さが縮尺後の高さのままになっていた

いずれも `@media print` で `!important` 付きで 0 / auto に強制した。
検証: 印刷ルールを無条件適用するエミュレーションで、各 `.print-page` の
上端が 0 / 1123 / 2245px と A4 境界（1123px 刻み）に一致することを確認。

### 追補4: 印刷の濃度感を市販譜へ寄せる（2026-07-18）

実機印刷を市販の楽譜と並べて比較したところ「全体的に太い」ため、
印刷時のみ以下を適用した（画面表示は変更なし）:

- `.print-page .score-area` を `scale(0.9)`（transform-origin: top center）で縮小。
  インクの滲みで線が太って見える分の補正も兼ねる。
- `--score-stroke-width` を表示ウェイト設定に関わらず 0.8（「細い」相当）へ
  `!important` で固定。`.score-area` の inline style（画面用の表示ウェイト）より
  優先させるために `!important` が必要。

倍率（0.9）と太さ（0.8）は `@media print` 内の該当ルールで調整できる。

### 追補5: 印刷インク色の変数化と一時的な青印刷（2026-07-18）

黒インク切れの間も印刷できるよう、印刷ブロックの色指定を
`--print-ink` 変数に一本化した。**現在は一時措置として青（#1d4ed8）**。
黒へ戻すときは `@media print` 冒頭の `:root { --print-ink: ... }` を
`#000` に変えるだけでよい。

実装上のポイント:
- VexFlow は色を (1) 要素自身の fill/stroke 属性、(2) 親 `<g>` の属性、
  (3) **svg ルート要素の `stroke="black"`** の3経路で付けている。
  要素単位のルールだけでは (2)(3) からの継承分（五線・符幹など）が
  元の黒のまま残るため、`g[stroke]` / `svg[stroke]` などグループ・
  ルート側も変数色へ差し替えるルールを追加した。
- fill="none"・stroke="none" は従来どおり尊重（塗り・線を追加しない）。
- fill 属性を持たない SVG デフォルト黒のグリフ（符頭・音部記号）にも
  色が付くよう、fill ルールは `[fill]` の存在条件を外した
  `path:not([fill="none"])` 形にした（ヒット判定は除外）。
- タイトル・ページ番号など HTML テキストの color も同変数で統一。
- 検証: 印刷エミュレーションで可視要素の黒残り 0 件を確認。

### 未解決の既知問題（別タスク）

- 画面幅が2ページ分未満のとき `visiblePages` が2ページ目以降を DOM から
  間引くため、狭いウィンドウから印刷すると2ページ目が印刷されない。
- 末尾の空の大譜表も印刷される（紙の節約オプション未実装）。
- 編成譜（多パート）は1段の高さがパート数に依存するため、パート数が
  多い場合は 1 段/ページでも A4 からあふれる可能性が残る。
