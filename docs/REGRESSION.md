# Regression Checklist (quick)

## A. クリック精度
- [ ] scale=1.0 / 0.86 / 0.8 で、1段目の1小節目に **E4, G4, B4, D5**（=ミ・ソ・シ・レ）を下からクリックして狙い通りに入る
- [ ] 五線の「線の上」をクリックしても上の間に吸われない（線に吸着）
- [ ] 五線の外（加線域：line=4.5 以降）でも正しい音高が入る

## D. Safari 固有チェック（再発防止）
> CSS `zoom` プロパティ起因の座標ズレバグが過去に繰り返し発生。
> 2026-06 にページ縮小を `transform: scale` へ置き換えて根本対策済み（issue #13）だが、**Safari での確認は継続すること。**
> あわせて `.page-wrapper` / `.print-page` へ CSS `zoom` が再導入されていないことも確認する。
- [ ] **Safari** で scale=1.0 のとき、ガイドライン（ホバー時の横線）がマウスカーソルと同じ高さに表示される
- [ ] **Safari** で scale=0.86 / 0.8 のとき、ガイドラインがマウスカーソルと同じ高さに表示される
- [ ] **Safari** でクリックした位置と音符が描画される高さが一致する（ガイドラインの高さ＝実際の音符の高さ）
- [ ] **Chrome** で同じ操作を行い、Safari との表示差がないことを確認する
- [ ] ページ縮小時（scale<1.0）に、ページ間の余白が間延びしていない（`ScaledPageWrapper` の高さ補正が効いている）
- [ ] 印刷プレビューでページが原寸（縮小されていない状態）で出力される

**上記が失敗した場合は [`docs/safari-coordinate-transform.md`](safari-coordinate-transform.md) を参照。**

> 手動の逃げ道だった「Y補正」ボタンは Issue #134 で撤去済み（対症療法UIのため）。ここが失敗したら座標変換そのものの退行を疑い、対症療法で埋めずに原因を直すこと。

## E. Safari 音声チェック（再発防止）
> Safari では `AudioContext` が `running` に見えても、別タブの動画再生やホットリロード後に無音になることがある。
- [ ] **Safari** で音色プレビューが鳴る
- [ ] **Safari** で譜面再生が鳴る
- [ ] 別タブで動画や音声を再生したあとでも、Safari 側に戻って再生できる
- [ ] コンソールに `[SimpleAudioEngine] 出力経路をウォームアップしました` が出る
- [ ] **Chrome** では同じ操作で常に鳴る
- [ ] 正常に鳴っているとき、再生ボタン付近に無音検知の通知が**出ない**（誤検知チェック）
- [ ] 再生開始直後（1秒以内）に一時停止しても、無音検知の通知が**出ない**（一時停止の suspended は正常な状態）
- [ ] 無音が発生した場合、コンソールに `[ScorePage] 無音状態を検知しました:` の診断ログが出て、再生ボタン付近に自動再起動の通知が出る（このログを issue #14 へ貼る）
- [ ] 正常に鳴っているとき、コンソールの `出力ヘルスチェック` 行の `mainPathPeak=` が 0 でない（実音経路の実測値・issue #618）
- [ ] 実音経路が無音のときだけ「このタブの音声経路が壊れています。…タブを閉じて開き直してください。」が出て、再生が止まる（このとき自動再起動の通知と「「音の調子がおかしいとき」を開く」ボタンは**出ない**）
- [ ] 先頭が全休符の譜面・休符の拍からの途中再生でも、無音検知の通知が**出ない**（#618 round1 P1-1: 観測窓 0〜0.85 秒の中に発音が無いだけ）
- [ ] 音量スライダーを 20% まで下げても、正常に鳴っていれば通知が**出ない**（#618 round1 P1-2: ピークは音量ぶん縮む）
- [ ] 停止ボタンを押した直後に無音検知の通知が**出ない**（#618 round1 P2: 停止で予約済みの自己診断も取り消す）

**上記が失敗した場合は [`docs/audio-safari-notes.md`](audio-safari-notes.md) を参照。**

## B. 小節幅の自動割付
- [ ] 「十六分×3＋二分」など細かい音価と長い音価が混在しても溢れない
- [ ] 全音符・二分音符を含む小節が“やや広め”に割り当てられる
- [ ] 32分・64分が続く小節でも符頭が重ならない

## F. アーティキュレーション（奏法記号）
- [ ] パレットの `•` / `>` / `‒` / `^` / `𝄐` を選んで音符をクリックすると記号が付く
- [ ] 同じボタンで同じ音符を再クリックすると外れる（トグル）
- [ ] スタッカート＋アクセントのように複数を重ねて付けられる
- [ ] 休符をクリックしても何も起きない
- [ ] フェルマータ・マルカートは符頭の上に表示される
- [ ] フェルマータの弧が**頂点で太く両端へ細くなる塗り形状**で、開口部の中央に点があること（Issue #527。
      細い一定太さの線＝針金状に見えていたら退行）。単旋律とピアノ大譜表で同じ見た目になること
- [ ] ⤢（サイズ変更）でフェルマータを拡大しても、弧と点が同じ倍率で一緒に大きくなること
- [ ] 再生で、スタッカートが付いた音は短く切れ、アクセント／マルカートは強く鳴る（テンポ自体は変わらない）
- [ ] 保存→再読込で記号が保持される

## G. 小節選択（Issue #145）
> 選択ハイライトは `.vf-hit` の `fill: transparent !important` に負けて**一度まったく見えなくなっていた**。
> クラス `vf-measure-selected` で上書きしているので、CSS を触ったら必ず「見えるか」を確認する。
- [ ] 小節選択ツールでクリック → その小節が青枠＋薄青で塗られる（4譜種すべて）
- [ ] 小節Aで押して小節Bまでドラッグ → A〜B がまとめて選択される（音符が詰まった小節を通っても途切れない）
- [ ] ドラッグ範囲選択の直後でも、次の1クリック（または Shift+クリック）が無反応にならない
- [ ] 音符ツール中に小節を `Shift+クリック` → 小節選択になり、音符は置かれない
- [ ] 音符ツール中の通常クリック（Shift なし）は従来どおり音符が置かれる
- [ ] 複数パートの譜面では、選んだ小節位置の全パートが同時に選択される
- [ ] 印刷プレビュー・PDF書出・印刷に選択ハイライトが出ない

## H. 記号の調整オーバーレイ（Issue #230）
> クリック位置にそのまま開いていたため、調整対象の記号を自分で隠していた。
> 配置ロジックは `symbolOverlayPlacementUtils.ts` に集約し、サイズ変更・位置調整で共有している（2系統にしないこと）。
- [ ] 譜面**中央**の記号で位置調整（✥）を開く → オーバーレイが記号を隠さない
- [ ] 譜面**上端**（1段目・ツールバー直下）の記号で開く → 上に入らないので下へ回り、ツールバーの下に潜らない
- [ ] 譜面**下端**の記号で開く → 画面下へはみ出さない
- [ ] 譜面の**左端・右端**の記号で開く → 左右に見切れない
- [ ] 開いたまま矢印キーで動かす → 記号は動くが**オーバーレイは動かない**（記号もオーバーレイも見えたまま）
- [ ] 開いたまま**記号そのものをドラッグ**（Issue #522）→ 記号が指について動き、離すと確定する。
      「元に戻す」1回で掴む前の位置へ戻る。ほとんど動かさずに離したときは何も保存されない
      （オーバーレイは開いたまま）。ドラッグの直後のクリックで記号が選び直されない
- [ ] **未選択の記号をそのまま掴んで動かす**（Issue #553）→ 動かし始めた時点で ✥ が開き、
      記号が指について動く。離すと確定し、「元に戻す」1回で戻る（＝保存はドラッグ1回ぶん）
- [ ] 未選択の記号を**ほとんど動かさずに離す**（3px 未満）→ 位置は変わらず、従来どおり
      ✥ が開くだけ。**ここが動いてしまうなら退行**（誤爆防止のしきい値が効いていない）
- [ ] 記号にカーソルを乗せると、選択の有無によらず掴めるカーソル（grab）になる
- [ ] **⤢（サイズ変更ツール）中**は記号を掴んでも動かず、クリックで大きさのパネルが開く
- [ ] **音符・休符タブ**では記号を掴んでも動かない（音符の入力・小節の範囲選択と衝突しない）
- [ ] サイズ変更（⤢）でも上の5項目が同じように成り立つ
- [ ] ページを縮小表示（scale<1.0）した状態でも、オーバーレイが記号の近くに出る

## I. 削除のフィードバックと選択の自動解除（Issue #238）
> 選択（青枠）が残ったまま Delete が譜面へ届き、三連符がグループごと**無言で**消える事故が実機で起きた。
> 「確認ダイアログを出さず、起きたことを通知する」「モードが変わったら選択を手放す」の2本立てで対処している。
> 設計の詳細は [`.claude/specs/delete-feedback-and-selection-clear/design.md`](../.claude/specs/delete-feedback-and-selection-clear/design.md)。
- [ ] 音符を選択 → `Delete` → 画面下端の中央に「音符を削除しました（Cmd/Ctrl+Z で元に戻せます）」が数秒出て、自動で消える
- [ ] 3連符の**2音目**（他に音符が残る位置）を選択 → `Delete` → **その位置だけが連符内の休符になり**、連符の囲み・数字・残りの音符はそのまま。「連符内の音符を休符にしました」と出る（Issue #283。声部1・声部2どちらでも同じ）
- [ ] そのまま残りの音符も順に `Delete` → **最後の1音を消したときだけ**グループ全体が同じ長さの通常の休符1つになり、「3連符グループを削除しました」と出る
- [ ] 連符内の**休符**を選択 → `Delete` → 従来どおりグループ全体が通常の休符になる（グループごと消したいときの近道）
- [ ] ピアノ譜の**声部2**で和音の1つの符頭を選択 → `Delete` → **その1音だけ**が消え、「和音の1音を削除しました」と出る（Issue #280。連符の中の和音でも同じで、連符グループ・残りの音・ビームは維持される。声部2の和音の最後の1音を消したときだけ、従来どおりグループごと休符になる）
- [ ] 削除で**確認ダイアログが出ない**（選択→即 Delete の操作感が従来どおり）
- [ ] 音符を選択 → ツールバーのタブを切り替え → 青枠が消える。そのあとの `Delete` で譜面が変わらない
- [ ] 音符を選択 → パレットで別の音価を選ぶ → 青枠が消える
- [ ] 音符を選択 → 再生を開始 → 青枠が消える
- [ ] スラー／松葉を選択した状態でも、上の3つのきっかけで選択が外れる
- [ ] スラー／松葉を選択 → `Cmd/Ctrl+Z` で**その弧が消える** → `Delete` を押しても、残っている別の弧・松葉が消えない（Issue #265。index 参照の残存選択で「選んでいない弧」が消える事故）
- [ ] スラー／松葉を選択 → **別の小節だけ** Undo → `Delete` で、選んでいた弧はちゃんと消える（安全解除が効きすぎて毎回選び直しにならないこと）
- [ ] 通知が出ているあいだも、その真下あたりの譜面をクリックできる（通知がクリックを吸わない）
- [ ] 保存の状態表示（画面右下）と削除の通知（下端中央）が同時に出ても重ならない

## J. 再生中の位置ハイライト（Issue #268）
> 再生位置は「符頭の色を青く変える」方式から「段の背面に淡い橙色の縦帯を出す」方式へ変えた。
> 旧方式は選択（青枠）と混同するうえ、当たり判定 rect を書き換えるので消し残しが譜面に色として残った。
> 設計の詳細は [`.claude/specs/playback-position-visualization/design.md`](../.claude/specs/playback-position-visualization/design.md)。
- [ ] 再生すると、鳴っている位置に**橙色の縦帯**が出て音符と一緒に進む（青ではない＝選択枠と見分けが付く）
- [ ] 帯は**音符の背面**にあり、符頭・符幹・五線が帯に隠れない
- [ ] ピアノ大譜表・編成譜で、帯が**段の上から下まで**を1本で貫く（片方のパートしか鳴っていない拍でも高さが変わらない）
- [ ] 再生中に譜面をクリックできる（帯がクリックを吸わない）
- [ ] 一時停止・停止・別タブへ切り替えて戻る、のいずれでも帯が消える。**消えたあと譜面に色が残らない**
- [ ] 複数ページの譜面（レイアウトの「段数/ページ」を減らす）でも帯は同時に1本だけ
- [ ] 印刷プレビュー・PDF書出で帯が出ない（黒い矩形にもならない）

## K. 和音の同音重複を作らせない（Issue #281）
> 同じ高さの符頭は完全に重なって1つに見えるため、重複が入ると利用者は気づけず、
> 「1音消したのに見た目が変わらない」という原因の分かりにくい症状になる。
> 設計の詳細は [`.claude/specs/bug-fixes/design.md`](../.claude/specs/bug-fixes/design.md) の Issue #281 の節。
- [ ] 和音の1音を選択 → 矢印キーで既存の音と**同じ高さ**へ動かす → 符頭が1つにまとまり、「和音の1音にまとめました」の通知が出る
- [ ] まとめた直後にもう一度矢印キー → **残った1音だけ**が動く（和音全体が動かない＝選択が付け替わっている）
- [ ] `Cmd/Ctrl+Z` で元の和音（2音）に戻る
- [ ] 重ならない移動では音数が変わらず、通知も出ない
- [ ] 和音**全体**を選択した状態の矢印キー移動は従来どおり（音数が変わらない）
- [ ] `docs/qa/regression/moonlight-bars1-9.score.json` を「開く」の「ファイル」ボタン（.score.json）で読み込む → 3小節目右手と8小節目の声部2にあるユニゾン重複が1音になっている（他の音高・スラー・連符は不変）

## L. 連符グループの連続性（Issue #282）

> 連符グループは「同じ tuplet.id が**連続**する区間」として扱われる。
> 挿入位置がグループの内側に入るとグループが前後に割れ、囲み（「3」と括弧）が消える・
> 削除やコピーが断片しか掴めない、という壊れ方をする。
> 設計の詳細は [`.claude/specs/tuplet-implementation/design.md`](../.claude/specs/tuplet-implementation/design.md) の追記10。
- [ ] 3連符を1つ置いたあと、その**2音目・3音目の真上あたり**をクリックして音符を置く → 連符の囲みが消えず、新しい音符はグループの外（手前か直後）に入る
- [ ] 同じ操作を**連符ツール**で行う → 新しい連符グループが既存グループの外に3音そろって入る
- [ ] 同じ操作を**声部2**で行っても同じ結果になる
- [ ] 分断された連符を含む古い保存データ（月光 fixture の9小節目）を「開く」の「ファイル」ボタン（.score.json）で読む → 連符の囲みが全グループぶん描かれる
- [ ] 同じデータを localStorage 経由（自動保存の復元）で読んでも同じ結果になる
- [ ] 開発ビルドで編集していて、コンソールに `[storage] 連符グループが分断されたまま保存されようとしています` が出たら、その直前の操作が新たな発生経路（Issue を立てる）

## M. 2声部の弧（Issue #296）
> 向きだけを声部で固定した（#192）状態では、端点と障害物が符頭基準のままだったため、
> 上声のスラーが自声部の符幹・ビームを貫通していた。端点は符幹先端側へ付ける。
> 設計の詳細は [`.claude/specs/voice2-arc-support/design.md`](../.claude/specs/voice2-arc-support/design.md) §20。
- [ ] ピアノ譜の1つの小節に声部1と声部2の両方を入れ、声部1の音符（連桁でつながる8分音符など）にスラーを張る → 弧が**ビームより上**を通り、符頭・符幹・ビームのどれとも交わらない
- [ ] 同じ弧を手動で反転する → 弧が符頭側へ回り、符頭のすぐ外に付く（符幹先端まで離れない）
- [ ] 声部2（下声）のスラーも同じく、下向きの符幹の先端より下を通る
- [ ] 声部を1つしか使っていない小節・単旋律譜・四重奏・編成譜のスラーの見え方が変わらない
- [ ] 段をまたぐ弧で、前の段の終わりと次の段の始まりの高さがそろっている

## N. 声部を消し切ったら単声部へ戻る（Issue #305）
> 中身が空でも `voices[1]` の器が残っていると多声小節と判定され、符幹の上向き固定と
> スラーの符幹アンカー（M の挙動）が解けないまま「2声部の残骸」が残っていた。
> 設計の詳細は [`.claude/specs/piano-two-voice-implementation/design.md`](../.claude/specs/piano-two-voice-implementation/design.md) の Issue #305 の節。
- [ ] 2声部の小節で声部2の音符を**全部**削除 → 声部1の符幹の向きが音高なりに戻り、スラーが符頭側へ戻る（単声部の小節と同じ見え方）
- [ ] そのまま `Cmd/Ctrl+Z` → 1手で2声部の状態（下声の最後の音符）へ戻る
- [ ] 保存 → 読み直しても単声部のまま（`voices` が復活しない）
- [ ] 声部2に**休符だけ**残した状態では2声部のまま（明示的に置いた休符は消えていない）
- [ ] 声部1を空にして声部2にだけ音符がある小節は、2声部のまま扱われる（下声だけ先に書いている途中を壊さない）

## O. 段またぎ表示のビーム（Issue #313）
> 「同じ五線に連続して載る音符だけ」をビーム生成へ渡していたため、**またぎで抜けた音符の拍が数えられず**、
> 上の五線に残った音符が1音ずつずれて束ねられていた（連符の境界・数字の位置と食い違う）。
> 拍の区切りは全音符列で決め、またぎ位置では切るだけにしている。
> 設計の詳細は [`.claude/specs/cross-staff-notation/design.md`](../.claude/specs/cross-staff-notation/design.md) §12。
- [ ] 4/4 の小節に8分3連を4組入れ、1組目の**頭2音**を ⇵ で下の五線へ出す → 残りのビームが連符ごとに1本ずつ架かり、1組目の3音目は旗になる（1音ずれた束ができない）
- [ ] 同じ操作をピアノ譜の**声部2**で行っても同じ結果になる
- [ ] またぎに出した音符・単独になった音符に**旗が描かれている**（符尾だけの裸の音符にならない）
- [ ] 連符でない8分音符（8分×6など）で1音だけまたぎに出す → 残りは従来どおり拍単位（2+2）で束ねられる
- [ ] 段またぎを使っていない譜面のビームが従来とまったく同じ（月光 fixture の読込で連符・ビームの本数が変わらない）

## P. 段またぎ表示の当たり判定（Issue #315）

## S. 進行中ドラッグの中断（Issue #244 段2・PR #339 レビュー対応）

- 弧（スラー/タイ）のハンドルを**押したまま数字キー・R キーでツールを切り替え**ても、

## T. 音符選択の左右移動と「空の段」（Issue #442）

- 音符を選択して ←/→ を押すと、選択が同じ声部の前／次のイベントへ移ること
  （小節またぎ・段またぎとも。まだ何も書いていない小節は飛ばす）。
- **段をまたいで移った先で、青枠がちゃんと1つ出ていること**。
  段ごとに別インスタンスが選択を持つので、移動は引き継ぎイベントで行っている。
  受け取り条件を「小節の範囲」だけにすると、譜面の余りを埋める**空の段**（Issue #41）が
  データを持たないまま範囲だけ名乗って選択を主張し、選択の一意化で互いに解除し合って
  **どこにも青枠が残らない**（実装中に実際に踏んだ）。実際にその音符を描いている段だけが受け取ること。
- 曲の最初・最後でさらに押したときは選択が動かず、理由の通知が出ること（#318）。
- 音符を選んでいないときの ←/→ は従来どおり小節選択のカーソル移動であること。
- 固定テスト: ScorePageNoteArrowNavigation.test.tsx（6件。小節選択残し・声部2実配線・入力欄フォーカス除外を含む）・noteNavigationUtils.test.ts（7件）

## U. タイの再生（Issue #445）

- 同じ高さの2音をタイで結んで再生すると、**1音として長く**鳴ること
  （「タン・タン」と2回聞こえたら退行）。小節をまたぐタイも同じ。
- タイを3つ以上つなげたら、合計の長さぶん伸びること。
- **タイのあとの音の位置がずれないこと**（テンポが崩れない）。
  伸ばしているのは「鳴っている長さ」だけで、次の音までの間隔は記譜どおり。
- 和音の一部だけをタイで結んだら、**結んだ音だけが伸び、結んでいない音は2回鳴る**こと。
- **スラー**（違う高さを結ぶ弧）は1音にまとめないこと。従来どおり2回鳴る。
- 途中再生（小節を選んで再生）で、**タイの後ろ側の小節から始めたときに音が消えないこと**。
  開始音が範囲外なので、継続音をそのまま鳴らす作りにしている。
- リピートで「次の小節」が変わる箇所（1番括弧の末尾など）をまたぐタイは、
  繋がらず2音として鳴る。これは意図した安全側の動作。
- 音色を「内蔵音源」に切り替えても同じように聞こえること（両エンジンに実装済み）。
- 固定テスト: tiePlaybackUtils.test.ts（17件）・SimpleAudioEngine.test.ts / SoundFontEngine.test.ts のタイ節（スウィング・小節送りを含む）・ScorePageTiePlayback.test.tsx（3件・声部2/トリル相互作用を含む配線）

- [ ] このモード中は**五線のクリックで音符が入らない**（面が選択に割り当てられているため）。
      音符・休符タブへ戻せば従来どおり入力できる。
- [ ] **選択中の段の右下の ◢ を斜めにドラッグ**すると、**全段の音符の大きさが同時に変わる**。
      ドラッグ中の吹き出しに「音符の大きさ（**全体**）: N%」と出る。
      **1段だけが変わって見えたら退行**（角の意味を取り違えさせないための最重要点）。
- [ ] **◢ もレイアウトタブの間だけ**出る。段を選んだまま音符・休符タブへ戻すと ◢ は消える
      （選択そのものとパネルは残ってよい）。**◢ だけが譜面に残っていたら退行**（round1 P2）。
- [ ] **大きく引いて段が別のページへ送られても、値が跳ね戻らない**。◢ はページ→段と辿った先に
      描いているので、段がページをまたぐと要素はいったん消えて描き直される。ドラッグの主は
      ScorePage 直下に1つだけ置いてあり、◢ の出入りとは無関係に最後まで引き続けられる。
      **引いた瞬間に元の大きさへ戻る・「元に戻す」が空振りするなら退行**（round1 P1）。
      ドラッグ中の吹き出しも消えずにカーソルについてくる（吹き出しは譜面ではなく画面に出している）。
- [ ] ◢ で変えた値が、レイアウトタブの「音符の大きさ」の**数値入力欄の数字と完全に一致**する
      （刻みは5%。#578 でスライダーから数値入力へ置き換えたが、値・刻みは変えていない）。
- [ ] 大きさの変更は **「元に戻す」1回**で戻る。**数値入力欄で変えた場合も同じ**
      （1回の編集＝欄にフォーカスが入ってから外れるまで＝履歴1件。同じ欄で打ち直しても1件）。
      ほとんど動かさずに離したときは履歴が増えない。
- [ ] **数値入力欄で大きさを変えたあと、別の編集を Undo しても大きさが巻き戻らない**
      （大きさをスナップショットに入れた副作用。欄側の履歴を外すとここが壊れる）。
- [ ] **実印刷**（ブラウザの印刷）に、面の当たり判定・◢・吹き出しが出ない。
      印刷プレビューでは段調整UIを意図的に残す設計（print-preview/design.md）なので、
      プレビュー中に見えて操作できるのは仕様。
- [ ] **帯もレイアウトタブの間だけ**出る。ページの先頭ではない段を選んだまま音符・休符タブへ戻すと、
      帯も面も◢も消える（選択そのものとパネルは残ってよい）。**帯だけが残っていたら退行**（round2 P2-2）。
- [ ] **同時に掴めるのは1つだけ**。片手で帯を引いている最中に、もう一方のポインタ（タッチとマウスのように
      種類が違うと、どちらも primary として同時に成立する）で別の帯や◢を掴んでも**反応しない**。
      2本目が掴めてしまうと、Undo の退避先が上書きされて確定済みの履歴が巻き戻る（round2 P2-1）。
      先のドラッグを離せば、次は普通に掴める（掴めなくなったらロックの外し忘れ）。
- [ ] 固定テスト: ScorePageLayoutAdjustMode.test.tsx（12件。うち4件は round1 P1・P2 と round2 P2-1・P2-2 の
      再発検出で、修正前のコードに対して実際に落ちることを確認済み）・AppCssSystemSelectPrint.test.ts（印刷と
      `.layout-adjust-mode` の静的チェック）・ScorePageSystemGapDrag.test.tsx（16件・共通フック化の退行検出）

## AA. 作品切替直後の再生（Issue #609）

> 切替の復元は非同期。復元中の再生を止めないと「画面は切替先なのに前の作品が鳴る」。
> 設計の詳細は [`.claude/specs/multi-score-storage/design.md`](../.claude/specs/multi-score-storage/design.md) の追補（2026-09-05）。

- [ ] 作品Aを再生→停止→作品一覧でBへ切替→**すぐ**再生: 鳴るのは必ずB。切替直後の一瞬は
      再生ボタンが無効になり、ツールチップに「作品を読み込み中」が出る
- [ ] Aを**再生中**にBへ切り替える: Aの音がその場で止まる（後続の小節が鳴り続けない）
- [ ] Aを**一時停止中**にBへ切り替える: ボタンが「再開」ではなく「再生」に戻り、押すとBの最初から鳴る
- [ ] 起動直後（前回の作品の復元）に再生の開始が遅くなっていない（復元中だけ無効・終われば即押せる）

## AE. 段の中のパート境界ドラッグ（Issue #572）

> レイアウトタブを開いている間、段の**中の五線と五線の間**（ピアノの右手/左手、四重奏の4段、編成譜のパート間）にも
> 掴みしろが出る。上下にドラッグすると「パート間隔」（レイアウトタブのスライダーと同じ全体設定）が変わる。
> 部品は段の上端の帯（Y節・#523）と共用（`LayoutGapDragBand.tsx`）。
> 設計は [`.claude/specs/page-layout-controls/design.md`](../.claude/specs/page-layout-controls/design.md) の追補（2026-09-05）。

- [ ] **ピアノ譜**で段を選び、右手と左手の間の境界をドラッグすると、掴んだ線が指について動き、
      レイアウトタブの「パート間隔」の数値も同じ値になっている。
- [ ] **パート間隔は譜面全体の設定**なので、どの段のどの境界を掴んでも全部の段のパート間隔が変わる
      （段ごとの個別化は #449。これは仕様であって退行ではない）。
- [ ] **段の間隔の帯と取り違えない**: パート境界の帯を動かしても段と段のすき間は変わらず、
      段の上端の帯を動かしてもパート間隔は変わらない。
- [ ] **弦楽四重奏・編成譜**では境界の数だけ帯が出る。**下の境界ほど指と 1:1 で動く**
      （2番目の境界は1目盛りで2段ぶん動くので、換算を忘れると指より速く動く）。
- [ ] **単旋律譜**には帯が出ない（段の中に境界が無いため）。
- [ ] **画面表示のズームを上げた状態**（150% など）でも、指と境界が 1:1 で動く。
- [ ] **ドラッグ1回＝「元に戻す」1回**でパート間隔が掴む前の値へ戻る（1px ごとに履歴が増えていたら退行）。
      **掴む前と同じ値に戻して離したとき（＝何も変わっていないとき）は履歴が増えない**
      （直前の譜面編集が Undo 1回でそのまま戻る）。段の間隔の帯・角の◢とまったく同じ部品
      （`beginLayoutValueDrag` / `endLayoutValueDrag`）に相乗りしているので、片方だけ壊れたら配線の外れ。
- [ ] **レイアウトタブのスライダーでパート間隔を変えた場合も、つまみ操作1回＝履歴1件**
      （矢印キーの押しっぱなしも1件）。**スライダーで変えたあと別の編集を Undo しても
      パート間隔が巻き戻らない**（音符の大きさ・#571 と同じ副作用。スライダー側の履歴を外すとここが壊れる）。
- [ ] **タッチでもドラッグできる**。取り上げられた（pointercancel）ときは掴む前の値へ戻る。
- [ ] 帯を掴んでも段の選択が解けない。**整えるモード（レイアウトタブ）の間は、段を選んでいなくても
      すべての段にパート境界の帯が出る**（#571 の帯・◢ とそろえた条件。仕様4）。
      **音符・休符タブでは1本も出ない**（譜面を書いている間の見た目を変えないという約束）。
- [ ] **同時に掴めるのは1つだけ**。パート境界の帯を引いている最中に、別の種類のポインタで
      段の間隔の帯や◢を掴んでも反応しない（Undo の退避先を共有しているため・#571 round2 P2-1）。
- [ ] **実印刷**（ブラウザの印刷）に帯や値の吹き出しが出ない（基底クラスの `display:none` を共用）。
- [ ] 音符・休符タブへ戻せば帯は消え、五線の間の音符クリックが元どおりになる（段の選択は不要）。
- [ ] 既知の制約: 段数/ページが自動のとき、ドラッグで段が次ページへ移ると値が巻き戻る（#690）。リセット／プリセット適用は履歴に積まない（#689）。
- [ ] 固定テスト: ScorePagePartGapDrag.test.tsx（14件）・AppCssSystemSelectPrint.test.ts（変種の配置の静的チェック）
