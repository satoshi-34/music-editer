# 画面表示の線の太さの下限（フロア）の修正前後の画像 — Issue #210

室内オーケストラ（編成譜）の**1段目**を、**画面に出ているのと同じデバイスピクセル数**で
切り出した画像です。左が原寸（1:1）、右が4倍拡大（画素を補間しないニアレストネイバー）。

| 画像 | 状態 |
| --- | --- |
| `images/before-chamber-zoom50.png` | 修正前（main `a3842e1`）。五線が **0.57 デバイスピクセル**しかなく、1画素を塗り切れずにかすれる |
| `images/after-chamber-zoom50.png` | 修正後。五線が **1.00 デバイスピクセル**まで戻り、小節線・終止線の太線もそれに比例して太くなる |

撮影条件（2枚とも同じ）:

- 1440×900・`devicePixelRatio` 2
- localStorage を空にしてから `score-view-zoom` に `0.5` だけを入れて起動
- 楽譜設定 → 編成譜 → 室内オーケストラ（8パート）、画面表示のズーム 50%
- このときの実効倍率（SVG論理単位1つが何 CSS px になるか）は前後とも **0.220**

数値の一覧と設計の判断は `.claude/specs/engraving-defaults/design.md` の §15〜§19 を参照。

## 作り方（同じ画像を作り直すとき）

画面キャプチャではなく、**描画中の SVG に計算後スタイルを焼き込んでから canvas で PNG 化**しています
（`docs/qa/engraving-defaults/capture-ab-images.js` と同じ考え方）。ただしこの Issue で見たいのは
「線が1画素を塗り切れずにかすれる」というラスタライズの結果なので、ページ原寸ではなく
**実際の表示倍率 × devicePixelRatio** で描いているところが違います。

1. アプリを開き、上の撮影条件をそろえる
2. コンソールに `capture-floor-images.js` を貼り付けて実行
3. `await floorShot('after-chamber-zoom50.png')`

「修正前」は CSS を手で書き換えて作るのではなく、`git checkout <main の SHA> -- src/` で本当に
修正前の状態へ戻し、dev サーバーを再起動してから撮っています（Vite は `.night-worktrees/` 配下を
watch 対象外にしているため、ファイルを戻しただけでは反映されません。**サーバーの再起動が必要**です）。
