# Git開発ワークフロー

## 概要

一人開発でのコンフリクトを避けるための標準ワークフロー手順です。
新しい機能開発や修正作業を行う際は、必ずこの手順に従ってください。

## 基本原則

- **小さな機能ごとにブランチを作成**（1-2日で完成する単位）
- **作業前に必ずmainブランチを最新に更新**
- **機能完成後はすぐにマージ**（長期ブランチを避ける）
- **GitHub上での直接編集は避ける**（README以外）

## 標準ワークフロー

### 1. 新機能開始前の準備

```bash
# mainブランチに移動して最新状態に更新
git checkout main
git pull origin main

# 新しい機能ブランチを作成
git checkout -b feat/機能名
```

### 2. 開発・コミット

```bash
# 変更をステージング
git add .

# 意味のあるコミットメッセージでコミット
git commit -m "feat: 具体的な変更内容"

# 必要に応じて中間プッシュ
git push origin feat/機能名
```

### 3. 機能完成後のマージ

```bash
# mainブランチに戻る
git checkout main

# 機能ブランチをマージ
git merge feat/機能名

# リモートにプッシュ
git push origin main

# 不要になったブランチを削除
git branch -d feat/機能名
```

## コンフリクト回避のポイント

### ❌ 避けるべきパターン

- 長期間（1週間以上）のブランチ作業
- 複数ブランチでの同時作業
- GitHub上でのファイル直接編集
- mainブランチの更新を忘れる

### ✅ 推奨パターン

- 1-2日で完成する小さな機能単位
- 作業前の必須チェック（mainの最新化）
- 完成後の即座マージ
- ローカルでの全ての編集作業

## 緊急修正の場合

```bash
# 緊急修正もブランチを作成
git checkout main
git pull origin main
git checkout -b fix/緊急修正内容

# 修正・テスト
git add .
git commit -m "fix: 緊急修正内容"

# 即座にマージ
git checkout main
git merge fix/緊急修正内容
git push origin main
git branch -d fix/緊急修正内容
```

## トラブル時の対処

### コンフリクトが発生した場合

1. **マージでコンフリクト解決**（推奨）
   ```bash
   git merge origin/main
   # コンフリクトファイルを手動修正
   git add .
   git commit -m "merge: コンフリクト解決"
   ```

2. **リベースは複雑になりがちなので避ける**

### ブランチが古くなった場合

```bash
# 作業前にmainを取り込む
git checkout feat/your-branch
git merge main
```

## 注意事項

- このワークフローは一人開発用です
- チーム開発の場合は別途プルリクエストベースのワークフローを使用
- 重要な変更前は必ずバックアップを取る
- テストが通ることを確認してからマージする

## 次回作業時のチェックリスト

- [ ] mainブランチが最新か確認
- [ ] 新しいブランチを作成
- [ ] 小さな単位で作業
- [ ] 完成後すぐにマージ
- [ ] 不要ブランチの削除

---

**重要**: このワークフローに従うことで、一人開発でのコンフリクトを大幅に減らすことができます。
