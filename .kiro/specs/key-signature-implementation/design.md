# 設計書: 調号（Key Signature）実装

## 概要

臨時記号の入力基盤は入っていたが、譜面全体の前提になる調号は未実装だった。  
そのため、G 系や F 系の譜面でも、入力・表示・再生が常に自然音前提で動いていた。

今回の実装では、**調号の保存**, **システム先頭への描画**, **新規入力と通常移動への既定反映**, **臨時記号ルールとの統合** を追加する。

## 実装方針

### 1. 保存データに `keySignature` を追加する

`SavedScoreData` に `keySignature` を追加する。  
旧データ互換のため、読み込み時に値が無い場合は `C`（調号なし）として扱う。

- 現行保存時は `keySignature` を必ず含める
- 旧データや不正値は `normalizeKeySignature()` で `C` に補正する
- 保存フォーマットのバージョンは `3.1.0` に上げる

### 2. 調号は VexFlow 互換のファミリー値で持つ

内部値は `C / G / D / A / E / B / F# / C# / F / Bb / Eb / Ab / Db / Gb / Cb` を使う。  
この形式にすると、描画時に `stave.addKeySignature()` へ安全に渡せる。

UI では「♯1つ（G dur / e moll）」のように、同じ調号を共有する長調・短調を補足表示する。

### 3. 調号込みの既定音高を入力時に反映する

`lineToKey()` や `l2k()` は従来どおり自然音の線・間だけを返す。  
そのうえで、入力確定時に `applyKeySignatureToNaturalKey()` を通して、調号に含まれる `# / b` を内部キー文字列へ反映する。

例:

- G 系で `f/4` を置こうとしたら `f#/4`
- F 系で `b/3` を置こうとしたら `bb/3`

対象にする操作:

- 五線クリックによる新規入力
- 和音追加
- `Alt` なしの上下移動
- `Shift` 付きオクターブ移動

`Alt + ↑/↓` は明示的な半音操作なので、従来どおり MIDI ベースの処理を優先する。

### 4. 小節ごとの臨時記号状態を調号で初期化する

`createMeasureAccidentalState()` を調号対応に拡張し、小節開始時点の既定状態を seed する。

例:

- G 系なら各オクターブの `f/*` を `#`
- F 系なら各オクターブの `b/*` を `b`

これにより、調号どおりの音では不要な臨時記号を省略し、調号に逆らう音だけ `n / # / b` を表示できる。

### 5. 各システム先頭へ調号を描画する

`StaffCanvas` と `PianoSystemCanvas` の各システム先頭で、次の順に記号を追加する。

1. `addClef()`
2. 必要なら `addTimeSignature()`
3. `addKeySignature()`

`C` の場合は見た目の調号が無いため、`addKeySignature()` は呼ばない。

## 影響範囲

- `src/utils/noteKeyUtils.ts`: 調号定義、既定変化音の計算、小節状態の初期化
- `src/types/storage.ts`: `SavedScoreData.keySignature` の追加
- `src/utils/storage.ts`: 調号の保存・読込・旧データ互換
- `src/hooks/useScoreStorage.ts`: 保存 API へ調号を渡す
- `src/components/ScorePage.tsx`: 調号 state と UI セレクト
- `src/components/StaffCanvas.tsx`: 単旋律譜の調号描画・入力反映
- `src/components/PianoSystemCanvas.tsx`: 多段譜の調号描画・入力反映
- `src/components/PianoStaff.tsx` / `src/components/QuartetStaff.tsx`: 調号 props の中継
- `src/data/demoScores.ts`: サンプル譜の既定調号設定

## 操作ルール

- ツールバーに `調号` セレクトを配置する
- `♯ / ♭ / ♮` ツール選択中に各システム先頭の行頭をクリックした場合は、音符ではなく調号変更として扱う
- 既存の音符セルをクリックした場合は臨時記号を優先し、音符が無い場所や空小節の調号領域だけを調号変更として扱う
- 拍子記号がある段では、調号領域を「拍子記号の右から音符開始位置まで」に合わせる
- 調号領域が狭すぎる場合でも押せるよう最小クリック幅を確保し、臨時記号ツール中は薄い帯で領域を可視化する
- 調号クリック時はコンソールへ現在値・次値・クリック座標・判定範囲を出し、Safari などブラウザ差異の切り分けをしやすくする
- 行頭の `♯` はシャープ系調号を1段進め、`♭` はフラット系調号を1段進める
- 反対系統へ切り替える場合は、いったん `♯1つ` または `♭1つ` から始める
- `♮` は `C` に戻す
- 調号変更時に既存音符の一括移調は行わない
- 調号変更後の**新規入力と通常移動**から既定音高へ反映する
- 臨時記号ボタンは従来どおり使え、調号に逆らう音では必要な `n / # / b` が自動表示される

## セキュリティと堅牢性

- 保存データの `keySignature` は許可リストで検証する
- 旧データや不正値は `C` に正規化し、未知の値を描画 API に渡さない
- 見た目だけでなく内部キー文字列も調号込みに補正し、再生音との不一致を防ぐ
