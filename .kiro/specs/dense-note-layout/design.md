# 設計書: 細かい音符による過密改段の修正

## 問題

単旋律譜の改段判定が、16分音符を符頭とビームを合わせて約 8.5px と過小評価していた。実際には VexFlow がより広い幅を使うため、設定した段あたり小節数（例: 4）を維持した段で符頭・符尾・ビームが重なった。

## 修正設計

- 小節の最低幅を `measureMinimumContentWidth` に集約する
- 各音符に符頭 8px を確保し、16分・32分・64分音符へは符尾・ビームぶんの追加幅を与える
- 臨時記号と前打音の横方向の張り出しも最低幅に加える
- 幅計算は VexFlow の描画より先に動くため、入力途中や旧保存データで `keys` が未確定でも空配列として扱い、描画を中断させない
- 既存の候補順（設定値 → 3 → 2 → 1）を維持し、最低幅の合計が収まらないときだけ次の候補へ減らす
- 自動休符補完は、背景クリックだけでなく休符本体の置換・分割でも先に実行する。これにより、次の段の休符を音符へ変えたタイミングでも、前段の未完成小節が補完後の密度で再レイアウトされる
- ピアノ大譜表・複数パート譜も `measureMinimumContentWidth` を使い、各パートのうち最大の最低幅に合わせて小節幅を決める

## 影響範囲

- `src/components/StaffCanvas.tsx`: 単旋律譜の改段候補を選ぶために新しい最低幅を使う
- `src/components/PianoSystemCanvas.tsx`: 複数段譜の小節幅計算と休符置換時の自動休符補完に同じ最低幅を使う
- `src/utils/measureLayoutUtils.ts`: 音符密度を含む小節の最低幅を計算する
- `src/utils/measureLayoutUtils.test.ts`: 16分音符16個の最低幅と装飾音の加算を検証する
- `README.md`: 「段あたり小節数」が上限であり、過密時は自動で減ることを明記する

## 最小チェック

- 16分音符16個の小節は 210px 以上の最低幅として扱われる
- 過密な段は設定値より少ない小節数へ自動改段する
- 休符の置換・分割で過去小節へ休符が自動補完された直後も、補完後の幅で再レイアウトされる
- `npm run build` と関連テストが成功し、ブラウザのコンソールにエラーがない
