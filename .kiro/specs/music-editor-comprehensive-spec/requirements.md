# 要件定義書

## はじめに

Music Editor MVPは、Finaleライクな楽譜作成機能を提供するWebアプリケーションです。ユーザーが直感的に楽譜を作成・編集し、保存・読み込みができる包括的な音楽編集環境を提供します。本システムは、VexFlowライブラリを基盤とし、React + TypeScriptで構築されています。

## 用語集

- **Music_Editor**: 楽譜作成・編集機能を提供するWebアプリケーションシステム
- **Score_Canvas**: 五線譜を描画し、音符の配置・編集を管理するコンポーネント
- **Note_Event**: 音価、音高、休符フラグを持つ個別の音楽要素
- **Measure_Data**: 複数のNote_Eventを含む小節データ
- **Tool_Palette**: 音価と休符の選択を行うユーザーインターフェース
- **VexFlow**: 楽譜レンダリングを行う外部ライブラリ
- **LocalStorage**: ブラウザ内でのデータ永続化機能
- **Score_Metadata**: タイトル、作曲者等の楽譜メタ情報
- **Multi_Page_Layout**: 複数ページにわたる楽譜レイアウト機能
- **Coordinate_Transform**: クライアント座標とSVG座標間の変換処理
- **Auto_Scale**: 画面サイズに応じた自動スケーリング機能

## 要件

### 要件 1: 楽譜表示・基本レイアウト

**ユーザーストーリー:** 音楽家として、標準的な五線譜形式で楽譜を表示し、複数ページにわたるレイアウトで作品を管理したいと考えています。

#### 受入基準

1. WHEN アプリケーションが起動した場合、THE Music_Editor はト音記号と4/4拍子の五線譜を表示しなければならない
2. WHEN 楽譜が複数の段にわたる場合、THE Music_Editor は適切な段間隔で複数段のレイアウトを提供しなければならない
3. WHEN 楽譜が複数ページにわたる場合、THE Music_Editor は自動的にページ分割を行い、各ページにページ番号を表示しなければならない
4. WHEN 画面サイズが1200px未満の場合、THE Music_Editor は1列レイアウトに自動切り替えしなければならない
5. WHEN 画面サイズが変更された場合、THE Music_Editor は自動スケーリングを適用して最適な表示倍率を維持しなければならない

### 要件 2: 音符・休符配置機能

**ユーザーストーリー:** 作曲家として、クリック操作で直感的に音符や休符を五線譜上に配置し、正確な位置に音楽要素を記録したいと考えています。

#### 受入基準

1. WHEN ユーザーが五線譜上をクリックした場合、THE Music_Editor は選択された音価の音符または休符を配置しなければならない
2. WHEN 音符を配置する場合、THE Music_Editor はクリック位置のY座標から正確な音高を計算し、適切な線または間に配置しなければならない
3. WHEN 音符を配置する場合、THE Music_Editor は0.5行刻みでのスナップ機能を提供し、加線域も含めて配置可能にしなければならない
4. WHEN 小節内の拍数が4拍を超える場合、THE Music_Editor は音符の追加を拒否し、既存の小節状態を維持しなければならない
5. WHEN 音符を配置する場合、THE Music_Editor は小節幅を音価に応じて自動調整しなければならない

### 要件 3: 音価・休符選択機能

**ユーザーストーリー:** 音楽家として、様々な音価の音符と休符を選択し、多様なリズムパターンを作成したいと考えています。

#### 受入基準

1. THE Music_Editor は全音符、二分音符、四分音符、八分音符、十六分音符、三十二分音符、六十四分音符の選択機能を提供しなければならない
2. THE Music_Editor は各音価に対応する休符の選択機能を提供しなければならない
3. WHEN ユーザーが音価を選択した場合、THE Music_Editor は選択状態を視覚的に表示しなければならない
4. WHEN ユーザーが休符モードを選択した場合、THE Music_Editor は以降のクリックで休符を配置しなければならない
5. THE Music_Editor は選択された音価と休符モードの状態を一貫して維持しなければならない

### 要件 4: 音符選択・編集機能

**ユーザーストーリー:** 編集者として、配置済みの音符を選択し、キーボード操作で効率的に編集・移動・削除を行いたいと考えています。

#### 受入基準

1. WHEN ユーザーが配置済み音符をクリックした場合、THE Music_Editor はその音符を選択状態にし、視覚的フィードバックを提供しなければならない
2. WHEN 音符が選択されている状態でDeleteまたはBackspaceキーが押された場合、THE Music_Editor はその音符を削除しなければならない
3. WHEN 音符が選択されている状態で↑/↓キーが押された場合、THE Music_Editor は音符を線/間1段分上下に移動しなければならない
4. WHEN 音符が選択されている状態でAlt+↑/↓キーが押された場合、THE Music_Editor は音符を半音分上下に移動し、必要に応じて臨時記号を自動付与しなければならない
5. WHEN 音符が選択されている状態でShift+↑/↓キーが押された場合、THE Music_Editor は音符を1オクターブ分上下に移動しなければならない
6. WHEN Escapeキーが押された場合、THE Music_Editor は音符の選択を解除しなければならない

### 要件 5: 座標変換・位置精度

**ユーザーストーリー:** ユーザーとして、クリックした位置に正確に音符が配置され、表示倍率が変更されても一貫した操作性を期待します。

#### 受入基準

1. WHEN ユーザーがクリックした場合、THE Music_Editor はクライアント座標をSVG座標に正確に変換しなければならない
2. WHEN スケール変換が適用されている場合、THE Music_Editor は変換行列を考慮した正確な座標計算を実行しなければならない
3. WHEN 座標変換を実行する場合、THE Music_Editor はgetScreenCTM()メソッドを使用して正確な変換行列を取得しなければならない
4. WHEN マウスカーソルが五線譜上を移動した場合、THE Music_Editor はガイドライン（横線と点）をカーソル位置に正確に表示しなければならない
5. WHEN ガイドラインを表示する場合、THE Music_Editor は最も近い線または間にスナップした位置に表示しなければならない

### 要件 6: 楽譜メタデータ管理

**ユーザーストーリー:** 作曲家として、楽譜にタイトル、作曲者、編曲者等の情報を追加し、作品の詳細を記録したいと考えています。

#### 受入基準

1. THE Music_Editor はタイトルとサブタイトルの編集機能を提供しなければならない
2. THE Music_Editor は作詞者、作曲者、編曲者の情報編集機能を提供しなければならない
3. WHEN メタデータを編集する場合、THE Music_Editor はインライン編集機能を提供しなければならない
4. WHEN 1ページ目を表示する場合、THE Music_Editor はタイトル情報を大きく表示しなければならない
5. WHEN 2ページ目以降を表示する場合、THE Music_Editor はタイトルを小さく表示しなければならない

### 要件 7: データ保存・読み込み機能

**ユーザーストーリー:** 音楽家として、作成した楽譜を保存し、後で読み込んで編集を継続できる機能を必要としています。

#### 受入基準

1. WHEN ユーザーが保存ボタンをクリックした場合、THE Music_Editor は現在の楽譜データをLocalStorageに保存しなければならない
2. WHEN 保存処理を実行する場合、THE Music_Editor は楽譜メタデータ、小節データ、レイアウト情報を含む完全なデータを保存しなければならない
3. WHEN ユーザーが読み込みボタンをクリックした場合、THE Music_Editor は保存されたデータを読み込み、楽譜を復元しなければならない
4. WHEN データを読み込む場合、THE Music_Editor はメタデータをUIに反映し、音符を正確な位置に復元しなければならない
5. WHEN 保存データが存在しない場合、THE Music_Editor は適切なメッセージを表示しなければならない
6. WHEN データが破損している場合、THE Music_Editor はエラーを適切に処理し、アプリケーションの安定性を維持しなければならない

### 要件 8: データ整合性・エラーハンドリング

**ユーザーストーリー:** ユーザーとして、データの破損や容量不足等の問題が発生しても、アプリケーションが安定して動作することを期待します。

#### 受入基準

1. WHEN LocalStorageの容量が不足した場合、THE Music_Editor は適切なエラーメッセージを表示し、代替手段を提案しなければならない
2. WHEN 保存データにチェックサムを付与する場合、THE Music_Editor はデータ読み込み時に整合性を検証しなければならない
3. WHEN 無効なデータが検出された場合、THE Music_Editor はフォールバック処理を実行し、可能な限りデータを復旧しなければならない
4. WHEN 座標変換でエラーが発生した場合、THE Music_Editor は安全な座標値を使用してアプリケーションの継続動作を保証しなければならない
5. THE Music_Editor は全ての重要な処理でエラーハンドリングを実装し、予期しない例外でアプリケーションが停止しないようにしなければならない

### 要件 9: 休符重なり防止機能

**ユーザーストーリー:** 音楽家として、休符が他の音符と重ならず、読みやすい楽譜レイアウトを維持したいと考えています。

#### 受入基準

1. WHEN 休符を配置する場合、THE Music_Editor は時間ベースの位置計算を使用して適切な位置に配置しなければならない
2. WHEN 全休符を配置する場合、THE Music_Editor は小節の中央に配置しなければならない
3. WHEN 複数の休符が同じ小節に存在する場合、THE Music_Editor は重なりを防ぐために位置を自動調整しなければならない
4. WHEN Formatter実行後に休符位置を調整する場合、THE Music_Editor は元の音楽的意味を保持しなければならない
5. THE Music_Editor は休符の位置調整でエラーが発生した場合でも、楽譜の描画を継続しなければならない

### 要件 10: 印刷・出力機能

**ユーザーストーリー:** 音楽家として、作成した楽譜を印刷して物理的な楽譜として使用したいと考えています。

#### 受入基準

1. WHEN ユーザーが印刷ボタンをクリックした場合、THE Music_Editor はブラウザの印刷機能を起動しなければならない
2. WHEN 印刷プレビューを表示する場合、THE Music_Editor は印刷に適したレイアウトで楽譜を表示しなければならない
3. THE Music_Editor は印刷時に適切なページ分割を維持しなければならない
4. THE Music_Editor は印刷時にメタデータ（タイトル、作曲者等）を適切に配置しなければならない
5. THE Music_Editor は印刷時にツールバー等のUI要素を非表示にしなければならない

### 要件 11: レスポンシブデザイン・ユーザビリティ

**ユーザーストーリー:** ユーザーとして、様々な画面サイズのデバイスで快適に楽譜編集を行いたいと考えています。

#### 受入基準

1. WHEN 画面幅が1200px未満の場合、THE Music_Editor は1列レイアウトに自動切り替えしなければならない
2. WHEN 画面サイズが変更された場合、THE Music_Editor は自動スケーリングを適用して読みやすさを維持しなければならない
3. THE Music_Editor は0.75から1.0の範囲でスケール値を調整し、最適な表示を提供しなければならない
4. WHEN マウスホバー時に、THE Music_Editor は適切な視覚的フィードバック（カーソル変更、ハイライト等）を提供しなければならない
5. THE Music_Editor は直感的な操作性を提供し、音楽知識を持つユーザーが迷わず使用できるインターフェースを維持しなければならない

### 要件 12: パフォーマンス・安定性

**ユーザーストーリー:** ユーザーとして、大きな楽譜を編集する際も、アプリケーションが高速で安定して動作することを期待します。

#### 受入基準

1. WHEN 大量の音符が配置された場合、THE Music_Editor は描画パフォーマンスを維持しなければならない
2. WHEN 頻繁な編集操作が行われる場合、THE Music_Editor はメモリリークを防止し、安定した動作を維持しなければならない
3. THE Music_Editor は不要な再描画を避け、効率的な更新処理を実装しなければならない
4. WHEN 複数ページの楽譜を表示する場合、THE Music_Editor は必要なページのみを描画して処理負荷を軽減しなければならない
5. THE Music_Editor は全ての非同期処理で適切なエラーハンドリングを実装し、予期しない状態でも安定動作を保証しなければならない
